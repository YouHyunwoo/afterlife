# Devlog 1일차 — 3D 픽셀 숲 쇼케이스

독립 씬: `Assets/Devlog/Day01/Scenes/Devlog_Day01.unity`

기존 프로토타입에는 전후 비교 전용 공간이 없었다. 이 씬은 같은 배치의 평평한 작은 맵 세 개를 만들고, 기존 FBX를 재사용해 기본 도형 → 모델 배치 → 픽셀 표현과 타격 반응을 보여준다. 새 모델은 제작하지 않았다.

## 공간

| 루트 | 위치 | 구성 |
| --- | --- | --- |
| Before_Primitives | (0, 0, 0) | 회색 primitive 지형·나무·바위·건물·장식 |
| Process_ModelPlacement | (50, 0, 0) | 기존 모델과 색상, 연속적인 명암, 원본 화면 해상도 |
| After_PixelForest | (100, 0, 0) | 두께 있는 블록 지형, 깊이 기반 반투명 바다·거품, 픽셀 표현·바람·타격 반응 |

각 맵은 1×1 크기 타일 12×10개로 구성된다. Before는 얇은 primitive Cube, 중간 단계는 Plane 타일이다. After의 육지는 두께 0.8의 블록이며 윗면 y=0, 밑면 y=-0.8이다. 흙길과 육지 윗면은 같은 높이라 기존 모델 배치를 유지한다. 세 단계는 같은 바이옴 데이터를 사용하며 격자 선이 표시된다. 공간 사이에 38 단위 이상의 빈 영역이 남아 있어 중간 결과를 추가할 수 있다. 각 공간 뒤쪽에는 `AdditionalTakeSpace` 빈 Transform도 두었다.

바이옴은 프로토타입의 일곱 종류와 색을 사용한다: 초원·흙·모래·물·눈·숲·암석. 큰 프로토타입 지도를 그대로 축소하지 않고, 작은 쇼케이스에서 읽히도록 숲·설원·바위 군집·모래 해안·수면을 고정 배치했다. After의 물은 평평한 상태로 물결 색상이 움직인다. 숲에는 Fern, 초원에는 Flowers, 돌/흙/눈에는 Pebbles, 해안에는 Reeds를 배치한다. 물 위에 걸리는 기존 자원은 가까운 빈 육지 타일로 이동한다.

After의 해저 블록은 y=-0.8부터 -0.76까지 높이 0.04(육지 높이 0.8의 5%)이며, 물 블록은 그 위 y=-0.76부터 -0.4까지 높이 0.36(45%)이다. 땅과 물의 부피는 겹치지 않고 경계면만 맞닿는다. 합계 높이 0.4와 수면 높이는 유지한다. `OceanBlocks_HalfHeight`는 물 셀의 수면과 노출 옆면을 합친 메시다. 물끼리 맞닿는 내부 면은 없어서 반투명 면이 중복되지 않는다. 이전 Plane 물 타일은 비활성 상태로 보존한다. `OceanFloor`에는 동일한 0.04 높이의 해저 블록과 그 윗면에 기존 Pebbles 모델을 배치했다. 수심 셰이더의 바닥 좌표도 -0.76으로 맞춘다.

`After_OceanDepth.mat`은 뒤쪽 불투명 지형의 카메라 깊이를 월드 위치로 복원해 수면부터 뒤쪽 표면까지 물을 통과하는 거리를 구한다. 얕은 곳은 밝은 바다색과 낮은 불투명도, 깊은 곳은 진한 파랑과 높은 불투명도다. 해저/자갈은 물을 통해 보이고 수면보다 앞에 있는 육지는 깊이 검사로 가리지 않는다. 거품은 육지와 맞닿은 가장자리, 수면과 물체가 가까운 부분, 흩어진 흰 물결에 나타난다. 물 표면의 실제 높이는 움직이지 않는다.

수면 재질의 `Shallow ocean`, `Deep ocean`, `Depth darkening distance`, `Shallow opacity`, `Deep opacity`, `Shore foam width`로 색·깊이 대비·투명도·거품 폭을 조절한다. `Rendering/ShowcaseDepthPipeline.asset`과 `ShowcaseDepthRenderer.asset`은 Devlog 전용 복제본이며 불투명 물체 렌더링 직후 깊이를 복사한다. 프로젝트 공용 렌더러는 수정하지 않는다. After의 투명 물은 이 씬을 Play하여 전용 파이프라인이 활성화된 Game 뷰에서 확인한다.

Hierarchy의 `Terrain_Flat/BiomeGrid_12x10`, `Environment`, `ClickableResources`, `BiomeDetails`에서 배치를 수정한다. 이전 바닥과 `GroundDetails`는 비활성 상태로 보존한다. 배치는 런타임 생성이 아니라 씬에 직렬화되어 있다. 재생을 멈춘 뒤 수정하고 저장해야 유지된다. 나무·바위·Fern·Flowers·Pebbles·Reeds·House·Ruins·AbandonedAltar·FallenLog 및 도구 FBX는 기존 `_AfterlifePrototype` 에셋을 참조한다.

모델 방향과 크기는 `모델명_Pivot` 부모에서 조절한다. 자식 FBX 루트의 축 보정 회전은 유지해야 한다. 초기 버전에서 모델이 눕는 문제는 `Day01AxisMigration`이 한 번 보정하며 클릭 영역과 타격 도구 참조도 갱신한다. 열려 있는 씬에 미저장 편집이 있으면 자동 저장하지 않으므로 보정 후 씬을 직접 저장한다.

## 촬영 조작

씬을 단독으로 열고 Play를 누른 뒤 Game 뷰에 포커스를 둔다. 기본 시작 공간은 After다.

| 입력 | 기능 |
| --- | --- |
| 1 / 2 / 3 | Before / 중간 단계 / After로 즉시 이동 |
| 마우스 올리기 | 클릭 가능한 나무·바위 강조 |
| 왼쪽 클릭 | 타격. After에서는 흔들림·섬광·파편·도구 모션·효과음 |
| H | 촬영 안내 숨기기 / 표시 |
| P | After의 저해상도 픽셀 출력 켜기 / 끄기 |
| R | 타격 반응·파편·효과음 초기화 |

카메라 각도·줌과 16:9 비율은 단계마다 동일하다. 다른 화면 비율에서는 여백을 둔다. 1920×1080 Game 뷰를 권장한다. `DevlogDay01` Inspector의 `PixelHeight` 기본값은 360이며 화면 크기에 맞는 정수 배율에 가까운 저해상도로 렌더링한다. `CameraShake`를 끄면 흔들림 없는 비교 컷을 찍을 수 있다. `StartStage`로 시작 공간을 바꿀 수 있다. `P`는 화면 해상도만 바꾸며 명암 단계나 팔레트는 유지한다.

타격 대상은 소모되거나 파괴되지 않는다. 연속 클릭에는 0.24초 간격 제한이 있다. 게임의 경제·채집·전투 상태와 연결되지 않은 반복 촬영용 반응이다. 나무와 바위 이외의 환경 장식은 클릭 대상이 아니다.

After의 도구는 클릭 순간의 표면 교차점을 목표로 삼는다. 도끼 날 또는 곡괭이 끝이 0.12초 후 해당 점에 닿으며, 그 순간 대상 반응·파편·효과음을 실행한다. 짧게 접촉한 뒤 총 0.30초에 회수한다. 진행 중인 타격을 다른 클릭이 덮어쓰지 않으며, 마우스 이동으로 목표가 바뀌지 않는다. 교차점은 대상 메시의 로컬 좌표로 보관하여 대상이 흔들려도 같은 표면 지점을 따라간다. 단계 전환이나 R은 대기 중 타격도 취소한다.

접촉 좌표를 피벗 기준 숫자로 추정하지 않는다. Blender의 실제 메시 표면에 광선을 쏘아 도끼 날과 곡괭이 끝에 `ImpactPoint` 마커를 만들었으며, FBX 안에 함께 저장했다. Unity에서는 대상 모션 갱신 후 LateUpdate에서 도구 전체를 `목표점 - ImpactPoint.position`만큼 이동한다. 따라서 FBX 축 보정, 중간 부모, 크기를 포함한 실제 날 마커의 월드 위치가 목표점에 맞는다. 도구 모델 교체 시에도 실제 날 표면에 `ImpactPoint`를 둔다.

클릭은 Physics.Raycast나 큰 BoxCollider 대신, 에디터에서 저장한 실제 메시 삼각형과 현재 Transform을 사용한다. 화면 여백을 제외한 뷰포트 좌표를 사용하고 픽셀 출력 중에는 표시된 픽셀 중심으로 맞춘다. 나무·바위와 건물·폐허 중 가장 가까운 표면이 판정을 결정하므로 건물 뒤의 자원을 선택하지 않는다. 안내 문구는 비상호작용 표시이므로 해당 화면 영역의 클릭을 차단하지 않는다. 기존 BoxCollider는 클릭 판정에 사용하지 않는다.

`Picking`의 표면 데이터는 모델별로 공유하며 FBX Read/Write 설정을 변경하지 않는다. 모델 형태를 이후 변경하거나 자원을 추가할 때에는 해당 모델의 표면 데이터를 다시 생성/연결해야 한다. 위치·회전·크기 수정과 타격 모션은 별도 재생성 없이 반영된다.

파편은 나무/돌 종류별 고정 색 대신, 클릭한 삼각형의 정점 색을 교차점의 무게중심 좌표로 보간한 뒤 해당 재질의 색을 곱해 만든다. 잎은 초록색, 줄기는 갈색, 광석은 해당 결정의 색으로 나온다. 색은 클릭 시점에 저장하므로 도구가 내려오는 동안 마우스를 옮겨도 바뀌지 않는다. 타격 섬광이나 hover 강조색은 섞지 않으며 파편의 조명은 각 파편 면 방향에 따라 적용된다. 기존 클릭 데이터에는 에디터 임포트 시 정점 색이 자동 추가된다.

## 낮·밤과 시야

시야 가장자리의 감쇠 폭은 0.85에서 1.8로 확대했다. 바깥 반경은 유지하며 마우스 시야는 중심에서 거리 1.4~3.2, 집 시야는 2.4~4.2 구간에서 서서히 어두워진다. 밤에 기존과 같은 바깥 경계 안쪽으로 그라데이션이 넓어졌는지 확인한다.

`N` 키로 약 0.5초에 걸쳐 낮·밤을 전환한다. 낮에는 기존 밝기를 유지하고 밤에는 시야 밖의 지형·오브젝트·물·거품을 푸른 어둠으로 낮춘다. 마우스 광선과 바닥 평면의 교차점 위 0.8에 `CursorVisionPoint`를 배치한다. 마우스 시야 반경은 3.2, 집의 `HouseVisionPoint` 반경은 4.2이고 집의 시야점도 바닥 위 0.8에 있다. 두 시야는 높이를 포함한 3D 거리로 합쳐진다. 프로토타입처럼 벽에 의한 시야 차폐는 하지 않는다. 마우스가 Game 표시 영역이나 맵 밖으로 나가면 마우스 시야만 사라진다. 집의 금색 창 유리는 밤에 약한 흰색에 가까운 빛으로 발광하고 주변 표면에도 낮은 강도의 빛이 남는다. 블룸 대신 픽셀 색으로 표현한다.

`Day01Showcase` Inspector의 Vision Height / Cursor Vision Radius / House Vision Radius를 Play 전에 조절할 수 있다. 독립 `Afterlife.Devlog.Lighting` 표현 모듈에 메인 쇼케이스가 입력과 단계 선택을 전달한다. 단계 전환은 낮·밤 상태를 유지하고 현재 공간으로 집 시야를 옮긴다. 종료 시 전용 셰이더 전역값, 태양과 카메라 배경을 복원하고 임시 시야점을 제거한다.

확인: Refresh → Play → Game 클릭 → 3 → N. 밤에 집 창이 빛나고 주변이 어두워지는지, 빈 바닥에 마우스를 움직여도 시야가 따라오는지 확인한다. Game 밖으로 마우스를 옮겨도 집 주변 시야는 남아야 한다. 다시 N을 누르면 낮으로 돌아오고 1/2/3 전환 시 현재 공간에 시야가 있어야 한다. 조명·런타임·에디터 C# 빌드는 통과했으며 실제 화면은 직접 확인하지 않았다.

## 굴뚝 연기와 창문 불빛

집 주변 고정 시야 반경 4.2는 유지한다. 주변 표면에 더하던 조명 색만 제거하고 금색 창 유리에만 약한 따뜻한 발광을 적용한다. `ShowcaseSmoke`는 모델 단계와 After의 House의 저장된 클릭 메시를 월드 좌표로 변환한 뒤 최고 높이 면의 고유 정점 중심에 ParticleSystem을 생성한다. 현재 House의 최고 면은 굴뚝 입구이며, 하드코딩된 제작 좌표 대신 실제 FBX 축/회전/크기를 반영한다. 집 모델을 교체해 지붕이 굴뚝보다 높아지면 전용 입구 마커로 바꿔야 한다. Billboard 렌더러의 quad에 3단계 노이즈/왜곡과 원형 가장자리 마스크를 적용한다. 초당 8개의 연기가 올라가며 크기가 퍼지고 수명이 끝날 때 투명해진다. 굴뚝 위 1.1~2.2 높이에서도 투명도를 줄여 윗부분이 자연스럽게 사라진다. R 또는 단계 전환 시 기존 연기를 지우고 다시 방출하며 종료 시 시스템과 임시 머티리얼을 해제한다. Before에는 굴뚝 모델이 없어 연기를 추가하지 않는다.

확인: Refresh → Play → 3에서 굴뚝의 연기가 위로 올라가며 퍼지고 사라지는지 확인한다. N으로 밤을 켜 창문만 약한 따뜻한 색으로 빛나는지 확인하고, 마우스를 Game 밖으로 옮겨도 집 주변 시야가 남는지 확인한다. C# 모듈 빌드는 확인하며 실제 셰이더 화면은 직접 검증하지 않는다.

## 현관 길과 빌보드 풀

레이아웃 버전 7은 길을 남쪽 입구 → 중앙 굽이 → 집 현관 앞 방향으로 바꾼다. 세 단계의 타일 데이터를 갱신하며 길 위 작은 장식은 비활성화한다. 육지 높이와 수면 구성은 유지한다.

독립 `Afterlife.Devlog.Vegetation` 모듈은 Process/After의 Grass 타일에만 풀 quad를 배치한다. Perlin 밀도와 고정 시드로 분포·크기를 정하고 건물과 자원 밑은 제외한다. 단계별로 한 메시로 묶고 셰이더에서 카메라 방향의 수직 빌보드로 만든다. quad 안 풀잎 다섯 개는 gradient Perlin 노이즈로 길이·굽힘·가장자리·색이 달라진다. 두 주파수의 Perlin 바람으로 윗변 두 점을 같은 거리만큼 좌우 이동한다. 별도 Perlin 흐름으로 앞뒤 기울임을 만들고, 밑변 중앙은 고정한 채 가상 깊이에 따른 원근 배율로 윗변의 폭과 높이를 바꾼다. 직교 카메라에서도 원근 효과가 보인다. 풀은 낮·밤/시야 조명을 공유하며 클릭 대상은 아니다. 종료 시 생성 메시·머티리얼을 해제한다.

확인: Play 정지 → Refresh → Play → 3. 현관까지 이어진 길, 풀 타일의 군락, 고정된 밑변과 좌우/앞뒤로 흔들리는 윗부분을 확인한다. P로 픽셀 표현을 끄면 기울임 차이를 더 쉽게 볼 수 있다. N으로 밤의 풀과 시야 감쇠도 확인한다. 코어/식생/런타임/에디터 C# 빌드는 경고·오류 없이 통과했고 실제 화면은 직접 확인하지 않았다.

## 입체 지형과 타일별 장식 변형

레이아웃 버전 8은 Process/After의 육지 타일을 4×4 구획의 낮은 굴곡 메시로 교체한다. 모든 타일 테두리는 y=0으로 맞추고 안쪽 높이만 바이옴별로 달리한다. 높이 기준은 흙길 0.018, 모래 0.035, 풀/숲 0.055, 눈 0.085, 암석 0.12이며 형태·정점 변화에 따라 달라진다. 건물/환경 모델이 걸친 타일은 평평한 버전으로 유지한다. Before와 기존 물/5% 해저 구성은 바꾸지 않는다. 블록 바닥은 기존 높이를 유지한다.

`ShowcaseTileVariants`는 Unity 참조 없는 지형 코어에서 좌표별 고정 시드로 4종 높이 형태, 0/90/180/270도 회전, 바이옴별 장식 유형을 고른다. 암석은 빈 타일·자갈·돌+고사리, 초원은 빈 타일·꽃·자갈·고사리, 숲은 빈 타일·고사리·돌+고사리, 눈/모래는 빈 타일·드문 자갈로 구성한다. 흙길에는 장식을 놓지 않는다. 장식은 `TileDecoration_*` 자식으로 타일에 종속되며 타일과 함께 회전한다. 기존 FBX를 재사용하고 건물/자원에 겹치는 배치는 제외한다. 기존 BiomeDetails는 비활성 상태로 보존한다.

색을 잘게 찍던 지형 셰이더 노이즈를 제거하고 절제된 바이옴 색·넓은 정점색 영역·실제 삼각형 면의 명암으로 표현한다. 풀 군락과 자원 밑동도 회전된 타일의 삼각형 표면 높이에 맞춘다. 생성 메시와 머티리얼은 Geometry/Materials에서 유형별로 재사용한다.

확인: Play 정지 → Refresh → Play → 2/3. 타일 경계에 틈이 없는지, 내부 면의 굴곡과 명암이 보이는지, 같은 바이옴에 빈 타일과 장식 타일이 섞이는지 확인한다. 풀/꽃/돌이 떠 있거나 땅에 깊게 묻히지 않아야 하고 현관 길과 물/해저 높이는 유지돼야 한다. 코어·식생·런타임·에디터 C# 빌드는 경고/오류 없이 통과했으며 실제 화면은 직접 확인하지 않았다.

## 설치와 수명

### 완성 단계의 일반 클릭 피드백

레이아웃 버전 10은 After의 활성 지형·장식 메시에도 표면 클릭 데이터를 연결한다. 자원이 아닌 표면을 클릭하면 교차점에서 크기 0.03의 파편 4개가 표면 바깥으로 짧게 튀고 0.32초 안에 사라진다. 색은 기존처럼 교차 삼각형의 정점색과 해당 서브메시 머티리얼색을 곱해 구하며, 물은 얕은 물의 기본색을 쓴다. 조명/그림자/거품까지 포함한 화면 픽셀을 읽는 방식은 아니다. 도구 모션·화면 흔들림·타격음은 발생하지 않는다. 기존 나무/바위 타격과 눈 파편은 유지하고 도구 타격 중에는 일반 클릭을 추가하지 않는다. Before/Process에는 적용하지 않는다.

확인: Refresh → Play → 3에서 흙·풀·암석 타일과 집 벽을 클릭해 작은 파편과 색 차이를 확인한다. 지형에 가려진 자원이 선택되지 않는지, 나무/바위의 기존 타격이 유지되는지 확인한다. 런타임/에디터 C# 빌드는 통과했으며 실제 화면은 직접 확인하지 않았다.

### 사용자 제공 풀 PNG

현재 기본 풀 실루엣은 사용자 제공 16×16 PNG 네 장을 `Resources/GrassSprites/Grass0~3.png`에 원본 그대로 저장해 사용한다. 셰이더로 만들던 잎 모양은 제거했다. 각 quad에 한 이미지를 고정 시드로 선택하며, 투명 여백을 제외한 UV와 원본 비율을 사용해 밑부분을 지면에 맞춘다. 에디터 임포터는 Point 필터·Clamp·무압축·mipmap 없음으로 설정한다. PNG 알파로 모양을 정하고 흰 영역은 타일색으로 착색한다. 3단계 명도, 희귀 풀/꽃, 좌우·앞뒤 바람은 유지한다. Refresh → Play → 3에서 네 종류 픽셀 실루엣과 지면 접촉을 확인한다. 식생/에디터 C# 빌드는 통과했고 실제 화면은 직접 검증하지 않았다.

수면 거품 크기는 `Foam pattern size` 1.7로 확대했다. 흰 거품은 `White foam minimum strength` 0.8로 노이즈/해안 거리 감쇠 하한을 올리고 선 폭도 넓혀 선이 완전히 사라지는 구간을 줄였다. 셀 내부의 물 공간은 유지한다. 두 값은 After_OceanDepth 머티리얼에서 조절할 수 있다. Refresh 후 Play → 3에서 큰 거품 무늬와 지속되는 흰 거품 선을 확인한다. 이번 변경은 셰이더/머티리얼 조정이며 실제 GPU 렌더링은 직접 확인하지 않았다.

### 풀 색 일치와 희귀 군락

기본 풀의 기준색은 해당 타일의 `_BaseColor`에서 가져온다. 뿌리는 그 색을 유지하고, 지면 법선과 같은 명암/그림자 계산을 적용한다. Perlin 값 0.42 미만은 0.88배, 0.42~0.58은 1배, 0.58 이상은 1.12배 명도로 분류해 군락의 윗부분에 반영한다. 잎마다 무작위 얼룩을 추가하지 않는다.

고정 시드로 일반 풀 94%, 1.55배 키의 황갈색 풀 2%, 0.55배 높이의 검은 풀 1%, 같은 높이의 흰 풀 1%, 작은 꽃 2%를 배치한다. 꽃도 billboard quad에 줄기와 다섯 꽃잎을 절차적으로 그리며 기존 타일 꽃 장식은 유지한다. 낮은 풀은 흔들림 폭도 작다. Refresh 후 Play → 3에서 기본 풀 뿌리가 바닥과 자연스럽게 이어지는지, 어두움/기본/밝음 군락과 드문 특이 풀·꽃이 섞이는지 확인한다. 식생/런타임 C# 빌드는 통과했고 실제 화면은 직접 확인하지 않았다.

### 사분면 패턴 제거 — 버전 9

이전의 2×2 영역별 정점색 분할을 제거해 모든 지형 정점색을 흰색으로 통일했다. 내부 꼭짓점의 X/Z 위치와 높이를 고정 시드로 불규칙하게 배치하고 삼각형 대각선 방향도 바꾼다. 높이 형태는 16종으로 늘렸으며 테두리 좌표와 높이는 고정한다. 명암 단계 강도도 0.6에서 0.25로 낮춰 넓은 사각형 밴딩을 줄였다. 풀/장식/자원 높이는 새 불규칙 삼각형의 무게중심 보간으로 맞춘다.

흙길에는 빈 타일과 DirtClods 타일이 섞인다. 흙 덩어리는 기존 Pebbles 메시를 낮게 눌러 흙색 머티리얼로 표현하며 타일 자식으로 배치한다. 기존 생성 장식은 Undo를 지원하는 방식으로 교체해 중복을 방지한다. Refresh → Play → 3에서 사분면 색 분할이 없어졌는지, 불규칙한 면의 명암과 낮은 흙 덩어리가 보이는지 확인한다. 관련 C# 모듈 네 개의 빌드는 경고/오류 없이 통과했으며 실제 화면은 직접 검증하지 않았다.

### 타격 방향 반동

기존 크기 변형과 고정 Z축 흔들림을 제거했다. 표면 교차점에서 밑동 중심으로 향하는 수평 방향으로 밀리고 기울어진 뒤 감쇠 진동으로 복귀한다. 중심 바로 위의 타격은 도구의 진행 방향을 사용한다. 나무는 크게 기울고 약하게 이동하며, 바위는 작게 기울고 짧게 밀린다. 원본 크기는 항상 유지하고 R/비활성화 시 원래 위치·회전을 복원한다. Refresh → Play → 3에서 같은 자원의 좌우 표면을 각각 때려 첫 반동 방향이 반대로 바뀌는지, 크기가 변하지 않는지, 반동 후 제자리에 돌아오는지 확인한다.

### 눈 제거 경계와 파편 발생 영역

눈 타격의 원형 거리 감쇠에 모델 로컬 좌표의 3D 노이즈 두 주파수를 섞어 경계를 불규칙하게 만든다. 남은 눈이 적으면 원재질 색으로 부드럽게 섞이고 고정된 미세 노이즈 마스크로 잘게 사라진다. CPU와 HLSL에서 같은 정수 해시·보간·감쇠식을 사용해 눈 메시 두께, 화면, 깊이·그림자, 클릭 판정의 경계를 맞춘다. 노이즈는 시간에 따라 변하지 않아 경계가 반짝이지 않는다.

타격 전 눈 윗면의 삼각형에서 면적 표본을 모으고 타격 후 남은 눈을 비교한다. 실제 눈 감소가 있는 표본만 대상으로 면적×감소량에 비례해 최대 20개의 방출 위치를 선택한다. 이미 벗겨졌거나 영향받지 않은 부위, 눈 덩어리 밑면에서는 방출하지 않는다. 기존 한 점 주위의 임의 위치 생성은 제거했고 눈 파편의 아래 방향 속도와 중력은 유지했다. Refresh → Play → 3에서 경계가 원형으로 잘리지 않는지, 파편이 눈이 털린 표면 범위에서 떨어지는지, 눈 없는 곳을 계속 때려도 눈 파편이 나오지 않는지 확인한다.

나무와 돌은 각 단계의 로컬 좌표를 `ShowcaseBiomeMap`에 조회해 바이옴을 판정한다. Play 중 모델 단계와 After의 눈 바이옴에서는 월드 법선이 위를 향하는 면에 눈을 덮고 줄기 옆면과 아랫면은 원색을 유지한다. 공유 머티리얼을 변경하지 않고 오브젝트별 프로퍼티 블록으로 적용한다. 다른 바이옴으로 이동하면 눈 표현도 해제된다. After에서 눈 덮인 자원을 때리면 기존 표면색 파편 9개를 유지하면서 눈 파편 20개를 추가한다. 눈 파편은 더 작고 납작하며 아래 방향 초기 속도와 중력 7.5로 최대 1.05초 동안 우수수 떨어지고, 바닥에 닿으면 0.16초 이내에 사라진다. R/단계 전환/비활성화 시 기존 파편과 함께 정리된다. 눈은 원본을 변형하는 대신 별도 SnowCap 메시로 생성한다. 위를 향하는 면과 콘형 나무의 초록 잎 면을 선택하고, 면을 분할한 뒤 같은 위치의 정점을 공유한다. 공유 법선으로 두께 0.045의 윗면을 만들고 테두리 옆면과 밑면을 연결해 면 사이가 벌어지지 않도록 한다. 원본 메시/FBX는 그대로 유지한다. 타격 지점의 눈 두께를 CPU에서 줄이고 눈/깊이/그림자 셰이더와 클릭 판정에서 완전히 벗겨진 부분을 제외한다. 생성한 눈 메시도 독립적인 클릭 표면으로 등록한다. 클릭 메시에도 같은 변형과 바람을 적용하며 깊이/그림자 패스도 변형을 공유한다. 콘형 Tree1은 정점 팔레트로 잎과 줄기를 구분해 잎 전체를 눈으로 덮는다. 타격 지점은 모델 로컬 좌표로 보관하고 주변 눈 색과 두께를 함께 줄인다. 한 지점의 제거 강도는 타격마다 0.55 증가한다. 한 테이크에 최대 32개 영역을 기억하며 이후 타격은 가장 가까운 기록에 누적한다. R/단계 전환 시 눈이 복원된다.

레이아웃 버전 4에서는 세 단계의 마지막 돌 하나를 로컬 (-4.6, 0, 4.2)로 옮겨 눈 덮인 나무와 돌을 함께 비교할 수 있게 한다. Before는 눈 표현을 적용하지 않는다. 확인 절차는 Refresh → Play → Game 클릭 → 3이며, 뒤쪽 왼편 눈 타일의 나무/돌을 때릴 때 흰색·옅은 파란색 눈 파편과 원래 재질색 파편이 함께 보여야 한다. 일반 바이옴의 자원에는 눈 덮임과 눈 파편이 없어야 한다.

`Day01SceneBuilder`는 처음 임포트될 때 씬이 없으면 새 씬을 별도로 생성하고 닫는다. 이미 존재하는 Devlog 씬과 사용자가 열어 둔 씬은 덮어쓰지 않는다. Tools 메뉴와 Build Settings 항목은 추가하지 않는다. `.meta`는 Unity가 생성한다.

런타임·에디터는 각각 독립 asmdef다. 이 모듈은 촬영용 Unity 표현 계층이며 게임 로직/전역 서비스에 의존하지 않는다. 게임 프로토타입의 렌더 파이프라인 에셋을 복제해 실행 중에만 사용하고, 비활성화 시 이전 파이프라인을 복구한다. 임시 RenderTexture·파편·파이프라인 인스턴스도 해제한다. 다른 게임 씬과 동시에 Additive 재생하는 용도로 설계하지 않았다.

## 검증과 직접 확인

바이옴 배치는 Unity 참조가 없는 `Afterlife.Devlog.Terrain` 코어 모듈이다. 코어·런타임·에디터 모듈을 각각 `dotnet build --no-restore`로 컴파일했고 경고 0개, 오류 0개였다.

House 지붕 네 면의 winding을 바로잡았다. Blender 원본과 House FBX를 갱신했고 `tools/art/build_world.py`의 roof 생성 함수도 수정해 재생성 시 문제가 반복되지 않게 했다. 원본 House를 공유하는 프로토타입에도 지붕 수정이 반영된다.

저장소 AGENTS.md 규칙에 따라 Unity EditMode/PlayMode 테스트와 플레이 스모크 테스트는 실행하지 않았다. 셰이더의 실제 렌더링, 화면 구도, 효과음과 타격 재생은 아래 순서로 직접 확인해야 한다.

1. 씬을 단독으로 열고 Play → 집 지붕의 겉면과 12×10 바이옴 격자를 확인한다. After의 육지는 두께 0.8의 블록, 물은 높이 0.04의 해저 위에 0.36 높이로 쌓여 합계 0.4여야 한다. Before/중간 단계는 기존 얇은 바닥을 유지해야 한다.
2. 1 → 2 → 3을 눌러 같은 구도의 primitive → 모델 → 픽셀 화면으로 전환되는지 확인한다.
3. After에서 앞쪽 바위와 양옆 나무의 보이는 표면에 마우스를 올리고 클릭한다. 대상 강조, 타격 섬광·흔들림·파편·도구와 소리가 나오고 자원은 남아 있어야 한다. 빈 공간, 수면, 집 지붕을 클릭하면 뒤쪽 자원은 반응하지 않아야 한다.
4. H로 안내를 숨기고 P로 픽셀 크기 차이를 비교한다. 화면 구도와 클릭 위치는 유지되어야 한다.
5. R 또는 단계 전환 직후 진행 중인 타격 반응이 정리되는지 확인한다. 재생 종료 후 일반 게임 씬을 열었을 때 기존 렌더 설정이 유지되어야 한다.
6. After에서 나무와 바위의 서로 다른 높이/좌우 표면을 클릭한다. 도끼 날/곡괭이 끝과 파편 시작점이 클릭한 교차점에서 만나야 한다. 클릭 직후 마우스를 다른 곳으로 옮겨도 최초 목표를 때려야 한다.
7. 나뭇잎과 줄기, 일반 돌과 수정 부분을 각각 때려 파편의 색이 클릭한 부분의 색에 따라 바뀌는지 확인한다.
8. After 바다에서 흰 거품 위층과 하늘색 거품 아래층, 물 아래 해저·자갈을 확인한다. 거품은 보로노이 셀에 연속 노이즈 왜곡을 적용하며 각 층의 시드(17.3 / 83.7)와 이동 방향이 달라 독립적으로 움직여야 한다. 얕은 물 불투명도는 0.60, 깊은 물은 0.95로 이전보다 덜 비치고, 깊을수록 어두워져야 한다. P를 켜고 꺼도 깊이와 해저의 위치가 일치하고, 물끼리의 경계에 어두운 겹침 줄이나 해안 거품이 생기지 않아야 한다. 거품 두 층은 별도 메시가 아닌 수면 셰이더 안에서 하늘색 → 흰색 순으로 합성한다. 머티리얼의 Lower foam / Surface foam 색과 Blue foam seed / White foam seed로 각각 조정할 수 있다.

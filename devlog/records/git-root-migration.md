## 변경 전후

기존 Git 루트는 `impls/unity/Afterlife/`였고 main에 34개 파일의 실질 변경과 1,277개 신규 파일이 쌓여 있었다. 로컬 main의 시작점은 `495dc78063c8c58ab3e847c57faeee9959e1e14f`다. 로컬 origin/main 참조보다 32커밋 앞선 상태였으며 원격 최신 상태는 조회하지 않았다.

Git 루트를 프로젝트 최상위로 옮겼다. Unity 프로젝트와 에셋의 실제 디스크 경로는 바꾸지 않았다. 기존 커밋을 재작성하지 않고 새 경로 변경 커밋을 추가했다.

- main 경로 변경: `17327da7c151b803ec5b3c76e3a015b3811d4626`
- 기능별 커밋 완료점: `1d8efff12e1de6c21b240b9c751fb2fb62e6b2ef`
- dev 루트 통합: `3a1b3d985573953d74bd7f99c5c542626faed1f6`

dev 루트 통합 커밋은 기능별 개발 커밋과 main 경로 변경 커밋을 부모로 갖는다. 따라서 main은 dev의 조상이며, 이후 검증을 마치면 정상 병합할 수 있다. main에는 미검증 신규 게임 기능을 넣지 않았다.

## 보존과 검증

- 원래 추적 파일과 신규 Unity 파일 3,226개의 SHA-256을 기록했다. 로그 문자열 복원 외에 파일 바이트가 보존됐는지 대조했다.
- main/dev의 경로 변경 전 전체 Git 트리와 변경 후 `impls/unity/Afterlife/` 하위 트리의 객체 ID가 동일함을 확인했다.
- 신규 Unity 에셋의 기존 `.meta`를 함께 커밋했다. `.meta`를 만들거나 수정하지 않았다.
- 기존 브랜치·원격 추적 참조·stash 및 원격 URL을 유지했다. 기존 브랜치와 stash는 이전 경로를 사용하므로 [Git 운영 규칙](../../docs/git-workflow.md)의 복구 절차를 따른다.
- Windows 이동 과정에서 남은 빈 숨김 폴더를 제거하고 사용자 소유의 루트 `.git` 폴더를 구성했다. 전역 safe.directory 설정은 변경하지 않았다.
- 자동 생성 프로젝트에 이전 Moonstone 경로가 남아 있어 기존 `Temp/MoonstoneMigration/*.csproj` 검증 프로젝트를 사용했다. Devlog 및 독립 모듈은 기존 `*.ModuleValidation.csproj`로 검증했다.
- 빌드 로그와 초기 Git 번들은 `local-backups/git-root-migration-20260920/`에 보관한다. 백업·로그·분석 도구 설치본·과거 배포 ZIP·별도 3D Test 프로젝트는 로컬에 보존하고 Git에서 제외한다.

기능별 커밋 이후 `Mona12TextKR SDF.asset`의 동적 글리프 테이블과 아틀라스 캐시 갱신을 관찰했다. 이 후속 변경은 초기 기능 정리 대상과 구분해 로컬 미커밋 상태로 보존했으며 되돌리지 않았다.

## 사용자 확인 절차

1. Unity Hub에서 기존 경로 `impls/unity/Afterlife/`를 연다. Console에 새 어셈블리 또는 에셋 참조 오류가 없어야 한다.
2. 기존 Main/Field/World 장면에서 월드 생성, 건설 가이드와 웨이브 스폰을 확인한다.
3. `Afterlife_PixelPrototype`에서 타이틀 진입, 건설·전투·강화·환생과 재진입을 확인한다.
4. `Devlog_Day01`에서 Before/After 전환, 지형 선택, 물 호버음, 식생·눈·타격·파괴·낮밤 표현을 확인한다.

이번 검증은 C# 컴파일과 Git/파일 보존 확인이다. Unity Play, GPU 표현, 청취 및 Player 빌드는 실행하지 않았다.

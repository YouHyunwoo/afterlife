# Day01 → 프로토타입 이관 기록

1~10번 기능 묶음의 코드 이관과 커밋을 완료하여 임시 컨텍스트를 영구 기록으로 전환했다. Unity 실제 화면·청취 검증은 완료로 간주하지 않으며 아래 확인 절차로 추적한다. 이후 본문의 시간순 작업 메모는 당시 상태를 보존한다.

## 확정된 방향

- 최신 확정 규칙: 모든 커서 상호작용은 직접 클릭으로 시작하고 자동화 강화 후 호버 주기 방식으로 전환한다. [상세](../../docs/game-process/46-click-work-and-automation.md).
- Day01 공용 모듈을 지도·셰이더·입력 주입으로 재사용한다. 공용 표현과 게임 규칙을 분리한다.
- 시야는 Day01 단일 방식. 지형/수면/해안 수직면은 남고 풀·오브젝트는 시야 밖에서 숨는다. 마우스 시야 잔상을 유지한다. 디더·알파 비교 버튼은 제거했다.
- 일반 풀/식물 장식은 지형의 기준색을 공유한다.
- Settings의 Camera Ground Distance는 실제 forward 거리와 직교 표시 범위를 함께 조절한다. 사용자 동작 확인 완료. 커밋 `e31497b`.
- 기능별 커밋은 사용자 요청 시 수행한다. Unity Play/Test Runner/배치 검증은 실행하지 않는다. C# 빌드와 화면 검증 상태를 구분한다.

## 현재 연결 지점

- `PrototypeVegetation.cs`: 풀/잎/바람, 지면 색 텍스처, 풀 가림 및 해제.
- `PrototypePresentation.cs`: 효과 초기화/갱신/판 초기화/종료.
- `PrototypeInteraction.cs`: 커서 지형 선택, 입력 차단, 시야 업로드, 카메라 조절.
- `PrototypeHover.cs`: Hover 모듈에 지도/흙먼지 셰이더/커서 이동을 주입한다. 타일 중심 좌표 차이(-0.5)를 어댑터에서 보정한다.
- 공용 `ShowcaseTileHover.Map`: Day01 기본값을 보존하며 임의 지도 범위와 바이옴을 받는다. 셰이더 전역값은 생성 시 보관/해제 시 복원한다.
- TerrainSurface.Raycast의 선택적 높이 함수는 흔적으로 변형된 삼각형 선택에 사용하며 활성 지형 흔적이 있을 때만 적용한다.
- `PrototypeSurfaceFeedback.cs`: 나무·바위의 읽기 가능한 원본 메시만 ShowcasePickSurface로 등록한다. 원본 메시 캐시 수명은 Interaction 모듈이 담당하며 삭제/재시작 시 컴포넌트와 함께 해제한다.
- 다음 시작점: 오브젝트 적설·눈 타격 침식. Snow의 ISnowTarget 어댑터와 프로토타입 자원 수명 연결을 조사한다.

## 보존해야 할 미커밋 변경

기여 주기(2→1), UI 씬·프리팹, 폰트 변경은 기존 별도 작업이므로 덮어쓰거나 이관 커밋에 섞지 않는다.

## 검증

이전: Devlog 21개 모듈/프로토타입 C# 빌드 통과. GPU/HLSL/Play는 사용자 확인 대상. 카메라 조절만 사용자 동작 확인을 받았다.

## 이번 묶음 확인 절차

1. Afterlife_PixelPrototype의 풀 위로 마우스를 움직이면 Sway 반응 후 복원되어야 한다.
2. 물 위로 움직이면 간격을 두고 원형 파문과 거품 변화가 보이고, 정지하면 새 파문 없이 약 2초 안에 잦아들어야 한다.
3. 흙 위로 움직이면 먼지가 발생하고 시야 밖에서는 숨는다. 모래/눈 지면은 흔적이 생긴 뒤 약 2.5초에 복원된다.
4. UI 위, 카메라 이동/회전 중에는 새 흔적이 생기지 않는다. 메뉴에서는 흔적·먼지가 멈추고 재시작하면 초기화된다.
5. Day01에서도 기존 반응이 유지되고 두 씬을 번갈아 실행해 이전 흔적이 남지 않는지 확인한다.

검증 결과: Devlog 21개 모듈 및 프로토타입 C# 빌드 통과. 기존 Day01 CS0252 경고는 유지. Unity Play/HLSL 검증은 미실행이다. 새 에셋의 .meta는 Unity 자동 임포트에 맡긴다. 이 묶음에는 음향, 오브젝트 적설 침식, 타격 자국이 포함되지 않는다.

표현 한계: 모래/눈 흔적의 기하 정밀도는 기존 지형 세분화(일반 0.25m)에 따른다. 흔적 주변 정적 장식/게임 개체의 기준 높이는 변경하지 않는다. GPU 비용과 실제 화면은 아직 측정하지 않았다.

## 정밀 표면 선택·타격 자국 묶음

- 기존 콜라이더 후보 탐색 후 나무/바위만 공용 삼각형 교차 계산으로 정밀 확인한다. 빌보드 잎과 접지 메시를 제외한다. 읽기 가능한 메시가 전혀 없으면 기존 콜라이더 선택을 유지하며 자국은 추가하지 않는다.
- 도구 접근 방향으로 실제 메시를 레이캐스트하여 날의 접촉점을 맞추고, 기여 이벤트당 한 번만 자국을 추가한다. 실제 메시를 만나지 못하면 기존 도구 접촉 위치를 유지한다.
- DamageMarks의 표면 로컬 좌표 이력(최대 8개, 근접 자국 병합)과 HLSL을 재사용한다. 나무는 껍질의 V형 자국, 바위는 밝은 파인 면과 누적 균열이다. 초록 수관에는 도끼 자국을 그리지 않는다.
- 틴트 변경은 기존 MPB를 보존한다. 타격 자국/Transform 변경 시에만 배열과 행렬을 업로드한다. 재시작/제거/씬 종료 때 등록과 이력을 해제한다.
- 이 절은 이전 이관 기록이다. 이후 직접 클릭→자동화 규칙이 채택되어 입력 규칙을 변경했다. 실제 메시 절삭은 없으며 수관 바람/잎 카드의 GPU 변위까지 정밀 선택에 반영하지 않는다. 건물·유닛은 기존 선택을 유지한다.

검증: 프로토타입 `dotnet build --no-restore` 오류/경고 0개. 공용 Interaction/DamageMarks 코드는 그대로 재사용했다. HLSL/Unity Play 검증 미실행.

사용자 확인: 나무·바위 가장자리/빈 공간에서 선택이 메시와 맞는지 확인한다. 클릭 작업 및 자동화 후 호버 작업 시 도구 날이 표면에 닿으며 자국이 누적되어야 한다. 마우스를 올렸다 빼도 자국이 유지되고, 흔들릴 때 함께 움직이며 시야 밖에서 숨겨져야 한다. 자원 소멸/재생성 및 재시작 후 이전 자국이나 MissingReference 오류가 없어야 한다.

## 클릭 작업 전환 및 타격 피드백

모든 커서 작업의 수동/자동화 전환, R8 첫 단계 해금, 도끼/곡괭이 준비→접촉→회수, 공용 타격 정지·반동·섬광·작은 파편을 추가했다. 누적 표면 자국을 유지한다. 미커밋이며 C# 빌드 통과, Unity 체감 확인 대기. 전체 파괴 연출은 다음 묶음이다. 상세 규칙과 수동 확인 절차는 위 최신 규칙 문서를 따른다.

## 도구 표시·모션 일치 보정

사용자 확인에서 프로토타입의 무작위 도구 방향과 등장 위치/궤적 차이가 발견됐다. 도끼·곡괭이는 Day01처럼 FBX 루트 축을 보존하고 FrontMarker 보정을 생략한다. 실제 ImpactPoint를 정렬하며 클릭/자동 스윙 시작 시 카메라 회전과 접근 벡터(right .45 + up .55 - forward .25)를 고정한다. 접근은 제곱 가속, 회전 -65→25도, 접촉 .12초, 정지 .045초, 전체 .285초 뒤 숨김으로 맞췄다. 수동 타격점 고정과 자동 대상별 도구는 유지한다. C# 빌드 통과, Unity 화면 확인 대기.

## 수동 작업 쿨타임

사용자 확정: 클릭 작업 쿨타임은 자동화 주기(Interval)의 절반이다(사용자 후속 요청: 클릭만 2배 빠르게). 자동화 주기와 도구 애니메이션 시간은 유지한다. 기존 0.285초 입력 제한을 제거하고 모델에서 작업 예약/쿨타임을 관리한다. 모든 대상이 하나의 쿨타임을 공유하고 승인된 클릭부터 계산한다. 대기 클릭은 버리며 접촉 전 취소는 예약/쿨타임을 환원한다. 초기화/환생 시 첫 클릭은 즉시 가능하다. C# 빌드 통과, Unity 연타/일시정지/주기 변경 확인 대기.

## 공격 3종·망치·상호작용 피드백

공격은 우/좌 대각 베기·내려베기 중 무작위 1종을 스윙 전체에 고정한다. 망치도 카메라 기준 표면 접촉/회수로 변경했다. 읽기 가능한 상호작용 메시 전체로 표면 선택을 확장하되 자국은 나무/바위만 유지한다. 공격/채집에만 플래시, 건설/수리/이전에는 무플래시 작업 반동·녹색 입자, 상자/귀중품에는 손 동작·금색 입자를 적용한다. 접촉 프레임을 보장하고 같은 프레임 중복 피격 이벤트의 방향 손실을 막았다. C# 빌드 통과, Unity 확인 대기, 미커밋. 상세 확인 절차는 규칙 문서 46번에 기록했다.

## 검 손잡이 축·상자 타격 보정

검 3종은 칼끝을 이동시키는 방식에서 손잡이 축 회전으로 교체했다. 손잡이/칼날 접촉점은 모델 경계 기반이며 준비→가속→접촉 정지→관성 마무리로 이어진다. 상자는 손 도구를 생성하지 않고 맞은 위치 반대 방향으로 밀림/기울기 반동을 준다. 사용자 추가 요청에 따라 상자 타격 플래시도 적용했다. 건설/수리는 무플래시 유지. C# 빌드 통과, Unity 확인 대기.

상자 반동 방향 보정: 화면에 보이는 메시 경계 중심의 수평면에 클릭 광선을 투영하고 중심에서 클릭 반대 방향을 구한다. 시작 시 방향을 고정하며 중앙 클릭은 카메라에서 멀어지는 지면 방향으로 처리한다. 최대 0.14m 이동 후 약 0.265초에 원위치로 돌아오고 반대편으로 재진동하지 않는다. 플래시/기울기/상자 열림은 유지한다. Unity에서 상자 왼쪽·오른쪽·위·아래를 클릭해 반대쪽 반동이 보이는지 확인한다. C# 빌드 통과, 화면 확인 대기.

## 파괴·파편·제거 연출 묶음

- PrototypeDestruction 어댑터가 모델에서 소진된 나무/바위 뷰를 연출 완료까지 보존한다. 획득량/자원 제거 등 게임 규칙은 기존 모델이 결정하며 추가 보상은 없다.
- 나무: 마지막 타격 반대 방향으로 기본 1.1초/88도 넘어짐, 약 0.55초 유지 후 1.15초 디졸브. 잎 카드에 원본 수관의 제거 속성과 버전을 전달한다.
- 바위: 공용 ShowcaseDestruction에서 6개 조각을 생성하여 1.5초 튕김/구름 후 1.15초 디졸브. 원본 뷰는 즉시 숨기며, 접지용 메시가 파편으로 선택되지 않도록 필터를 주입한다. 원본 재질/색을 유지하고 타격 플래시·자국은 파편에 복사하지 않는다.
- 프로토타입 PixelSurface도 공유 ShowcaseDissolve를 사용한다. 시야 감쇠·시야 밖 숨김은 유지한다.
- 입력 콜라이더는 파괴 시작 때 끄고, 판 초기화/씬 종료/연출 완료 때 모듈 및 생성 조각을 정리한다. 메뉴 중에는 진행이 정지한다.
- 공용 모듈 기존 호출은 선택 인자 추가로 보존한다. 새 메타데이터는 Unity 임포트가 생성한다.

검증: Devlog 21개 모듈과 프로토타입 C# 빌드 통과. Unity/HLSL/Play 미실행. 나무/바위를 끝까지 채집해 위 순서대로 사라지는지, 잎만 남지 않는지, 시야 이탈·메뉴·재시작 후 파편/유령 콜라이더가 남지 않는지 확인한다. 실제 메시 절삭이나 물리 Rigidbody 파괴는 아니며 원본 바위 메시를 작게 복제한 시각 조각이다.

## 오브젝트 적설·눈 타격 침식 묶음

- 눈 바이옴의 읽기 가능한 고정 오브젝트 메시(나무·바위·건물·상자 등)에 Day01 ShowcaseSnowCap을 연결했다. 이동 유닛은 제외한다.
- PrototypeSnowTarget은 ISnowTarget 어댑터로서 32개 국소 타격 기록과 공용 침식 함수를 사용한다. 클릭/자동화의 실제 접촉 시 덮개 두께·면적이 감소하고 눈 조각이 떨어진다. 게임 보상과 쿨타임은 변경하지 않는다.
- 눈 덮개도 정밀 표면 선택에 포함하며 이미 침식된 부분은 통과한다. 눈 표면에는 목재/돌 자국을 새기지 않는다. 원본 및 잎 카드에 적설/침식 속성을 전달한다.
- 프로토타입 셰이더에 적설을 연결해 기존 시야/낮밤 감쇠와 파괴 디졸브를 따른다. 바위 파편의 원본 선택에서 별도 눈 메시를 제외한다.
- 오브젝트 제거·재시작·씬 종료 시 눈 메시와 재질을 해제한다. 메타데이터는 Unity가 생성한다.

검증: 프로토타입 C# 빌드 통과. Unity/HLSL/플레이 검증 미실행. 눈 지역의 나무/바위 상단을 반복 클릭해 눈이 국소적으로 벗겨지는지, 자동화에서도 동일한지 확인한다. 시야 이탈·파괴·재시작 후 눈만 남지 않는지와 건설/수리의 무플래시도 확인한다. 다음 묶음은 환경음·상호작용/파괴 음향이다.

## 환경음·물/타격/파괴 음향 묶음

- 기존 PrototypeAudio의 12채널·종류별 쿨타임·프레임 병합·시야/화면 밖 차단을 유지한다. 자원 효과음은 공용 ShowcaseAudioBank에서 읽는다. 나무 타격은 Day01 피치 변화, 바위 타격은 2종 순차 재생, 자원 소진은 나무 쓰러짐/바위 파괴로 구분한다. 기존 ResourceEmpty 중복 출력은 제거했다.
- 실제 기여가 확정되는 접촉 틱에 채집음이 나며 마지막 채집 틱에는 파괴음도 시작한다. UI·전투·건설·수리 등 기존 효과음은 유지한다. 입력 거절/쿨타임 대기에는 채집음이 나지 않는다.
- 물 파문 생성 이벤트를 ShowcaseAudio에 연결했다. 5종 변형·연속 재생 감쇠·간격·3채널 제한을 재사용한다. 풀 스침은 실제 풀 위에서 포인터가 이동할 때 02~04 음원, 낮의 새 울음은 ShowcaseAmbience 간헐 스케줄을 사용한다. 미사용 바람 음원은 재생하지 않는다.
- SoundVolume을 환경음·물·타격/파괴에 공통 적용한다. 메뉴/정지/포커스 이탈 시 환경음은 비활성화하고 물을 멈춘다. 타이틀/결과 화면에서도 환경음이 페이드아웃하도록 연결했다. 판 초기화와 컴포넌트 해제 시 채널/일정을 정리하고 파문 이벤트 구독을 해제한다.
- 음원 파일을 복제/편집하지 않았다. docs/audio-credits.md에 프로토타입 사용 범위를 기록했다. 공유마당 CC BY의 실제 공개용 게임 크레딧/영상 설명란 반영은 아직 미완료다.

검증: Devlog 21개 모듈 및 프로토타입 dotnet build 통과. Unity 실행/청취 미실행. Unity에서 (1) 나무/바위 클릭과 자동화 접촉음·마지막 파괴음을 확인하고 (2) 풀 이동/정지·물 연속 이동·낮/밤 새 울음을 비교한다. (3) 음량 0·메뉴·타이틀·재시작에서 잔류/중복 음향이 없는지 확인한다. 다음 묶음은 집 연기 등 남은 환경 연출이다.

### 풀 스침 무음 수정

사용자 확인: 프로토타입에서 풀 스침이 들리지 않음. ShowcaseGrass의 접촉 위치 등록이 `map==null`인 Day01 경로로 제한돼 주입 맵의 HasGrassAt이 항상 false였다. 생성된 풀 위치 등록을 주입 맵에도 적용했다. 음량이나 재생 조건을 완화하지 않고 누락된 접촉 데이터를 복구했다. C# 재빌드 및 Unity에서 풀 위 마우스 이동/정지 청취 확인 대상.

사용자 청취 피드백: 프로토타입 풀 스침 기본 볼륨을 0.28에서 0.14로 절반 감쇠했다. 전체 SoundVolume 배율은 유지한다.

## 집 굴뚝 연기 묶음

- ShowcaseSmoke에 선택적인 방출 대상 판정과 셰이더 주입을 추가했다. Day01 기본 House_Pivot 탐색은 보존하며 PrototypeSmoke 어댑터는 완공된 집만 선택한다.
- 원본 메시의 최상단 꼭짓점을 평균하여 Day01처럼 굴뚝 입구를 구한다. 적설 덮개/접지 메시/추가 파티클은 탐색에서 제외한다.
- 3.2~4.4초 수명, 초당 8개, 집당 최대 64개, 위로 상승하며 퍼지는 노이즈 연기 설정을 재사용한다. 식생과 동일한 ShowcaseWind를 주입한다.
- 공용 연기 셰이더 본문을 ShowcaseSmokePass로 분리했다. 프로토타입의 Resources 셰이더는 기존 시야/낮밤 밝기를 주입하며 시야 밖 연기는 숨긴다. 별도 전역 조명 시스템을 시작하지 않는다.
- 건설 중/이전 중에는 방출하지 않고, 완공 후 생성한다. 집 제거 시 입자를 비우고 메시/재질 소유물을 정리한다. 메뉴/모델 정지에는 입자 시뮬레이션을 일시정지하며 판 초기화/씬 해제에도 정리한다.

검증: Devlog 21개 모듈 및 프로토타입 dotnet build 통과. Unity/HLSL/플레이 미실행. 완공된 집 굴뚝에서 연기가 위로 올라가 바람에 흐르는지 확인한다. 밤/시야 이탈, 메뉴 정지/재개, 집 건설·이전·철거, 재시작에서 연기 중복이나 잔류가 없어야 한다. 메타데이터는 Unity 자동 생성 대상이다.

기능 목록 대조: Day01의 폐허 수정 HDR 발광과 밤 창문 Bloom은 아직 별도 대조/이관이 남았다. 집 연기 구현만으로 전체 이관 완료를 선언하지 않는다. 기존 집 주변 광원은 유지했다. 임시 컨텍스트는 이 항목까지 처리한 뒤 영구 기록으로 전환한다.

## 폐허 수정·밤 창문 발광과 Bloom

- 최신 Day01 소스 기준으로 발광 본문을 공용 ShowcaseEmission.hlsl로 추출했다. 수정은 청록 정점 팔레트에 3.5, 밤에는 0.78배, 시간 변화 ±4%. 집 창문은 금색 정점 팔레트에 원래 색조를 보존하여 밤 HDR 2.8, 시간 변화 ±1.5%를 사용한다. 과거 문서의 중간 조정값보다 현재 소스값이 우선이다.
- PrototypeGlow가 Ruins와 완공/이전 중이 아닌 House 원본 표면에 플래그를 부여한다. 적설 덮개·접지·파티클에는 적용하지 않는다. 기존 MPB의 타격/적설 속성을 유지하며 게임 보상·시야 반경은 바꾸지 않는다.
- ShowcaseCrystalGlow에 선택적인 렌더러 목록 주입을 추가했다. 프로토타입은 동적 대상 플래그를 직접 관리하고 공용 모듈의 카메라/Volume 수명과 Bloom threshold 1.15, intensity 0.48, scatter 0.52를 재사용한다.
- 런타임 URP 복사본 HDR과 카메라 후처리를 활성화하고 저해상도 Point 렌더 텍스처를 DefaultHDR로 변경했다. 기존 Renderer.asset의 비어 있던 PostProcessData 참조를 현재 URP 패키지의 실제 GUID로 연결했다. 새 메타데이터는 Unity 임포트가 생성한다.
- 시야 밖 오브젝트 clip 이후에만 발광한다. 창문은 낮에 원래 색이며 밤에 켜진다. 씬 해제 시 Volume/Profile을 제거하고 카메라 상태를 복원한다. 픽셀 해상도 변경 시 HDR 텍스처를 재생성한다.

검증: Devlog 21개 모듈과 프로토타입 C# 빌드 통과. Unity/HLSL/GPU 화면 검증 미실행. (1) 폐허의 수정만 청록색으로 번지는지 (2) 완공 집의 창문만 밤에 따뜻하게 발광하고 낮에 꺼지는지 (3) 시야 밖 대상 자체의 발광이 사라지는지 (4) 해상도 변경·집 이전/철거·재시작·씬 종료 후 오류나 Volume 중복이 없는지 확인한다. Bloom은 화면상 번짐이며 실제 광원/시야 반경 추가가 아니다.

## 이관 구현 완료 및 확인 대기

계획한 1~10번 게임플레이 기능 묶음의 코드 연결을 마쳤다. 실제 화면·청취 확인과 사용자 조정은 별도로 남아 있다. 임시 문서는 해당 확인과 마지막 커밋까지 추적한 후 영구 기록으로 정리한다. Day01 촬영 시퀀스/비교 버튼, 비상호작용 표면을 누르는 촬영용 파편, Sink 비교 모드는 프로토타입 게임 규칙의 이관 대상에서 제외한다. 공개 음원 크레딧은 공개 준비 때 실제 게임/영상에 반영해야 한다.

## 최종 연결 점검

- 이관 기능: 지형/바이옴, 해안/수면, 식생/바람, 단일 시야/잔상, 지면 호버, 정밀 타격/도구, 파괴, 적설, 음향, 연기/발광의 연결을 코드 목록과 대조했다.
- 어댑터 경계: 재생/렌더링은 뷰, 게임 자원·작업 판정은 모델, Day01 구체 씬 탐색은 공용 모듈의 기본 경로로 유지한다. 프로토타입은 지도·셰이더·대상을 주입한다.
- 수명: Reset/Dispose 및 이벤트 구독 해제 경로를 확인했다. 실제 Unity 재시작·씬 종료 검증은 아래 항목으로 남긴다.
- 추가 보정: 건물/자원 아래 GPU 마스크로 숨겨진 풀도 소리 접촉에 남아 있었다. HasGrassAt에 선택적인 가시성 판정을 주입하고 프로토타입의 같은 마스크 CPU 데이터를 사용해 숨은 풀의 스침 재생을 제외했다. Day01 기존 호출은 유지한다. 이 마무리 보정은 `941ca07`에 포함했다.
- 검증: Devlog 21개 모듈 및 프로토타입 C# 빌드 통과. HLSL 컴파일·플레이·청취는 미실행이다.

### Unity 확인 순서

1. 낮/밤에 지형·풀·시야 잔상을 확인한다. 시야 밖에는 지형/해안/물만 남아야 한다.
2. 나무/바위/상자 클릭, 자동화 이후 호버, 건설/수리를 비교한다. 쿨타임·도구 접촉·반동·작업별 플래시가 규칙대로 보여야 한다.
3. 눈 위 자원을 반복 타격/소진한다. 눈이 국소적으로 벗겨지고 파괴 후 원본/잎/눈이 남지 않아야 한다.
4. 풀·물 위 마우스 이동/정지와 음량 0을 확인한다. 건물 아래 숨은 풀은 스침 소리가 나지 않아야 한다.
5. 완공 집의 연기·밤 창문과 폐허 수정 Bloom을 확인한다. 시야 밖 오브젝트는 숨고 건설/이전/철거에 맞춰 표현이 정리돼야 한다.
6. 메뉴 정지/재개, 해상도 변경, 재시작/환생, 씬 종료를 확인한다. 중복 음향·파티클·Volume과 콘솔 오류가 없어야 한다.

공개 음원 크레딧 반영은 별도 출시 준비 항목으로 유지한다. 구현 이관 완료는 화면·청취 검증 완료나 공개 준비 완료를 의미하지 않는다.

## 사용자 재확인: 풀·타일 장식 이관 보정

이전 코드 연결 완료 판정과 별개로 풀·장식의 실제 생성 규칙에 차이가 남아 있었다. 프로토타입 풀은 주입 Map 기본값 4×4를 사용했고 Day01은 7×7이었다. 장식은 별도 군집/확률 코드로 갈대·통나무 등을 배치하여 공용 TileDecoration의 흙덩이·이끼 낀 돌과 배치 밀도/크기가 일치하지 않았다. 중앙 7×7 영역을 무조건 제외하고 지면에서 -0.045 내려놓는 오프셋도 있었다.

- 풀 Map.SamplesPerAxis=7로 Day01 밀도를 명시한다. 공용 풀 종류/군집/바람과 4타일 청크·거리 LOD는 유지한다.
- 장식 종류는 ShowcaseTileVariants.Decoration을 사용한다. 꽃/고사리 두 묶음, 자갈, Rock0+Fern 이끼 돌, 흙덩이를 해당 바이옴에 배치한다. Day01 크기(돌 .42, 기타 .45~.65, 흙덩이 .8/.55/.7)와 흙 색(.34/.255/.18)을 적용한다.
- Day01 꽃/고사리 군집 억제 조건을 ShowcaseGrass.DecorationVisible로 공유한다. 고정된 중앙 빈 영역 대신 실제 건물/자원 가림 마스크를 사용한다.
- FBX 원래 축/스케일을 보존한 장식을 지형 높이+.007에 배치하고 8타일 청크로 합친다. 모든 서브메시 삼각형과 정점색을 포함한다. 초록 식물은 기존 지형색 연동을 유지한다.
- 장식 정점에 개체별 뿌리 좌표를 보관해 같은 풀 가림 마스크를 적용한다. 건물 설치/이전/철거 시 청크 재생성 없이 아래 장식도 숨김/복원된다.

검증: Devlog 21개 모듈·프로토타입 C# 빌드 통과. Unity/HLSL 화면 검증 미실행. 다시 플레이해 초원/숲의 풀 밀도·꽃/고사리 군집, 흙의 흙덩이, 바위/눈/모래의 자갈을 확인한다. 중앙에도 빈 지면에는 장식이 생기고 건물 아래에는 숨겨져야 한다. 시야 밖 풀/장식 숨김과 낮밤 지형색 일치도 확인한다. 밀도 증가의 실제 GPU 비용은 Unity 프로파일링 확인 대상이다.

### 풀 종류가 하나처럼 보이는 문제

변종/스프라이트는 생성됐으나 PrototypeGrassOutput이 꽃 이외의 최종 색을 지형색으로 덮어썼다. 일반 풀은 지형색을 유지하고 변종은 공용 셰이더의 끝 색을 뿌리→끝 보간으로 복원했다. 꽃잎도 공용 색을 유지한다. Day01 기본 출력은 변경하지 않는다. HLSL 화면 검증은 미실행이며 Unity에서 갈색/어두운색/밝은색 풀과 숲의 청록/이끼/자주색 끝이 구분되는지 확인한다. 일반 풀과 뿌리의 지면색 및 시야 감쇠는 유지한다.

### 밝은 베이지 풀의 색 공간 보정

사용자 참고 이미지와 Grass0~3 원본 알파 및 Day01 공유 패스를 대조했다. Day01의 변종/꽃 색 상수는 그대로 조명 계산에 사용되는데 프로토타입만 GRASS_AUTHORED_COLOR에서 SRGBToLinear를 추가 적용해 베이지 표현을 어두운 갈색으로 만들었다. 이 프로토타입 전용 변환과 미사용 함수를 제거해 Day01 기본 색 입력을 공유한다. 정점색의 기존 변환과 일반 풀의 지면색 연결은 유지한다. 숫자만 보고 갈색으로 설명했던 이전 판단은 부정확했다. 실제 HLSL/GPU 확인은 미실행이며 Unity 낮에서 해당 베이지 풀·밝은 풀·꽃 색을 확인한다.

### 기본 풀 중심으로 비율 조정

사용자 요청: 풀 전체 밀도는 유지하고 색이 다른 풀/장식 대신 기본 풀을 늘린다. 프로토타입 Map.AccentFraction=.25를 주입하여 변종·꽃의 선택 비율을 기존의 1/4로 줄였다. 제외된 변종은 생성 생략이 아니라 같은 위치·같은 스프라이트의 기본 풀(kind 0)로 전환한다. 7×7 샘플과 군집 확률은 유지하며 Day01 기본값은 1이다. 별도 타일 장식도 고정 시드로 약 1/4만 남기고 초원/숲의 기존 바탕 풀이 드러나게 했다. 흙/모래/눈/바위에 새 풀을 억지로 추가하지 않는다. Unity 화면 확인 대기.

### 풀 단색·Inspector 조절

풀은 뿌리 고정 직립 빌보드이며 바람의 tilt/depth와 HoverGrass가 기울기를 만든다. 지면에 평평하게 배치하는 회전은 없다. 변종의 뿌리→끝 보간을 제거하고 베이지/어두운색/밝은색/청록/이끼/자주색을 각각 전체 풀에 적용한다. Settings의 풀 색상 그룹에서 해당 색과 꽃 두 색을 편집할 수 있다. GrassUsesTerrainColor를 끄면 기본 풀도 GrassBaseColor를 사용한다. 색은 플레이 중 반영되며 조명/낮밤/시야 감쇠는 유지한다. C# 빌드와 별도로 Unity에서 베이지 풀의 뿌리까지 단색인지, 색 변경이 즉시 반영되는지 확인한다.

### 집 대비 풀 크기 보정

Day01SceneBuilder는 집을 1.8배로 배치하지만 프로토타입은 원래 FBX 배율을 유지하고 양쪽 풀 pixelSize는 동일했다. 상대 크기 보정으로 Settings.GrassSizeScale 기본값을 1/1.8로 설정했다. 셰이더에서 폭/높이를 함께 줄이며 바람/호버의 높이 입력과 CPU 스침 접촉 반경도 같은 배율을 따른다. Inspector에서 플레이 중 조절 가능하고 밀도/변종 비율은 유지한다. Unity에서 집 문 앞 발판과 비교하여 크기를 확인한다.

## 집 1×1 기준 자원 비율과 전역 군집

- Day01 생성 기준 집 배율 1.8, 나무 1.15/1.28/1.41, 바위 1.05/1.20/1.35를 비교했다. 프로토타입 집의 1×1 점유와 기존 모델을 유지하고 자원 배율을 나무 약 .64~.78, 바위 약 .58~.75로 환산했다. Settings TreeModelScale=.7111, RockModelScale=.6667에 변형별 상대 배율을 적용한다. 새 게임/뷰 생성 시 적용되며 표면 선택 콜라이더도 렌더러 경계로 맞춘다. 체력/채집량은 변경하지 않는다.
- 초기 SeedBiomes가 Forest/Rocky만 생성하던 제한을 제거했다. 순수 C# ShowcaseResourceClusters가 9타일 구역의 흔들린 군집 중심과 반경(나무 3.8, 바위 3.1), 바이옴 가중치를 제공한다. 물은 제외하고 초원/흙/눈 등 육지 전체에 군집이 분산된다. 모래의 나무는 드물게, 숲은 나무, 바위 지형은 바위를 선호한다.
- 시작 주변 5타일 안은 기존 접근 자원을 보존한다. 초기 나무/바위 한도 내에서 눈 후보에 약 20% 예산을 우선 배정하고 나머지는 전체 지도의 고정 시드 순서로 배치한다. 눈 타일이 없거나 비어 있지 않으면 전체 유효 후보로 채운다. 장애물/물/기존 개체 점유를 검사한다.
- 주기 재생성도 같은 군집 판정을 사용한다. 기존 재생성 시간과 자원 한도 규칙은 유지한다. 눈 위 나무/바위는 기존 적설 어댑터가 처리한다.

검증: Devlog 21개 모듈 및 프로토타입 C# 빌드 통과. Unity 미실행. 새 게임에서 집 발판/나무/바위 비율, 맵 전역 군집과 빈 통로, 눈 지역 두 종류 자원과 적설을 확인한다. 자원을 소진한 뒤 재생성이 군집 근처에서 이뤄지는지, 축소된 나무/바위의 표면 클릭과 도구 접촉이 맞는지 확인한다.

### 자원 밀도 3배·전용 바이옴 복원

사용자 요청에 따라 초기 배치 목표/기본 한도를 나무 260→780, 바위 160→480으로 높였다. 일반 육지 군집의 후보 확률도 3배로 높여 한도만 늘고 실제 배치가 부족해지는 것을 방지한다. 숲은 나무 82%, 암석은 바위 72%의 기존 타일 배치와 4타일 간격 통로를 복원하고 초기 배치에서 우선 채운다. 반대 자원은 해당 바이옴을 점유하지 않는다. 이후 눈 우선 예산과 일반 군집을 채운다. 맵 크기·빈 공간에 따라 실제 개수는 목표보다 적을 수 있다. 재생성은 같은 후보 규칙과 늘어난 한도를 사용한다. 새 게임 적용, Unity 배치 확인 대기.

## 랜덤 지도·흙길·수계와 조밀한 자원 바이옴

- 사용자 확정: 흙 타일에는 나무/바위를 생성하지 않는다. 초기 수동 배치·군집·재생성 모두 같은 제외 규칙을 적용한다. 길은 Dirt 타일이며 풀도 해당 바이옴에는 생성하지 않는다.
- ShowcaseWorldMap은 Terrain 모듈의 순수 C# 생성기다. 시드로 해안 굴곡·숲/암석 패치·호수 형태를 바꾸고 호수에서 바다까지 연속 곡선을 물 타일로 래스터화한다. 물 가장자리는 모래, 눈 해안은 눈을 유지하며 기존 해안/수면 모듈이 그린다.
- 경로 방식은 육지 4방향 가중 최단 경로다. 완만한 노이즈 비용으로 길이 휘도록 하고 이미 만든 길은 낮은 비용으로 재사용하여 공통 구간/분기를 만든다. 시작점에서 도달 가능한 네 방향 탐험 지점을 선택한다. 중앙 주 길은 약 3~5타일 폭, 외곽 가지 길은 약 1~3타일 폭으로 변하고 물은 덮어쓰지 않는다. 실제 분기 모양/삼거리 위치는 시드에 따라 달라진다.
- 시작 지점 주변 11×11은 건조한 육지를 보장하고, 제단/폐허는 기존 고정 좌표 대신 길로 연결된 육지 목적지에 배치한다. 호수/강은 장식 오버레이가 아니라 이동/건설을 제한하는 실제 Water 타일이다.
- 숲의 나무/암석 지형의 바위는 이전의 4타일 간격 빈 줄과 확률 생략을 제거하고 가능한 모든 타일을 우선 채운다. 해당 바이옴 후보가 한도보다 많으면 초기 예산을 높이고 기존 초기 수량 기반 재생 한도가 이를 수용한다. 물/흙/개체 점유는 제외한다.
- Settings.MapSeed=0이면 새 게임마다 새 시드, 다른 정수이면 동일 지도 재현. 실제 시드는 F4 디버그 패널과 지도 재구성 로그에 표시한다. 새 게임에서 지형/수면/풀/장식/호버/마스크를 재생성하고 이전 지도 소유 메시·재질·텍스처를 정리한다.

검증: Devlog 모듈 및 프로토타입 C# 빌드. Unity 플레이/화면 검증 미실행. 새 게임 두 번으로 지도 차이, 고정 시드 재시작의 동일 배치, 넓은 흙길과 분기, 물 타일 강/호수, 흙 위 나무/바위 부재, 숲·암석의 조밀한 자원과 클릭/이동 가능 여부를 확인한다. 맵 전체 길찾기/밀집 자원의 실제 성능은 플레이 확인 대상이다.

### 숲/암석 90%와 초원 소군집·단독 배치

숲의 나무와 암석의 바위는 시드 기반 90% 후보 판정으로 빈 곳을 남긴다(기존 개체 점유 등으로 실제 비율은 더 낮을 수 있음). 초원은 이전 넓은 확률 군집을 대체해 각각 5~6개로 구성된 소군집을 계획하고 군집 중심 간 최소 5.5타일 간격을 둔다. 군집 사이에는 약 3타일 이상 간격의 단독 나무/바위를 섞는다. 5~6개 그룹은 배치 한도/점유 검사를 묶음으로 수행하여 초기 생성 때 일부만 잘리지 않게 한다. 시드가 같으면 같은 계획을 만들며 재생성은 해당 초원 후보 위치를 사용한다. 흙/물 제외, 눈 자원 배치는 유지한다. 새 게임 적용. 프로토타입 C# 빌드 통과, Unity에서 소군집 개수·간격·단독 배치와 숲/암석의 빈 자리 확인 대기.

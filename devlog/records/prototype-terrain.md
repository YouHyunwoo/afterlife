## 변경 전후

기존 프로토타입은 큰 평면 Cube의 셰이더에서 바이옴 색을 혼합했다. 오브젝트와 커서 선택 기준은 고정 Y였다.

이제 기존 TerrainMap의 초원·흙·모래·물·눈·숲·암석 분포에 Day01의 연속 gradient Perlin 높이장을 적용한다. 육지 상면은 0.25m 간격이며 이웃 타일은 같은 좌표의 높이와 대각선 규칙을 사용한다. 바이옴 색은 Day01의 좌표 왜곡/경계 혼합 규칙으로 생성하고 프로토타입의 기존 7색 팔레트를 사용한다. 물은 혼합 가중치에서 제외한다.

프로토타입의 타일 중심은 정수이고 Day01은 타일 모서리가 정수다. 색 혼합에만 +0.5 좌표 변환을 적용하며 높이장·선택·모델은 프로토타입 월드 좌표를 사용한다. MapRadius와 원래 바이옴 생성, 물 이동 제한, 자원 생성, 건설 점유 규칙은 변경하지 않는다. 이번 적용에서 별도의 고저차 이동 규칙은 추가하지 않는다. 작업 전에 있던 기여 주기 1초 설정도 보존한다.

## 모듈 구조

- `Afterlife.Devlog.Terrain`: 기존 Unity 비의존 코어. `ShowcaseBiomeBlend.Weights`의 지도 조회 함수 주입 오버로드를 추가했다. Day01의 기존 호출/지도 경계는 유지한다.
- `TerrainHeightGrid`: 맵 정점 높이를 한 번 계산하고 실제 삼각형과 같은 보간을 제공한다. Unity 참조가 없다.
- `Afterlife.Devlog.TerrainView`: 새 독립 Unity 어셈블리. 부모 Transform, 맵 범위, 바이옴 조회, 재질, 팔레트를 주입받아 8×8 타일 단위 메시를 생성한다. 물가와 맵 외곽의 측면을 닫고, 메시/재질/오브젝트를 소유·해제한다. Day01과 프로토타입 어셈블리를 참조하지 않는다.
- `PrototypeView`: 기존 Moonstone 주입 모델에서 지도 함수를 전달하는 어댑터다. SetUp에서 생성하고 OnDestroy에서 Dispose한다. 생성자나 MonoBehaviour 필드 초기화에서 Unity 네이티브 객체를 만들지 않는다.

씬/프리팹을 재작성하지 않는다. 기존 프로토타입 씬의 다음 실행에서 자동으로 생성된다. 새 소스와 asmdef의 `.meta`는 Unity 임포트가 생성하며 수작업으로 만들지 않는다.

## 표시 및 선택 연결

- 기존 지면 기준 높이 -0.06을 유지하고, 육지에 높이장을 더한다. 모델의 기존 지면 오프셋을 보존하며 표시 위치 Y만 높인다.
- 유닛의 모델 좌표/이동 보간은 2D로 유지하고 최종 표시 위치에서 높이를 조회한다. 방향 벡터에 높이 보정을 섞지 않는다.
- 기존 장식·풀도 같은 위치의 높이를 사용한다. 건물/자원은 중심점 기준으로 접지하며, 넓은 건물의 기초 평탄화는 이번 범위에 포함하지 않는다.
- 커서는 청크 경계로 후보를 줄이고 실제 메시 삼각형과 교차한다. 지형 Collider를 추가하지 않아 기존 Physics 대상 목록을 늘리지 않는다.
- 건설/호버 테두리는 변 길이를 세분화하고 지면 높이를 따른다. 범위 원, 선택 영역의 투영, 도구·피격 반응, 성장 표시, 투사체·번개·피드백 텍스트도 높이를 연결했다.
- 기존 시야/밤/마을 영역/커서 표시 셰이더는 유지하며 신규 지형 재질에만 `_TerrainRelief`를 사용한다.

## 이번 범위 밖

Day01의 둥근 해안, 수심 기반 반투명 수면·굴절·거품, 신규 풀/잎·바람·눈·호버·타격 효과는 아직 적용하지 않았다. 물은 기존 높이의 평면과 기존 단순 물결 색을 사용한다. 이번 물가 단면은 높이차를 닫는 벽이며 Rounded 해안 기능이 아니다.

## 검증

20개 Devlog 어셈블리 `dotnet build --no-restore` 통과. 프로토타입 빌드도 오류 0/경고 0. 기존 프로토타입 검증 csproj의 누락된 Temp DLL과 이전 Moonstone 이름을 현재 asmdef/Library DLL 참조로 갱신했다.

재검증: `python devlog/tools/build_modules.py` 후 `python devlog/tools/build_prototype.py`. 후자는 기존 검증 csproj를 사용해 현재 런타임 소스·asmdef 참조를 갱신하고 C#만 빌드한다. Unity Play/Test Runner, HLSL/GPU 검증과 실제 성능 측정은 실행하지 않았다.

사용자 확인:

1. Unity가 새 스크립트·asmdef를 임포트한 뒤 프로토타입 씬을 실행한다. 평면 대신 굴곡이 이어지고 숲/흙/눈 경계의 색이 자연스럽게 연결되어야 한다. 분홍색 셰이더 오류가 없어야 한다.
2. 카메라 이동으로 타일/청크 경계를 확인한다. 지면 틈이나 장식·자원의 큰 부유/매몰이 없어야 한다. 넓은 건물 모서리의 작은 높이차는 중심 접지 방식의 확인 대상이다.
3. 언덕 위 타일을 선택하고 건설·이동·자동 기여를 수행한다. 커서와 표시 테두리가 지면에 맞고, 기존 바이옴/물 이동 제한과 건설 규칙이 유지되어야 한다.
4. 낮/밤·재시작·Play 종료 후 재진입을 확인한다. 지형 중복, 해제된 메시 참조, 생성자 예외가 없어야 한다.
5. 같은 맵/시야에서 초기 생성 시간·CPU/GPU 시간·메모리·드로콜을 측정한다. 기존 평면보다 메시 복잡도가 늘었으므로 성능 향상을 보장하는 변경으로 해석하지 않는다.

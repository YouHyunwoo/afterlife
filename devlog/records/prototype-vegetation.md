## 변경 전후

기존 풀은 맵 전체를 한 메시로 합친 삼각형과 단순 사인 흔들림이었다. 이제 Day01의 PNG 빌보드, 군락 밀도, 꽃과 숲 전용 변종, 지면 색·법선에 따른 표현을 사용한다. 프로토타입의 TerrainMap을 읽어 초원/숲에만 생성하고 TerrainSurface의 실제 높이와 혼합색을 주입한다.

기존 나무 모델·충돌체는 유지한다. 읽기 가능한 수관 메시의 초록색 면에 잎 카드를 추가하며, 접지 그림자와 갈색 줄기는 제외한다. 기본 회전 변주와 표면 부착, 카메라 빌보드를 사용한다. 원본 수관과 잎·풀은 Wind의 같은 방향/시간/공간 돌풍 계산을 공유한다.

풀·잎 셰이더 계산은 공용 HLSL로 분리하고, 프로토타입 셰이더가 조명·시야 출력을 주입한다. Day01의 기존 생성 경로와 기본 셰이더 동작은 보존한다. 프로토타입은 기존 시야 배열과 밤/마을 조명을 사용하고 시야 밖 카드는 숨긴다. 잎은 원본 나무의 호버 색 변화와 위치 흔들림을 따른다.

## 모듈과 성능 범위

- Vegetation `ShowcaseGrass.Map`: 지도 반경·바이옴·높이·색·샘플 수를 주입한다. 주입 경로에서는 Day01의 고정 지도나 Hierarchy 이름을 조회하지 않는다. 기존 Day01은 타일당 7×7 후보를 유지하고 큰 프로토타입은 4×4 후보를 사용한다.
- 풀은 4×4 공간 청크로 묶고 기존 30/45 거리 기준의 전체/절반/1/4 밀도 조절을 사용한다. 매 프레임 정점 배열을 재생성하지 않는다.
- `ShowcaseLeafCards`: 기존 API에 선택적 Shader·최대 카드 수·속성 변환 함수를 추가한다. 프로토타입은 나무당 최대 384장과 기존 거리별 밀도 조절을 사용한다. 원본 Mesh 배열은 프로토타입에서 Mesh별로 재사용하고, 원본 색이 변경될 때만 속성 버전을 올려 잎에 복사한다. Day01 기본 상한은 2,000장 그대로다.
- `PrototypeVegetation`: 모델/시야와 모듈 사이의 조립 코드. 풀 가림은 타일당 4×4 픽셀 마스크로 처리한다. 건물·나무·바위의 ID/위치/크기 상태 해시가 바뀔 때만 업로드하며, 건설/이동/철거/자원 재생성 때 메시를 다시 만들지 않는다. 기존 개체 목록을 순회하는 비용은 매 프레임 남는다.
- `ShowcaseWind`: 기존 모듈을 재사용한다. 프로토타입 효과 시간을 전달하여 메뉴 일시정지와 함께 멈추고, 종료 시 이전 바람 전역값을 복원한다.

기존보다 표현량이 늘어나는 변경이다. 실제 CPU/GPU·메모리·드로콜 개선을 측정하거나 보장한 것은 아니다. 큰 맵의 생성 비용과 알파 카드 오버드로는 사용자 확인 대상이다.

## 수명 및 적용 범위

나무 생성 시 카드 모듈을 만들고, 기존 제거 반응이 끝나 나무 뷰를 삭제할 때 카드/메시/재질을 함께 해제한다. 재시작/환생 시 나무 카드를 해제·재생성하고, 같은 지도의 풀 청크는 유지하면서 가림 마스크를 갱신한다. 씬 종료 때 풀·카드·마스크·공유 나무 재질을 정리하고 바람 전역값을 복원한다. MonoBehaviour 필드 초기화에서는 Unity 리소스를 만들지 않는다.

신규 물리 충돌체는 추가하지 않는다. Day01의 호버 풀 눌림, 눈, 타격 디졸브, 환경음/연기는 이 묶음에 포함하지 않았다. 기존 정적 지형 장식은 유지한다. Wind 셰이더 전역값은 기존처럼 단일 활성 장면 소유를 전제로 한다.

## 검증과 사용자 확인

Devlog 21개 모듈 및 프로토타입에 `dotnet build --no-restore` 검증. 프로토타입 오류/경고 0개, Day01 기존 CS0252 경고 1개. Unity Play/Test Runner 및 GPU/HLSL 검증은 프로젝트 지침에 따라 실행하지 않았다. 새 `.meta`는 Unity 자동 임포트에 맡긴다.

1. Unity 임포트 후 `Afterlife_PixelPrototype`을 실행한다. 분홍색 셰이더 오류 없이 초원/숲에 PNG 풀·꽃이 보이고, 물/모래/눈에는 풀이 새로 생성되지 않아야 한다. 뿌리가 지형에 붙어 있어야 한다.
2. 카메라를 이동·회전한다. 풀과 잎이 카메라를 향하고, 가까운 나무에 잎 카드가 보이며 바람에 풀·수관·잎이 같은 큰 방향으로 흔들려야 한다. 멀리서 밀도가 줄어도 군락 전체가 갑자기 사라지지 않아야 한다.
3. 나무에 마우스를 올리고 벌목한다. 기존 호버 색·타격 흔들림을 잎이 따르고, 제거 후 떠 있는 잎이나 해제된 메시 오류가 없어야 한다.
4. 풀 위에 건설 후 이동/철거한다. 건물 밑 풀은 숨고, 비워진 자리에 기존 군락이 다시 보여야 한다. 나무/바위 재생성 시에도 밑동 주변 풀이 가려져야 한다.
5. 밤과 시야 경계를 확인한다. 잎·풀이 시야 밖에서 밝게 남지 않고, 메뉴 일시정지 시 바람도 멈춰야 한다.
6. 재시작/환생, Play 종료·재진입 후 중복 식생이나 생성자 예외가 없어야 한다. Day01의 기존 풀·잎·바람 표현도 확인한다.

재검증 명령: `python devlog/tools/build_modules.py`, `python devlog/tools/build_prototype.py`.

## 시야 페이드 비교 옵션 (과거 구현, 현재 제거)

아래 비교·보정 기록은 개발 당시 내용이다. 현재 사용법과 검증 기준은 마지막 Day01 시야 절을 따른다.

검은 식생 문제는 시야 계수를 RGB에 곱하면서 알파를 1로 유지한 처리에서 발생했다. 색 감쇠를 제거하고 F4 디버그 패널의 **식생 · 시야 페이드** 그룹에 두 방식을 추가했다.

- 디더 페이드(기본): 렌더 타깃 픽셀 기준 4×4 Bayer 패턴으로 점차 제거한다. 깊이 기록을 유지한다.
- 알파 페이드: 원래 색과 시야 계수 알파로 합성한다. 깊이 기록을 끄고 기존 투명 오브젝트 이후에 그린다. 청크/잎이 겹치는 곳의 정렬 차이는 비교 대상이다.

선택은 즉시 기존 풀/잎 전체에 적용하고 새 나무와 재시작에도 현재 선택을 유지한다. Play를 새로 시작하면 디더로 돌아간다. 기존 나무 본체의 시야 방식은 유지하며 비교 대상은 풀/잎 카드다.

Unity에서 F4 → 식생 · 시야 페이드의 두 버튼을 번갈아 선택하고 커서를 움직여 같은 시야 경계를 비교한다. 두 방식 모두 검은 잔상이 없어야 하며, 디더는 픽셀이 줄어들고 알파는 부드럽게 투명해져야 한다. 나무가 겹치는 곳, 해안, 밤, 재시작 후 새 나무도 확인한다. C# 빌드는 통과했으며 HLSL/Play 화면 검증은 미실행이다.

### 낮·밤 밝기 일치 보정

페이드만 적용하면 시야 경계에서 지형은 어두워지지만 남은 풀/잎 픽셀은 밝게 유지됐다. 지형·식생·수면이 공통 `PrototypeGroundBrightness`를 사용하도록 정리했다. 시야가 줄면 낮에는 지형과 같은 0.48 기준, 밤에는 0 기준으로 감쇠하며, 디더/알파 페이드는 별도로 유지한다. 기존 바이옴/꽃/잎의 고유 색은 유지하고 같은 밝기 비율을 적용한다.

Unity에서 낮과 밤 각각 동일 위치의 시야를 줄이면서 두 페이드 옵션을 비교한다. 어두운 지형 위에 밝은 풀 점이 남지 않고 함께 어두워져야 한다. C# 빌드만 검증했으며 셰이더 임포트·화면 확인은 사용자 확인 대상이다.

### 우선 보정: 색 공간과 풀의 시야 기준점

- 프로토타입의 꽃/갈색·검정·흰 풀 끝 고정색을 Linear 프로젝트에서 sRGB→Linear 변환한 뒤 혼합하도록 수정했다. 이미 변환된 기본색이나 숲 변종의 상대 색 배율은 다시 변환하지 않는다. Gamma 프로젝트는 원래 값을 사용한다.
- 풀의 시야·마을 조명 계산은 바람/빌보드 변위 이전 뿌리 위치를 사용한다. 디더 패턴은 실제 화면 픽셀을 계속 사용하고, 잎은 기존 기준을 유지한다.
- 공유 Grass HLSL에 선택적 출력/고정색 변환 훅을 추가했다. Day01은 기존 기본 경로를 유지한다. 알파 블렌딩·깊이 기록·정렬·카드 밀도는 변경하지 않았다.

프로토타입 C# 빌드 통과. 이 빌드는 HLSL 검증을 포함하지 않는다. Unity에서 F4→알파 페이드를 선택하고 낮/밤에 꽃과 풀 끝의 밝기, 시야 경계에서 바람에 따른 깜빡임을 비교한다. 고정색만 과하게 밝은 현상과 한 포기 안에서 시야값이 갈리던 현상이 줄어야 한다. 뿌리 위치와 화면 뒤 지형 위치는 원근/높이 때문에 여전히 다르며, 알파 중첩과 지형의 최종 무늬/영역 색 차이는 이번 보정으로 해결되지 않는다.

### 색 변환 include 오류 수정

사용자 Unity 임포트에서 `SRGBToLinear` 미선언 오류를 확인했다. PrototypeVegetationLighting이 색 변환 함수를 사용하면서 Color.hlsl을 직접 포함하지 않아 발생했다. 설치된 Core 패키지의 함수 선언을 확인하고 해당 헤더를 사용 전에 명시적으로 포함했다. C# 빌드로는 이 HLSL 오류를 검출할 수 없으며, 수정 후 Unity 재임포트 확인이 필요하다.

### 지형·풀·식물 장식의 기준색 통합

사용자 화면 비교에서 일반 풀이 여전히 검은 점처럼 보였다. 페이드 조정만으로 해결할 범위를 넘어, 지형과 풀의 서로 다른 최종 색 처리 및 어두운 변종을 함께 수정했다.

- 프로토타입 육지 팔레트를 Day01TerrainVariants의 초원/흙/모래/눈/숲/바위 값으로 맞췄다. 수면 색은 기존 별도 셰이더가 담당한다.
- 실제 맵으로 0.25m 간격 바이옴 색·지면 법선 텍스처를 한 번 생성한다. 색 텍스처는 sRGB, 법선 텍스처는 Linear로 설정하고 경계 텍셀 중심까지 좌표를 맞춘다. 기본 반경 45에서 각각 365×365 RGBA32이며 밉맵은 없다. 생성 후 CPU 복사본을 해제하고 종료 시 텍스처 해제/이전 전역값 복원을 수행한다.
- PrototypeGroundAppearance가 지형·풀·식물 장식의 공통 색 샘플, 명암, 영역 색과 약한 단계화를 담당한다. 지형의 별도 흙 노이즈/강한 단계화 대신 이 경로를 사용한다. 조명은 Day01의 연속 명암/약한 단계화 방식을 참고한 고정 방향광 표현이며, Day01 씬의 실제 광원/그림자를 복제한 것은 아니다.
- 프로토타입 일반 풀은 뿌리 위치의 공통 최종 기준색을 그대로 사용한다. 검정/흰색/갈색 끝 색, 숲 끝 색 및 톤 변주는 색 출력에서 제외하고 형태 변주는 유지한다. 꽃잎만 색을 남긴다. Day01 기존 풀 출력은 그대로 보존한다.
- 결합 장식 메시의 초록 식물 정점에 UV 마스크를 저장해 양치류/갈대/꽃 줄기를 같은 지면색에 연결한다. 돌·통나무·꽃잎은 원래 색을 유지한다. 원본 FBX 및 메타데이터는 수정하지 않는다.

검증: Devlog 21개와 프로토타입 C# 빌드 통과. HLSL/실제 화면은 미검증이며 Unity 임포트 후 새 Play에서 확인해야 한다. 생성 시 만든 팔레트/텍스처/장식 마스크가 있으므로 기존 Play를 계속한 화면만으로 비교하지 않는다.

확인 절차: 낮에 F4→알파 페이드로 일반 풀 군락과 주변 타일의 색이 연결되는지 확인하고, 시야를 이동시켜 검은 점 대비가 줄었는지 비교한다. 밤, 바이옴 경계, 건설/철거, 재시작을 확인한다. 꽃잎·돌·통나무의 고유 색은 남아야 한다. 디더 옵션도 정상이어야 한다. 같은 뿌리 좌표에서 지형과 풀의 기준색은 같지만 화면에서 풀 뒤에 비치는 다른 좌표의 지형, 알파 중첩, 꽃잎 대비까지 동일해지는 것은 아니다.

## Day01 시야 방식의 프로토타입 적용

현재 시야는 **Day01 단일 방식**이다. 디더/알파 전환 코드, 재질의 비교용 속성, F4의 식생 시야 비교 그룹을 제거했다. 디버그 패널 크기와 입력 차단 영역도 남은 항목에 맞췄다.

- Day01/프로토타입이 `ShowcaseVision.hlsl`의 평면 원형 시야(경계 폭 0.65)와 낮/밤 밝기 감쇠 함수를 공유한다. 지형·수면은 시야 밖에서도 낮 0.48, 밤 0.15 밝기로 남는다.
- 오브젝트는 같은 밝기 감쇠를 받은 뒤 시야 밖에서 clip된다. 기존 visibility 알파 곱은 기본 오브젝트 경로에서 제거했다. 풀/잎의 Day01 모드도 알파 중첩이나 디더 없이 같은 방식으로 처리한다. 기존 재질 고유 알파는 보존한다.
- 마우스 잔상은 최대 32개, 0.06초/0.35 거리 생성 기준, 정지 시 최신 위치 갱신, 빠른 이동 최대 8점 보간을 적용한다. 기본 1.4초 중 처음 20%는 유지하고 나머지는 SmoothStep으로 사라진다. 실제 지속 시간은 기존 Settings.VisionTrailSeconds를 사용한다.
- 모델 Visibility와 GPU 업로드가 VisionEcho.Strength의 같은 잔상 강도를 사용한다. 집·유닛·마우스의 기존 시야 반경과 시야 제공 규칙은 유지한다. 재시작/환생 시 기존 Echoes 초기화 경로를 따른다.
- 풀/잎은 깊이 기록과 불투명 출력을 고정 사용하며 신규 나무에도 동일하게 적용한다. Day01 테스트 토글과 프로토타입의 항상 켜진 게임 시야는 서로 다른 전역 상태를 유지한다.

검증: Devlog 21개와 프로토타입 C# 빌드 통과. 프로토타입 오류/경고 0개. 기존 기여 간격 변경은 유지했다. HLSL/Play 화면 검증은 실행하지 않았다.

사용자 확인: 새 Play에서 F4에 시야 비교 버튼이 없는지 확인하고 마우스로 맵을 훑는다. 경로가 잠시 남았다가 오래된 곳부터 어두워지고 시야가 완전히 사라진 곳에는 지형/수면만 남아야 한다. 집/유닛 주변은 해당 시야가 유지되어야 한다. 밤·해안 수직면·신규 나무·재시작도 확인한다.

공통 시야 HLSL 수정: 사용자 D3D11 컴파일 오류에서 `point` 예약어 충돌을 확인했다. ShowcaseVisionCircle 매개변수를 `positionXZ`로 변경했다. 공통 include를 사용하는 연기/지형/식생 모두에 반영되며, Unity 재임포트 확인은 필요하다.

# Picking 런타임 생성 전환

## 변경 전후

기존에는 Day01/Picking의 ScriptableObject 에셋을 프리팹에 연결했다. 이제 `ShowcasePickSurface.Mesh`는 직렬화되지 않는 프로퍼티이며, 최초 접근 시 같은 오브젝트의 `MeshFilter.sharedMesh`에서 데이터를 생성한다. 원본 Mesh별 공유 캐시를 사용하므로 같은 모델의 인스턴스가 늘어도 기본 Picking 데이터를 중복 생성하지 않는다.

`ShowcasePickMesh.Create`가 정점·노멀·삼각형·색·재질 슬롯·경계를 복사한다. 생성물에는 DontSave를 적용하며 에셋 파일을 만들지 않는다. 선택 교차 계산에서는 생성 데이터를 지역 변수로 받아 삼각형 루프 안에서 캐시를 반복 조회하지 않는다.

## 수명과 기존 소비자

- Surface는 공유 캐시의 사용자를 등록하고, 파괴되거나 원본 Mesh 참조가 바뀌면 기존 사용을 해제한다. 마지막 사용자가 사라지면 생성 데이터를 해제한다.
- 비활성 풀 객체는 데이터를 유지해 재활성화 때 재사용한다. 한 번도 활성화되지 않아 OnDestroy가 호출되지 않는 객체도 씬 언로드 때 정리한다.
- 도메인 리로드를 끈 플레이 진입, 플레이 종료, 에디터 어셈블리 리로드에서는 캐시를 정리한다. R 초기화는 같은 원본 메시를 재사용하므로 캐시를 다시 만들 필요가 없다.
- 눈/변형 지형이 `surface.Mesh`에 직접 넣는 데이터는 해당 모듈이 소유하고 해제한다. 기본 메시 데이터는 지형 복원에 사용할 수 있도록 Surface 수명 동안 유지한다.
- 같은 Mesh 인스턴스의 정점을 직접 수정한 경우 자동 변경 감지는 하지 않는다. 현재 변형 지형처럼 변경한 Picking 데이터를 주입하거나 새 Mesh 참조를 사용해야 한다.

## 에디터/데이터 마이그레이션

- 원본 모델 12개의 Read/Write를 Unity ModelImporter로 활성화했다. 이 설정은 CPU 메시 데이터를 유지하므로 메모리 비용이 추가된다.
- 프리팹 23개를 Unity PrefabUtility로 불러와 저장하여 구형 Mesh 필드를 제거했다.
- 참조 제거를 확인한 뒤 Unity AssetDatabase로 Picking 에셋 72개, 메타데이터 및 폴더를 삭제했다.
- 기존 저장 데이터 색상 업그레이더를 제거했다. 새 구성 도구는 원본 읽기 가능 설정만 준비하며 Picking 파일을 생성하지 않는다.
- 측정 도구는 이제 프리팹의 원본 메시를 수집해 실제 런타임 팩토리를 호출한다. 임시 Picking 에셋을 저장하는 측정 경로도 제거했다. 과거 측정 JSON은 당시 결과로 보존한다.
- 현재 열린 미저장 씬은 저장하지 않았다. 전후 비교에서 Devlog 씬 파일의 SHA-256이 동일하다.

[마이그레이션 결과](runtime-picking-migration.json). 최초 재직렬화 시도에서는 알 수 없는 구형 필드가 남아 삭제를 중단했다. 이후 PrefabUtility 저장으로 완료했으므로 JSON의 `readableModels`는 재시도 중 새로 변경된 항목이 없어 빈 배열이다. `previouslyUnreadableModelsNowEnabled`는 이전 측정과 최종 임포터 설정을 대조한 12개 목록이다.

## 확인 결과와 사용자 확인 절차

13개 Devlog 모듈의 `dotnet build --no-restore`가 모두 통과했다. Picking 폴더/폴더 메타데이터 부재, Devlog 프리팹·씬의 구형 Mesh 필드 0개, 이전 비활성 모델 12개 모두 Read/Write 활성화를 확인했다.

프로젝트 규칙에 따라 Play 모드와 Unity Test Runner는 실행하지 않았다. 사용자가 `Devlog_Day01`을 Play하여 다음을 확인한다.

1. Before/Process/After를 전환하고 나무·돌·제단·땅을 클릭한다. 기존처럼 정확한 위치에서 표면색에 맞는 파편이 나와야 한다.
2. 눈 덮인 나무 타격, 지형 호버, R 초기화를 수행한다. 눈/잎/변형 표면의 기존 동작이 유지되어야 한다.
3. 같은 자원 프리팹을 여러 개 생성하고 파괴·비활성화·재활성화한다. 클릭 판정이 유지되고 Read/Write 또는 MissingReference 오류가 없어야 한다.
4. Play 종료 후 다시 진입한다. 도메인 리로드를 끈 설정에서도 같은 결과가 나와야 하며 Picking 폴더는 다시 생기지 않아야 한다.

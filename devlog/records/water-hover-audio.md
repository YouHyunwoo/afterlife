# 물 호버 효과음

최신 볼륨 조정: 기본 물소리 볼륨 0.35 → 0.525(1.5배, 약 +3.5dB). 연속 이동 55% 비율 및 간격/피치 변형 유지. Audio 모듈 빌드 오류/경고 0개. Unity 청취 확인 대기.

## 연속 재생 자연화 — 현재 설정

- [x] 원본의 서로 다른 구간 5개 추출(0.36~0.52초)
- [x] 강한 어택 뒤 구간 선택, 잔여 피크 완화, 45ms 시작/180ms 끝 페이드
- [x] 같은 클립 연속 선택 방지, 0.25~0.40초 무작위 최소 재생 간격
- [x] 연속 이동 볼륨 55%, 피치 0.98~1.02, 볼륨 ±8% 변형
- [x] Audio/Day01 `dotnet build --no-restore` 통과
- [ ] 사용자 청취 확인

동심원 생성 수는 그대로 유지한다. 생성 이벤트가 들어올 때만 재생하므로 정지 중 새 소리는 나지 않는다. 이벤트가 0.6초 이상 없었다가 다시 들어오면 첫 재생 볼륨을 사용한다. 독립 AudioSource 3개로 앞 소리의 여운과 피치를 보존하고, 모두 사용 중이면 추가 재생을 생략한다. Reset/Dispose 시 모든 채널과 재생 간격·직전 클립 상태를 정리한다.

뱅크의 WaterRippleVariants 배열을 설정할 수 있다. 기존 WaterRipple 단일 참조도 호환하며, 기본 Day01은 Resources/DevlogAudio/WaterRipples의 5개 파일을 주입한다. 원본/분석/재현은 res/audio/freesori-water에 보관한다. 새 음원을 Archive로 옮기던 정리는 이미 이전 후보 이름에 한정되어 이 하위 폴더를 건드리지 않는다.

원본 구간: 1.12~1.60, 2.30~2.68, 2.84~3.30, 4.64~5.00, 6.86~7.38초. 44.1kHz/16bit/스테레오 유지. 편집본은 파형 기준이며 청취 검증을 실행하지 않았다. 추출 스크립트로 클리핑 없음과 Unity 임포트본 바이트 일치를 확인했다. 빌드는 오류 0개, 기존 ShowcaseTarget.cs:129의 CS0252 경고 1개다.

확인: Unity 임포트 후 Day01 After에서 물 위로 마우스를 연속 이동한다. 같은 발사음 같은 반복 대신 서로 다른 약한 물소리가 느슨한 간격으로 이어져야 한다. 0.6초 이상 정지 후 재이동하면 첫 소리가 조금 선명하고, 정지 시 여운만 남아야 한다. R/공간 전환 시 모든 물소리가 멈춰야 한다.

## 시작 어택 제거

사용자가 지적한 시작의 탁 소리를 줄이기 위해 기존 편집본의 첫 100ms를 제거했다. 현재 원본 2.30~2.60초의 0.30초 클립이며 시작 페이드는 30ms다. 남은 소리를 재정규화해 키우지 않고 기존 게인을 유지했다(피크 -16.12dBFS). Unity 임포트 WAV를 같은 경로에 갱신했고 메타데이터는 유지했다. 파일 길이, 무클리핑, 양끝 0샘플, 임포트본 바이트 일치를 확인했다. 코드 변경 없이 음원만 수정했으며, 아래 0.4초 설명은 최초 적용 기록이다. Unity에서 다시 Play하고 물 타일 위로 마우스를 움직여 시작의 탁 소리 제거 및 남은 물소리 볼륨을 확인한다.

## 무음 후속 수정

사용자 무음 제보 후 Resources의 WAV가 없고 같은 파일과 Unity 생성 메타가 Audio/Archive에 있음을 확인했다. Day01ModuleOrganization의 반복 정리가 기존 네 음원 외 모든 파일을 미사용으로 취급한 것이 원인이다.

정리를 알려진 이전 후보 9개로 한정해 신규 음원을 보존한다. 다음 Unity 스크립트 리로드/편집 모드 진입 시 AssetDatabase.MoveAsset으로 물소리를 Resources에 복구하며 GUID를 유지한다. 런타임 클립 누락 시 경고도 추가했다. Audio와 Day01 Editor ModuleValidation 빌드는 경고/오류 0개로 통과했다. Play 청취는 실행하지 않았다.

## 변경 전후

기존에는 물 호버 동심원만 생성됐다. 이제 실제 물 흔적 슬롯을 생성한 경우 Hover 모듈이 이벤트를 발행하고, Day01 조립 코드가 Audio 모듈의 별도 물소리 채널로 전달한다. Hover와 Audio 사이의 어셈블리 의존성은 추가하지 않았다.

8.5초 원본에서 2.20~2.60초를 추출했다. 10ms RMS상 2.21초 어택 뒤 감쇠하는 구간이다. 양끝 페이드와 피크 -6dBFS 조정으로 반복 재생을 준비했다. 청취로 확정한 결과는 아니며 사용자 확인이 필요하다.

기존 오디오 뱅크/씬 참조를 유지한다. 뱅크의 WaterRipple이 있으면 우선 사용하고, 없으면 Day01이 Resources의 편집본을 로드해 주입한다. WaterRippleVolume 기본값은 0.35다. 빠른 이동 및 같은 프레임의 여러 동심원은 최소 0.10초 간격으로 소리를 제한한다. 물 흔적 슬롯이 가득 차 새 동심원이 생성되지 않으면 소리도 요청하지 않는다.

R 초기화와 공간 전환은 물소리 채널과 간격 상태를 초기화한다. OnDisable에서 이벤트 구독을 해제하고 생성한 AudioSource를 정리한다. 메타데이터는 Unity 자동 임포트에 맡기며 수작업 생성하지 않는다.

## 사용자 확인 절차

1. Unity 임포트/컴파일 완료 후 Day01 씬을 Play하고 3번 After 공간으로 전환한다.
2. 물 타일 위에서 마우스를 움직이면 동심원 생성과 함께 짧은 물소리가 나야 한다.
3. 마우스를 멈추거나 육지로 옮기면 새 물소리가 나지 않아야 한다. 이미 재생 중인 0.4초 소리는 자연스럽게 끝난다.
4. 빠르게 이동해도 과도하게 겹치지 않고 나무/돌 타격음은 기존대로 재생돼야 한다.
5. 재생 중 R 또는 1/2 공간 전환 시 물소리가 멈추고, 다시 After에서 정상 재생돼야 한다.

프로젝트 규칙에 따라 Unity Play/Test Runner는 실행하지 않는다. 출처 및 사용자 확인에 따른 적용 근거는 `docs/audio-credits.md`에 기록한다.

# 조작과 자동 기여

> 최신 규칙: 초반의 모든 커서 작업은 대상 직접 클릭 1회로 실행하며, 자동화 강화 후에만 호버 주기 작업이 열린다. 아래의 시작부터 자동 기여 설명/과거 QA는 변경 전 기록이다. [최신 규칙·구현·검증](46-click-work-and-automation.md).


## 2026-09-19 최신 추가 · 단계형 튜토리얼

첫 플레이 튜토리얼은 [44 단계형 튜토리얼](44-guided-tutorial.md)을 따른다. HUD 순차 공개, 채집·농장·집·밤 방어·정산·유물 학습 후 마을을 유지하며 맵을 확장한다. 이후 튜토리얼 없는 새 게임은 집 1채로 시작한다. 모든 집 파괴가 실패 조건이며 수리는 무료다. 사용자 채택 기획이며 구현·경험 검증 전이다.

## 2026-09-16 최신 변경 · 사용자 피드백 반영

기존 클릭 고정 기여·영역 인구 보너스·커서 필수 공사·자동 환전 규칙은 대체되었다. 커서는 마우스를 따라 기본3초마다 기여하며 주기는 스킬로만 단축한다. 주민은 집에서만 공급하고 집당 주민 수를 강화한다. 주민은 회당 기여량/반경을 높인다. 공사는 자동+커서지원이며 자동 속도 강화가 있다.

낮/황혼/밤/새벽 정산과 공유 시야·마우스 탐험·잔상·임의 암흑 침공을 추가했다. 귀중품은 새벽에 돈으로 정산한다. 에테론은 환생 전용이다. 교역소는 클릭 모달의 재료별 비율 슬라이더와 환전 버튼으로 한 번 판매하며1개 제한은 유지한다. 병영은 생산/병종 목록 모달, 모든 모달ESC. 병력 클릭/박스 선택과 선택 몸체 드래그 공격 이동, 비중첩·배회. 카메라는중심400px이내정지·바깥비선형가속.

구체 구현/가설 수치·검증 상태는 [10 플레이 피드백 반영](10-playtest-revision.md)을 따른다. 이전 절의 대체된 규칙/첫 계산을 현행으로 사용하지 않는다.


- 핵심 요약: 주민 개별 지휘를 제거하고 주민 수로 커서 원형 기여를 강화한다.
- 상태: 방향 변경 반영. 세부 효율·반경·스킬 트리는 검토 중. 구현·검증 없음.

## 채택 규칙

주민은 개별 조작 대상 대신 주민 수로 표시하며 주민 수가 늘수록 커서 행동 효율이 좋아진다. 주민 수가 늘면 커서 범위와 작업 효율이 모두 증가한다. 커서 지휘에 주민이 자동 배정되어 행동하는 컨셉이며, 실제 개별 이동·시각화 여부는 미정이다. 재화 기반 스킬 트리 강화도 포함한다.

주민 클릭 선택·드래그 선택·선택 교체·작업 배정·선택 해제는 대체되었다. 병력은 별도 존재하며 병력 지휘까지 없애거나 기존 주민 입력을 병력에 자동 적용하지 않는다.

## 유지되는 자동 기여

- 클릭 위치를 중심으로 한 개의 원형 범위 지정. 새 작업 위치 지정 시 범위 이동.
- 범위 안의 가능한 채집·건설·수리 동시 수행.
- 활성 중 새 오브젝트·피해 감지. 개별 고갈·파괴 후 나머지 작업 유지.
- 모든 작업이 끝나면 종료. 마우스 이동과 무관하게 지정 범위 유지.
- 기본 작업 상태에서 우클릭은 자동 기여 취소. 건설·스킬·병력 모드의 입력 우선순위는 미정.
- 건설 비용은 배치할 때 지불하고 커서 기여로 공사 진행. 주민 수가 효율에 반영됨.

목재·석재 자동 수급 건물을 포함한다는 사용자 후속 결정에 따라 커서 기여와 별개의 자동 생산을 설계한다. 수동 주민 선택·배정은 재도입하지 않는다. 커서 명령의 자동 배정은 사용자 컨셉으로 채택한다. 주민 수 변화가 활성 기여에 즉시 반영되는지, 인구 0명의 기본 효율은 후속 설계다.

## 혼동 방지

원형 경계·영향 대상 표시, 우클릭 역할 안내, UI·드래그 입력과 월드 클릭 분리, 전체 완료 알림은 유지한다. 주민 선택 테두리와 선택 해제 우클릭 분기는 개별 선택 제거로 불필요해졌다. 주민 수와 현재 작업 효율을 보여주는 UI를 새 제안으로 둔다.

## 후속 결정

집당 주민 +1과 농장 상한의 연결·건물 파괴 후 효과 처리·작업 비용 부족, 병력 조작, 건설·스킬 모드가 남아 있다. 과거 결정은 [결정 기록](decisions.md)에 보존하며 이전 역할 분담을 새 기획의 검증 근거로 사용하지 않는다.

## 성장과 환생 화면

주민 수는 범위·작업 효율을 함께 높이고, 일반 스킬 트리는 범위 증가율의 효율과 수행 효율을 강화한다. 일반 강화는 연구소가 필요하다. 병력은 마을 주변 방어 위치에 배치하고 순찰한다. 환생은 제단이 필요하며 웨이브 종료 후 정비 시간에 가능하다. 환생 화면은 같은 판 안에서 진행을 처음으로 돌리고 해당 판에만 유지할 강화를 구매하는 흐름이다. 클리어·패배 결과 화면의 영구 콘텐츠 해금과 구분한다. 입력·전환 조건은 미정이며 상세 수명은 [성장 문서](05-system-map.md)를 따른다.

연구소 조건을 충족하면 일반 강화는 웨이브 진행 중에도 재화가 있을 때 구매할 수 있다. 화면을 여는 입력·배치와 게임 시간 정지 여부는 미정이다. 환생 시 일반 강화 초기화, 환생 강화 유지, 판 종료 시 두 강화 초기화를 구분해 표시하는 것을 제안한다.

## 환생 정산 단계

환생 시 처치 횟수·남은 일반 재화 등으로 추가 특수 재화를 정산하는 단계는 사용자 채택이다. 정산 내역→보유 특수 재화 확인→강화 구매→웨이브 재시작 순서를 제안한다. 정산 내역과 이미 지급된 웨이브 보상을 구분하는 상세 UI는 아직 제안이다.

## 환생 진입과 초기화 · 확정

제단 조건을 충족한 상태에서 웨이브 종료 후 정비 시간에 환생 가능. 정산과 강화 구매 후 마을·주민·병력·일반 재화·일반 강화를 시작 상태로 초기화하고 첫 웨이브로 돌아간다. 환생 강화·미사용 특수 재화·영구 해금은 유지한다. 모든 집 파괴 시 패배로 판이 종료되므로 환생 진입으로 대체하지 않는다.

세계관은 중세 판타지이며 마물들이 마을로 침공한다. 신을 모시는 제단을 포함한다. 신의 정체·커서의 세계관상 정체·환생 원리는 아직 정하지 않는다.

### 병력 · 사용자 지정 / 역할은 AI 제안

- 전사: 기본 근접 전열.
- 궁수: 단일 대상 원거리 지속 공격.
- 마법사: 다수 마물에 대한 범위 공격.
- 기사: 높은 생존력으로 위험한 전선을 유지. 마법사와 기사는 비용과 역할로 구별해 전사·궁수를 모두 쓸모없게 만들지 않는 안.

마을 주변 배치·순찰 방향은 유지한다. 병영 외 별도 마법사 생산 건물을 임의로 추가하지 않으며 병영 생산·연구 해금 조합을 추천한다.

### 마물 · 사용자 지정 / 역할은 AI 제안

- 슬라임: 초반 기본 방어 확인.
- 고블린: 빠른 접근과 빈틈 공격.
- 고블린 전사: 기본 고블린보다 단단한 전열.
- 고블린 주술사: 다른 마물 지원으로 우선 공격할 이유 제공.
- 오크: 강한 근접 압박과 건물 위협.
- 리자드: 측면 우회·빠른 교전 등 후보. 고블린과 차별점은 추가 결정.

추가 마물은 확장 후보로 둔다. 최종 웨이브의 보스 유무·종류는 아직 미정이다.

### 성장 연결과 소개 순서 · 제안

집 하나당 주민 +1 → 농장으로 주민 상한 확대 → 주민 증가로 커서 범위·작업 효율 증가. 연구소에서 일반 강화와 기사를, 제단에서 마법탑·마법사·환생·일부 노드를 해금한다. 벌목소·채석장은 독립 자원 수급을 만들어 커서를 공사·복구에 돌릴 여유를 제공한다.

집·기본 커서 작업 → 농장·자동 생산 → 전사·화살탑의 기본 방어 → 궁수와 빠른 마물 → 연구·마법사·마법탑·주술사 대응 → 기사·강한 마물·제단 스킬을 순차 소개하는 안이다. 정확한 웨이브 번호와 처음부터 해금된 목록은 미정이며 환생을 필수 절차로 고정하지 않는다.

### 다음 결정

기본 주민 상한 1, 시작 집 1개·주민 1명, 농장·목장 상한과 크기가 확정되었다. 다음은 집의 배치 가능 위치와 마을 영역의 확장·축소 규칙을 구체화한다. 연구소·제단 파괴 시 해금 유지 여부도 후속 미정이다.

### 강화와 선행 건물 · 사용자 채택

일반 스킬 트리는 연구소를 만들어야 이용 가능하다. 제단이 여는 일부 일반 강화 노드는 연구소의 기본 강화 조건에 추가되는 것으로 정리한다. 따라서 연구소만 있으면 일반 노드를, 연구소와 제단 조건을 모두 충족하면 제단 전용 노드를 강화한다. 구매 비용·노드 목록은 미정이다.

기존 병영 생산 구조에 연결하면 기사는 병영+연구소, 마법사는 병영+제단을 선행 조건으로 제안한다. 연구소·제단 자체에서 병력을 생산한다고 확정하지 않는다. 환생 강화 화면에도 연구소가 필요한 것으로 확대하지 않는다. 연구소 조건은 현재 대화의 일반 스킬 트리에 적용한다.

## 마을 영역과 인구 · 사용자 채택

- 시작: 집 1개와 주민 1명, 기본 주민 상한 1.
- 집: 1×1, 집당 주민 +1. 집을 중심으로 반경 N타일의 마을 영역 생성. N은 미정.
- 농장: 1×1, 주민 상한 +3. 목장: 2×1, 주민 상한 +10.
- 집을 포함한 신규 건물은 기존 마을 영역 안에만 배치한다（사용자 채택）. 새 집이 완공되면 해당 집의 영역이 생겨 마을을 바깥으로 확장한다. 착공만으로는 영역이 늘어나지 않는다. 시작 집은 최초 제공 상태다.
- 가까운 집의 영역은 점성 있는 것처럼 서로 붙으려는 형태로 연결된다. 집들이 가까울수록 각 집의 반경이 조금씩 증가한다.
- 마을 영역이 차지하는 타일 수 10개 단위마다 주민 +1, 인구 상한을 넘지 않도록 증가한다.

### 영역 판정 제안 · 미채택

- 시각적인 연결 효과와 실제 건설 가능한 타일 판정을 일치시킨다. 중복 영역 타일은 한 번만 센다.
- 집 사이 거리로 보너스를 계산하고, 확장된 반경이 다시 보너스를 무한히 늘리지 않도록 기본 집 위치를 기준으로 계산하는 안을 추천한다.
- N, 근접 판정 거리·보너스·최대값, 원 경계의 타일 포함 규칙, 서로 떨어진 마을 영역의 인구 집계 방식은 미정이다.
- 2×1 목장 등 다중 타일 건물은 점유하는 모든 타일이 마을 영역 안에 있을 때 배치 가능하도록 추천한다.
- 주민 수로 커서 기여 범위가 증가하는 규칙과 집 위치로 마을 영역이 증가하는 규칙을 구분한다. 둘은 서로 다른 범위다.

### 배치 선택의 의도와 위험

가깝게 지으면 연결·반경 보너스와 방어 집중의 이점이 있고, 넓게 배치하면 겹침을 줄여 새 타일을 확보한다. 어느 방식이 항상 유리한지는 아직 검증하지 않았다. 목장은 농장보다 면적당 상한 증가가 크므로 비용·선행 조건 또는 2×1 공간 확보의 대가를 후속 설계한다.

집 파괴로 영역이 축소돼도 기존 건물은 존속하며 정상 작동한다. 주민 보너스·현재 인구는 변경된 집·영역·상한에 맞춰 즉시 재계산한다（사용자 채택）.

### 영역 축소 후 처리 · 사용자 채택

집이 파괴되면 남은 집으로 마을 영역을 다시 계산하되, 영역 밖으로 밀려난 기존 건물은 자동 철거하지 않고 정상 작동한다（사용자 채택）. 신규 건설만 현재 마을 영역으로 제한한다. 집 한 채 손실이 주변 건물 전체의 연쇄 상실로 이어지는 것을 줄이려는 목적이다. 커서 채집·수리 가능 범위를 건설 영역으로 추가 제한하지 않는다.

집·영역·농장·목장 감소 시 주민 수와 상한을 즉시 재계산한다. 영역 밖 기존 집을 인정하는 경우 남은 완공 집의 영역을 모두 합쳐 재계산하는 일관성이 필요하다. 건물 존속과 기능 유지, 인구 즉시 재계산은 채택되었으며 아직 구현하지 않았다.

### 마지막 집 파괴 · 사용자 채택

집이 모두 파괴되면 다른 건물·병력이 남아 있어도 게임 오버다. 기존 모든 건물 파괴 패배 조건에 추가되며 마지막 집이 먼저 파괴되면 그 시점에 판이 끝난다. 마지막 집 소멸 후 복구용 집 건설 예외 제안은 폐기한다.

집이 일부 파괴된 경우에는 남은 집으로 영역을 재계산하고 영역 밖 기존 건물은 정상 작동한다. 건설 중인 집은 생존 집으로 세지 않는다. 최종 웨이브 성공·마지막 집 파괴가 동시에 일어난 경우의 우선순위는 미정이다. 환생 초기화 중 잠깐 집이 없는 상태를 전투 패배로 판단하지 않는다.

### 인구 변경과 커서 갱신 · 사용자 채택

건물 파괴·영역 변화로 주민이 줄면 커서 기여 범위와 수행 효율을 즉시 갱신한다. 자동 기여를 일괄 취소하지 않고 기존 중심의 줄어든 범위 안에서 작업을 계속한다. 남은 작업이 없을 때는 기존 종료 규칙 적용. 재건 시 주민·효율·범위도 현재 조건에 맞춰 회복한다. 이미 종료된 기여를 재건만으로 자동 재시작하지 않는다.

주민 수 변화와 원인（집·농장·목장 파괴 또는 영역 변화 등）을 알아볼 수 있게 표시한다. 이미 완료된 건설이나 지급된 자원을 되돌리는 것은 아니며 이후 작업 속도·대상이 바뀌는 것으로 정리한다.

### 해금 시설 파괴 처리 · 사용자 채택

연구소·제단이 파괴돼도 이미 구매한 강화와 생산한 병력·완공한 건물은 유지하고, 해당 시설을 필요로 하는 새 강화 구매·신규 생산·건설·환생만 제한한다（사용자 채택）. 다시 지으면 이용 가능해진다. 이미 진행 중인 생산·건설의 처리는 아래 채택 묶음을 따른다. 마지막 집 파괴에 의한 게임 오버 규칙은 유지한다.

## 건설·생산·파괴·복구 정책 묶음 · 사용자 채택

사용자가 대화에서 제시된 건설·생산·파괴·복구 묶음을 채택했다. 선불 생산비 환급은 대화 표에 포함하지 않았으므로 아래에서 별도 제안으로 구분한다.

| 상황 | 추천 처리 | 이유 |
|---|---|---|
| 연구소·제단 파괴 시 이미 시작한 기사·마법사 생산 또는 마법탑 공사 | 생산을 수행하는 건물·건설 현장이 살아 있으면 완료까지 진행. 새 주문은 제한 | 선행 조건을 이미 충족해 시작한 작업을 안정적으로 마무리 |
| 병영 자체 파괴 | 그 병영의 진행 중 생산과 예약 주문 취소. 기생산 병력은 유지 | 생산 주체가 사라진 경우와 해금 시설 손실 구분 |
| 파괴된 시설 재건 | 재건 완료 시 해당 선행 조건 복구. 강화 재구매는 불필요 | 기존 성과 유지 원칙과 연결 |
| 건설 중 건물 | 파괴 가능하지만 완공 전 인구·영역·해금·생산 기능 없음. 생존 집 판정에도 미포함 | 건설 현장만 반복 배치해 게임 오버를 회피하지 못하도록 함 |
| 사용자가 미완성 건설 취소 | 선불 비용 중 미진행 비율 환급 | 예: 진행 30%면 비용 70% 환급. 미진행 비율 환급 채택, 반올림 미정 |
| 적이 건설 현장·건물을 파괴 | 건설 비용 환급 없음 | 방어 실패 비용을 유지 |
| 수리 재료 부족 | 해당 수리만 대기, 가능한 다른 작업은 지속. 재료 확보 시 재개 | 부족은 완료가 아니므로 자동 기여가 잘못 종료되지 않게 함 |

위 공사 지속 규칙은 자동 작업이 없는데도 스스로 공사한다는 뜻이 아니다. 커서 기여 등 정상 진행 조건은 여전히 필요하다. 파괴된 연구소·제단이 여러 개 중 하나라면 유효한 같은 시설이 남아 있는 동안 선행 조건은 충족되는 안이다.

완공 건물의 자발적 철거·수리 소비율·상세 동시 승패 순서는 미정이다. 마지막 완공 집이 파괴되면 미완성 집이 있더라도 패배한다. 아직 구현하거나 테스트하지 않았다.

## 자동 수급·병력 생산·순찰 묶음 · 사용자 채택

### 운영 흐름

벌목소·채석장의 지속 수급 → 일반 강화와 병력 생산에 투자 → 병영 집결 지점으로 병력 이동 → 지정 위치 주변 순찰·자동 교전 → 손실 병력 보충.

| 항목 | 추천 규칙 | 목적 |
|---|---|---|
| 자동 수급 | 완공한 벌목소·채석장은 일정 주기로 재화에 직접 지급. 주민 배정·운반 불필요 | 개별 관리 부담 줄이기 |
| 커서 채집과 구분 | 커서는 자연 자원 오브젝트를 채집하고, 생산 건물의 주기 지급은 별도로 진행 | 생산 시설 클릭으로 수급이 중복되지 않도록 함 |
| 생산 시설 유지 | 건물이 살아 있는 동안 작동. 주변 자원 배치·고갈 조건 없이 운영 | 고갈 후 반복 이전 부담을 줄임. 수급 과잉 위험은 비용·주기로 검증 |
| 병력 생산 | 병영에서 병종과 수량 예약, 병영 하나당 한 기씩 순차 생산, 비용은 주문 시 선불 | 인구 전환 없이 자원·시간으로 전력 확대 |
| 생산 해금 | 기본 병종 전사·궁수, 기사에 연구소·마법사에 제단 필요. 생산 시작 시 선행 조건 확인 | 선행 시설 파괴 시 이미 진행 중인 생산 유지 규칙과 연결 |
| 예약과 환급 | 선행 시설이 없어지면 아직 시작하지 않은 해당 주문은 대기. 수동 취소 또는 병영 파괴 시 미시작 전액·진행 중 미진행 비율 환급 | 이미 진행한 주문과 대기 주문을 구분. 주문 시 선불과 이 환급 규칙은 사용자 채택 |
| 집결 | 병영별 집결 지점을 지정, 생산된 병력은 자동 이동 | 한 기씩 배치하는 반복 입력 감소 |
| 순찰·교전 | 집결 지점 주변 자동 순찰, 감지 범위 안의 적 공격. 추격 한계를 넘거나 적이 사라지면 복귀 | 병력이 마을에서 멀리 끌려가지 않게 함 |
| 재배치 | 집결 지점 변경 시 해당 병영에 연결된 기존 병력과 신규 병력 모두 새 지점으로 이동 | 병력 개별 선택 없이 전선 단위 지휘 |

집결점 지정 입력·유효 타일·경로가 없는 경우·병영 파괴 후 기생산 병력의 집결점 소유는 미정이다. 파괴된 병영의 병력도 마지막 지정 위치에서 순찰을 유지하는 안을 제안하되 재배치 수단은 후속 설계한다. 주민 상한을 병력 제한으로 재사용하지 않으며 병력 상한은 미정이다. 실제 병력 생산 비용·속도·순찰 반경은 수치 단계에서 제안한다.

대화에 제시된 자동 수급·생산·집결·순찰 묶음은 사용자 채택되었다. 병영 소멸 후 집결점 소유·경로 실패 같은 후속 세부안은 별도 미정이다. 다음은 마물 역할·웨이브 구성이다. 게임 구현·테스트는 실행하지 않는다.

## 마물·웨이브·공격 예고 묶음 · 사용자 채택

### 마물별 역할

| 마물 | 추천 역할 | 준비할 대응 |
|---|---|---|
| 슬라임 | 느린 기본 근접 마물 | 기본 전열·화력 확보 |
| 고블린 | 빠르게 접근하는 약한 근접 마물 | 넓은 감시와 궁수·화살탑 |
| 고블린 전사 | 일반 고블린보다 튼튼한 전열 | 전사·기사로 버티고 후열 화력 집중 |
| 고블린 주술사 | 뒤에서 아군 마물을 강화하는 지원형 | 후방까지 영향 주는 마법·범위 스킬 |
| 오크 | 느리지만 건물에 강한 피해를 주는 공성형 | 접근 전 화력과 전열 저지·수리 |
| 리자드 | 떨어져 공격하는 원거리 마물 | 병력 재배치로 사거리 압박·접근 |

사거리·체력·피해·주술사 효과는 아직 수치화하지 않는다. 리자드는 고블린의 빠른 접근과 겹치지 않게 원거리 역할로 채택되었다. 병력별 세부 공격 우선순위는 미정이다.

### 웨이브 구조

- 초반: 한 방향의 슬라임·고블린으로 채집·건설·기본 방어 흐름 소개.
- 중반: 전사형·주술사 등 서로 다른 역할을 섞고 공격 방향을 늘려 병력 구성과 재배치를 요구.
- 후반: 오크·리자드를 포함한 혼합 공격으로 전열·후열·시설 보호를 함께 요구. 적 수와 능력치만 일괄 증가시키지 않음.
- 최종: 보스급 마물 1종과 호위 마물이 등장하는 종합 방어전으로 채택. 보스 종류와 기술은 미정이며 신규 보스 제작 범위는 M3에서 검토.
- 일반 웨이브는 예정된 적 생성이 끝나고 남은 적을 모두 처치하면 클리어. 최종 웨이브도 보스뿐 아니라 남은 호위까지 처리해야 최종 승리한다.
- 정비 시간에는 적 종류·주요 특징·진입 방향·남은 시간을 표시. 전투 시작 후 예고 없이 새 진입 방향을 추가하지 않는 안.
- 지형·건물과 겹치지 않는 전장 외곽에서 생성하고 마을로 향한다. 막힌 경로와 적 정체로 클리어가 불가능해지지 않도록 검증 필요.
- 환생 후 같은 번호의 웨이브는 같은 기본 적 구성을 유지한다. 진입 방향·지도 재생성 여부는 별도 미정. 강화 전후 차이를 읽기 쉽게 하기 위함.

정확한 웨이브 수·준비 시간·전체 판 길이는 이 역할 묶음의 채택 이후 제안한다. 실제 플레이 검증 전이며 웨이브 간 조건을 처음부터 모두 수치 고정하지 않는다.

웨이브 수·시간·보상·비용의 첫 수치 묶음은 [05 경제·밸런스](05-system-map.md)에 제안했다. 역할·진행 구조 채택과 수치 검증은 구분한다.

## 커서 공격과 첫 전투 갱신

사용자 요청: 커서의 적 피해 추가, 범위 내 각 대상은 속도 분배 없이 독립 동시 작업. 첫 웨이브는 커서만으로 대응하고 두 번째부터 전사2명 준비를 목표로 재설계한다. 나무 클릭도 범위 내 다른 가능한 작업을 막지 않는다. 고정 범위 안 적에게 지속 피해·범위 밖 피해 중단·작업과 공격 병행·모든 작업 종료 후 새 적에는 재클릭이라는 연결안과 준비60초/첫 정비45초 변경안은 [05 v0.3](05-system-map.md)에 새 제안으로 기록했다. 게임 구현 없음.

## 3D 픽셀 아트 시각 방향 · 사용자 희망 / 기술 검토

사용자는 3D pixel art shader 방식의 가능성을 질문했다. 3D 모델과 장면을 낮은 내부 해상도로 렌더링하고 선명하게 확대하며 제한된 색·명암·윤곽선을 조합하는 방향을 추천한다. 셰이더만으로 기존2D 자산이3D가 되는 것은 아니며 모델·애니메이션·카메라·조명 제작 범위가 따로 필요하다.

추천 표현: 중세 판타지 마을을 비스듬히 내려다보는 고정 각도 직교 카메라, 단순한3D 모델, 픽셀 표현과 단계적인 명암. UI·글자·건설 안내·커서 범위는 가독성을 위해 별도 선명한 계층으로 유지한다. 카메라 이동 시 픽셀 떨림과 병력/마물 실루엣 구분은 검증 대상이다. 각도·해상도·색상표는 미정이다.

읽기 확인: 기존 impls/unity/Afterlife/Packages/manifest.json에 URP17.0.4 의존성이 있다. 렌더러 전환/호환성 검증이나 실제 화면 테스트는 수행하지 않았다. 별도 Afterlife 3d Test 폴더도 존재하지만 이번에는 내부 구현을 조사하지 않았으므로 재사용 가능 여부를 단정하지 않는다.

Unity6의 Full Screen Pass는 화면 전체에 머티리얼 효과를 적용할 수 있는 기반이다. 저해상도 렌더링과 조합하는 구체 파이프라인은 개발 단계에서 결정한다. 근거: https://docs.unity3d.com/cn/6000.0/Manual/urp/renderer-features/renderer-feature-full-screen-pass.html

개발 요청 후 집·나무·슬라임과 커서 범위를 담은 작은 시각 검증 장면으로 크기/명암/픽셀 안정성을 먼저 확인하는 안을 제안한다. 지금은 기획 기록만 수행하며 구현을 시작하지 않는다.

## M3 공간·호버 결정 반영

사용자 확정: 3D pixel art, 건물 사각 격자 배치, 적 연속 좌표 자유 이동, 큰 건물의 외곽 정지/공격, 모든 월드 오브젝트 호버 포커스. 새 프로토타입 씬에서 개발한다. 구체 검증 범위는08·07 최신 항목 참조. 호버는 활성 커서 범위를 이동시키지 않는 연결안이다.

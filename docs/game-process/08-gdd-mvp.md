5. 완결과 검증: 초기화·결과·재시작, 취소/파괴/부족 예외, 기술 확인 후 사용자 플레이 관찰. [07 검증 계획](07-validation.md)에 증거 기록.

## 공간·상호작용·씬 구성 · 최신 사용자 확정

- 시각 방향은3D pixel art. 지도상의 건물 배치는 사각 격자에 맞춘다. 건물의 점유 크기에 해당하는 연속 타일을 검사하여 배치하며 임의 좌표에 건물을 놓는 방식은 사용하지 않는다.
- 적 이동은 격자 칸 중심으로 제한하지 않는다. 지면 위 연속 좌표로 이동하되 건물과 장애물을 통과하지 않는 경로를 사용한다. 자유 이동은 충돌 무시·공중 이동을 뜻하지 않는다.
- 1×1보다 큰 건물도 건물 중심으로 파고들지 않고 외곽에서 멈춰 공격한다. 표적 중심과의 거리 대신 건물 외곽까지의 거리·적 몸체 크기·공격 사거리를 고려하는 구현안을 권장한다. 원거리 적이 추가될 때도 외곽 기준 사거리로 확장한다.
- 모든 월드 오브젝트는 호버 시 포커스 피드백을 표시한다. 건물·공사 중 건물·나무·바위·병력·적을 포함한다. 호버는 클릭 선택이나 활성 커서 범위를 옮기지 않는다.
- 프로토타입은 새로운 씬에서 진행한다. 이번 요청은M3 범위 수정이며 현재 씬 생성·코드 구현은 하지 않는다. 개발 요청 후 개발 대상 프로젝트를 확인하고 기존 씬을 덮어쓰지 않는 새 프로토타입 씬을 만든다.

### 연결 제안과 최소 검증 추가

- 다중 타일 배치는 점유 예정 타일 모두의 영역/충돌 유효성을 표시하고, 하나라도 불가하면 배치를 막는 안을 추천한다. 회전 입력은 첫 범위에 추가하지 않는다.
- 다중 타일 공격을 실제 검증하기 위해 기존 집·농장·교역소·병영4종에 기능 없는2×1 건물 검증용 대상을 개발 확인용으로 추가하는 안을 추천한다. 목장 전체 기능을 첫 플레이에 추가하는 것은 아니다. 병영의 본편 크기를 임의로2×1로 확정하지 않는다.
- 포커스는 얇은 외곽선/밝기 변화로 통일하고 활성 작업 범위와 시각적으로 구분하는 안을 추천한다. 클릭 불가능/작업 불가 오브젝트도 호버 피드백은 표시하되 가능한 행동을 별도로 안내한다. 월드 호버는UI가 입력을 가리는 동안 차단한다.
- 가려진 오브젝트가 겹치면 마우스 광선에서 가장 앞의 유효 대상을 피드백 대상으로 삼는 안을 추천한다. 구체적인 머티리얼/깊이 처리 방식은 개발 시 결정한다.

개발 의존 보완: 새 씬과3D 카메라 → 격자 배치/건물 점유 형태 → 자유 이동/외곽 접근 → 호버 피드백을 커서/경제/웨이브와 연결한다. 적의 목표 선정 정책은 이 공간 규칙만으로 확정하지 않는다.

사용자가 구현 시작을 요청해 M3 범위를 개발 기준으로 채택했다. 이후09의 임시 수치와 명시된 최소 예외로 첫 코드를 구현했다. 새 씬·코드·C# 빌드 완료, 실제 게임 실행 검증은 대기 중이며 M4 검증 완료는 아니다.

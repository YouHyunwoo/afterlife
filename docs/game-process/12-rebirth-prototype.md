# 확장 프로토타입 · 전투 반응과 환생

현재 M4 확장 구현 → M5 검증. 사용자 관찰: “지금 충분히 괜찮은 것 같은데 다음 웨이브를 더 하고 싶었어.” 첫 프로토타입의 핵심 순환은 다음 단계로 확장할 근거를 얻었다. 성능과 모든 예외 상황 검증 완료를 뜻하지 않는다.

## 이번 작업 목록

- [x] 전사/기사 손잡이 회전 공격, 실제 피해와 모션 동기화
- [x] 전투·커서 피해 공통 쉐이크와 0.2초 경직
- [x] 6웨이브 진행과 점진적 적 강화
- [x] 제단/정비 시간 환생 진입, 예상 정산/한 번 지급, 같은 판 내 에테론 유지
- [x] 작업·집 체력·생산의 작은 환생 강화 3종, 단계 비용 증가
- [x] 환생 시 일반 진행 초기화, 최종 승패 시 판 데이터 초기화 및 영구 해금 분리
- [x] C# 및 Windows 빌드, 검증 절차·범위 기록

초기 제안 수치: 6웨이브, 환생 강화 각 3단계, 비용 8→16→32. 이번 구간 클리어 웨이브 w별 성과 2w²의 합을 환생 시 지급한다. 처치·남은 재화의 보너스는 기본 보상의 절반 이하로 제한한다. 웨이브 클리어만으로 에테론을 즉시 지급하지 않는다. 확정 밸런스가 아닌 검증값이다.


## 완료 상태와 현재 단계

M4 확장 구현 및 Windows 빌드 완료. **M5 — 12 확장 프로토타입 플레이 검증 대기**. 첫 2일 프로토타입은 사용자의 수용과 더 진행하고 싶은 반응을 근거로 첫 검증 단계를 마친다. 모든 버그/성능 검증 완료나 본편 전체 기획 완료를 뜻하지 않는다.

## 전투 반응

- 전사와 기사는 실제 소지한 칼의 손잡이 끝을 축으로 상대를 향해 휘두른다. 0.18초 준비 동작 후 모델에서 타격을 판정하고 회복 모션으로 돌아간다. 30Hz 고정 틱에서 타격 시각은 틱 단위로 정렬된다.
- 타격 시 대상이 사라졌거나 사거리 밖으로 이동했으면 피해를 주지 않는다. 피격 중 준비하던 공격은 취소하고, 경직 종료 후 다시 공격할 수 있다.
- 커서/병력/마물 공격을 공통 ApplyDamage로 연결했다. 아군과 마물 모두 피격 시 쉐이크 및 0.2초 이동/공격 정지. 고정 틱의 절대 종료 시각을 사용해 유닛 처리 순서로 경직이 짧아지지 않게 했다.
- 연속 피격은 마지막 피격부터 0.2초로 갱신한다. 별도 경직 면역은 이번에 넣지 않았다. 다수 병력의 경직 집중이 지나치게 강한지는 플레이 확인 대상이다.
- 건물은 피해 시 흔들리고 공사/수리는 기존 바운스다. 궁수·마법사 전용 발사체/공격 아트는 후속이며, 이번 소지 칼 휘두르기는 전사/기사에 적용했다.

## 6일 진행 · 임시 밸런스

- 낮 60초 + 황혼 10초 + 밤 최소 60초 유지. 6일차 방어 후 새벽 결과 확인으로 최종 클리어.
- 침공 수 6/8/10/12/14/16, 체력 32/42/52/62/72/82. 침공 피해는 기본 5에 날마다 15%씩 더한다.
- 두 마리씩 나눠 첫 40초 안에 출현하고 모두 처치해야 새벽으로 넘어간다. 야생 마물은 기존 규칙 유지.
- 환생 없는 최소 진행 시간 약 13분. 남은 적 추격·정산 화면·환생 반복 시간은 별도다. 실제 난이도/소요 시간은 측정하지 않았다.

## 환생 정산과 초기화

1. 완공 제단이 있고 첫 밤 이후, 낮이나 새벽 정산에서 가능하다. 황혼/밤/최종 웨이브 완료/패배에서는 불가.
2. 제단 클릭 또는 새벽 정산의 ‘환생 검토’로 예상치를 확인한다. 미리보기·닫기는 지급하지 않는다. 새벽에서 검토 후 취소하면 원래 정산 화면으로 돌아간다.
3. ‘환생 확정’만 에테론을 한 번 지급하고 Phase.Rebirth로 전환한다. 상태 검사로 재호출을 막는다. 집 하나·일반 재화 0·일반 강화 0·병력 0으로 초기화하고 환생 강화 화면을 연다.
4. 강화 구매 또는 미사용 보관 후 ‘첫날부터 재건’/ESC/닫기로 새 시작 상태를 구성한다. 이번에 산 집 체력 강화도 첫 집부터 적용한다.
5. 이전 환생 강화·남은 에테론·이번 판 환생 횟수는 같은 판 안에서 유지한다. 성과 구간은 새로 시작하므로 다시 클리어한 웨이브는 새 정산 대상이다.
6. 최종 클리어/패배는 에테론을 지급하지 않는다. 일반 재화·강화·환생 강화·에테론·마을·병력을 지우고 결과 요약만 표시한다. 새 판은 처음부터 시작한다.

### 정산식

- 진행 기본 보상: 이번 구간에서 방어 완료한 각 w에 대해 2×w²를 합산. 1/2/3/4/5일 방어 시 누적 2/10/28/60/110.
- 처치 보너스: floor(이번 구간 마물 처치/10).
- 남은 재화 보너스: floor((목재+석재×2+돈)/100). 교역 전후 가치가 같아 환전만으로 보너스가 늘지 않는다.
- 처치+재화 보너스 합계는 진행 기본 보상의 50% 이하. 처치 보너스를 먼저 적용하고 남은 한도에 재화 보너스를 적용한다.
- 제6일 최종 방어 후에는 환생할 수 없으므로 그 시점의 계산값은 지급/소비 재화가 아니다.

### 작은 환생 강화

| 계열 | 단계당 효과 | 최대 | 단계별 가격 |
|---|---|---|---|
| 숙련의 기억 | 기본 채집·커서 건설/수리·자동 건설 효율 +20% | 3 | 8, 16, 32 |
| 수호의 축복 | 모든 집 최대 체력 +25% | 3 | 8, 16, 32 |
| 군세의 기억 | 병력 생산 속도 +20% (시간은 속도로 나눔) | 3 | 8, 16, 32 |

계열별 단계 비용이며 환생 횟수로 전체 가격을 올리지 않는다. 시작 재화/주민 지급, 커서 기여 주기 단축은 이 환생 노드에 포함하지 않는다. 기존 일반 강화와 효과 배율은 곱한다.

## 영구 해금의 최소 예제

같은 판에서 2일 이상 방어한 뒤 승리 또는 패배하면 **청록 마을 깃발 외형**을 해금한다. 환생 자체로는 영구 해금을 지급하지 않는다. 다음 판의 집에 깃발이 표시되며 전투 능력은 증가하지 않는다. 게임 종료 후에도 유지하기 위해 `AfterlifePrototype.Unlock.TealBanner.v1` 전용 PlayerPrefs 키만 저장한다. 기존 출시작 저장 키는 수정하지 않는다.

영구 콘텐츠 전체, 진행 중 판의 저장/불러오기, Steam 도전과제 연동은 여전히 후속이다. 앱을 종료하면 진행 중 판은 저장되지 않는다.

## 검증 증거와 직접 확인 절차

- C# Build-Prototype.ps1: 경고 0·오류 0.
- Unity Windows 개발 빌드: Succeeded, 경고 0·오류 0, 145,632,900바이트, 보고 시간 11.56초.
- 빌드 전후 프로젝트 설정 5개의 SHA256이 일치해 복원을 확인했다. Unity가 새 스크립트 메타를 생성했으며 수동 메타 작성은 하지 않았다.
- Unity 플레이/자동 테스트는 프로젝트 지침에 따라 실행하지 않았다. 상태 흐름은 코드 검토와 빌드로 확인했으며 아래 동작의 런타임 검증은 남아 있다.

1. 전사와 슬라임이 교전할 때 칼 타격과 체력 감소가 맞는지, 양쪽 모두 흔들리고 잠시 멈추는지 확인한다.
2. 2일차를 넘겨 3~6일로 이어지는지, 상단 날짜 바가 중앙부터 스크롤되는지 확인한다.
3. 제단을 완공하고 2일 방어 후 환생 미리보기를 여러 번 열고 닫는다. 실제 지급 전에는 잔액이 늘지 않아야 한다.
4. 환생 확정 시 기본 10+보너스를 한 번 받고, 8을 써서 강화한다. 첫날·집 하나·일반 재화 0·일반 강화 0·강화 효과/미사용 에테론 유지 확인.
5. 같은 판에서 다시 환생하면 같은 계열 다음 가격은 16이고, 이전 강화와 남은 에테론을 유지해야 한다.
6. 승패 후 새 판에서는 에테론/환생 강화가 0이어야 한다. 2일 이상 방어했으면 청록 깃발만 유지되는지 확인한다.

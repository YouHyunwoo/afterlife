## 판정과 범위

이번 프로토타입 UI 변경 범위 통과. 설계 규칙·생성 자산·코드·Windows 빌드·실제 화면과 입력 증거를 확인했다. M5 전체 게임 밸런스나 M6 출시 검증의 완료를 뜻하지 않는다.

기준 화면 1920×1080. 추가 화면 1280×720, 2560×1440, 2560×1080. 설정 UI 배율 80~120%를 확인했다. UI 기본 100%는 폴리싱 전 HUD 대비 약 80% 크기다.

## 실제 입력 검증

`Logs/UIQA/live02`의 게임 창에 Windows 마우스·키보드 입력을 전달했고, 실제 화면과 모델 상태를 함께 저장했다. 주요 증거는 이 문서의 `qa/ui-polish/`에 복사했다. 마지막 후보의 변경은 전리품 아이콘 단순화와 잠금 아이콘 추가이며, 아래 입력·경제·시간 로직은 동일하다. 최종 후보에서는 전체 화면과 잠금·최대 단계 상태를 다시 검증했다.

| 조작 | 실제 관찰 |
|---|---|
| 상단 빈 공간의 집 클릭 | 검사 대상 0 → 237, 선택 테두리 표시 |
| 건설 아이콘 클릭 | `tools=False → True`, 사이드 메뉴를 가리지 않는 목록 |
| 전리품 아이콘 클릭·휠 | `modal=Loot`, 스크롤 0 → 360, 실제 하단 아이템 표시 |
| 전리품 창 ESC | `modal=None`, 월드 조작 복귀 |
| 관리 창 유지 | 남은 시간이 감소, 진행 계속 |
| 메뉴 아이콘 | `modal=Menu`, 시간 3523.439초로 두 캡처에서 동일 |
| 수량 0 환전 클릭 | 돈 2345 유지, 판매 없음 |
| 목재 슬라이더 | 51%·6299개·예상 돈 7873으로 갱신 |
| 환전 버튼 | 목재 12345 → 6046, 돈 2345 → 10218; 예상액과 일치 |
| 연구소 단일 클릭·강화 | 한 번 클릭으로 열림; 돈 10218 → 10188, 기여 주기 1단계 표시 |
| 건물 직접 드래그 | 영역 밖은 안내하고 거절, 유효 타일은 `moving=1`·목적지 건설 시작 |
| 카메라 아이콘·가장자리 이동 | 잠금 해제 후 위치 (10,15,-14)에서 변화 |

| 메뉴 호버·누른 채 유지·해제 | 청록 강조, 테두리 하강, 해제 후 창 열림 |

입력 도구는 실행한 `AfterlifePrototype` PID와 창 이름을 확인한다. Windows 배율을 보정하며, Unity Input System이 인식하는 이동 이벤트도 함께 전송한다. 처음의 이동 실패는 SetCursorPos만 사용하는 QA 도구 문제였고 실제 이동 이벤트를 추가한 후 같은 게임에서 재확인했다. 영역 밖 건물 이전 거절은 정상 규칙이며 결함으로 분류하지 않았다.

- 자동 확인 11/11 통과. [전체 항목](qa/ui-polish/checks.txt). UI 영역 판정, 단일 클릭 분기, 건설 메뉴 분리, 최대 강화 상태, 가장자리·중앙 카메라 동작을 확인한다. 이 결과만으로 실제 입력 검증을 대신하지 않았다.

- [호버](qa/ui-polish/23-menu-hover.png)와 [눌림](qa/ui-polish/24-menu-pressed.png)을 실제 입력 중 캡처했다. 클릭 테두리 강조와 짧은 효과음도 구현했다. 소리의 주관적 청취 품질은 스크린샷 판정에 포함하지 않는다.

## 수정한 문제와 한계

비활성 글자 이중 감쇠, 보조 글자 대비, 큰 UI 배율의 상단 겹침, QA 병영 연결 누락을 발견해 수정 후 재검증했다. 초기 상세 이미지도 사용자의 추가 요구에 맞춰 단순한 16-bit 이미지로 교체했다. 숨긴 플레이어 창에서 얻은 첫 검은 캡처는 유효한 화면 증거에서 제외했다.

최종 플레이어 로그에서 폰트 미할당·C# 예외·셰이더 오류는 발견되지 않았다. 종료 시 `ComputeBuffer` 정리 경고는 이전 `pass02`와 최신 `pass06`에 동일하게 남아 있으며 UI 동작 실패는 재현되지 않았다. 이는 이번 UI QA 통과와 별개로 후속 엔진 자원 정리 점검 항목이다. 장시간 플레이 밸런스·업데이트 저장 호환·출시 안정성은 이번 UI 검증 범위가 아니다.

## 재실행

Unity 에디터가 닫혀 있는지 확인한 뒤 게임 프로젝트에서 `Tools/AfterlifePrototype/Build-Prototype.ps1`, `Build-Windows.ps1` 순으로 실행한다. 화면 점검은 플레이어에 `--ui-qa <출력 폴더>`를 전달한다. 실제 입력 점검은 `--ui-qa-live <출력 폴더>`를 사용한다. 일반 플레이는 인자 없이 실행하며 QA용 상태나 프레임 수집을 사용하지 않는다. QA 실행 중 UI 설정은 사용자 PlayerPrefs에 저장하지 않는다.

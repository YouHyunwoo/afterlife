# 43 · 독립 스킬·강화 시스템과 격자 트리 에디터

- 날짜: 2026-09-19
- 상태: 코드 구현 및 5개 독립 어셈블리 컴파일 완료. Unity 임포트·화면·플레이 검증 대기.
- 사용자 요청: 독립 모듈화된 스킬/강화 시스템, 이후 시스템의 모듈화 원칙, 연구소/제단 격자 트리와 드래그·자동 저장 에디터. 앞서 제안한 두 트리와 모달 화면 구현.
- 작업 목록: 기존 구조 조사 → 독립 코어 → 게임 어댑터와 20개 노드 → 모달/스킬 UI → 격자 에디터 → 독립 빌드와 문서 정리.

## 변경 전후

기존 프로토타입은 VillageModel의 Upgrade enum과 수치, 연구소 탭별 목록을 사용했다. 제단은 환생 기록을 표시했다. 별도의 Dev 강화 에디터와 레거시 스킬 UI는 현재 프로토타입과 다른 구조였다.

새 연구소/제단은 같은 독립 강화 코어를 사용하고 각자 10개 노드를 갖는다. 연구소는 상시 물리/인구/작업 성장, 제단은 스킬·조건부 축복을 담당한다. 기존 제단 환생 기록은 트리의 ‘환생 · 기록 확인’으로 여는 별도 모달에 보존했다. 연구소 탭 목록은 사용하지 않는다. 레거시 개발용 시스템은 별개로 유지한다.

## 모듈 경계

| 어셈블리 | 책임 | 의존성 |
| --- | --- | --- |
| Afterlife.Upgrades | 부모 조건, 가시성, 단계, 가격, 구매 결과, 초기화 | 순수 C#, Unity 및 스킬 모듈 참조 없음 |
| Afterlife.Skills | 해금 단계, 발동 정책, 재사용 시간, 지속시간, 주기 발동 | 순수 C#, Unity 및 강화 모듈 참조 없음 |
| Afterlife.Progression.Unity | ScriptableObject 데이터, 트리 UI, 배경, 드래그/줌 | 두 코어, uGUI, TMP |
| Afterlife.Prototype | 재화/건물 접근, 강화 효과, 스킬 효과, Moonstone 조립 | 독립 모듈을 어댑터에서 연결 |
| Afterlife.Prototype.Editor | 기본 데이터 생성, 격자 편집, 자동 저장/검증 | Editor 한정, 데이터/게임 기본 콘텐츠 |

코어 경로: `impls/unity/Afterlife/Assets/Afterlife/Modules/`. 게임 어댑터는 `PrototypeProgression.cs`, 기본 콘텐츠는 `PrototypeProgressionDefaults.cs`, 화면 연결은 `PrototypeProgressionUi.cs`다. 코어는 재화 지갑과 발동 가능 여부를 인터페이스로 주입받고 이벤트로 외부 효과를 요청한다. 씬 조립에서 모듈을 생성해 Moonstone 컨테이너에 등록한다. Unity 데이터는 시작 시 복제하고 코어에는 순수 정의/값 배열을 전달한다.

이후 신규 시스템도 같은 경계를 따르도록 Unity 프로젝트 `AGENTS.md`에 지속 규칙을 추가했다. 모든 기존 시스템을 이번 변경에서 일괄 재작성한 것은 아니다.

## 트리 규칙과 콘텐츠

- 무료 중심은 강화 노드 수에 포함하지 않는다. 부모가 없는 세 노드는 처음부터 표시한다.
- 부모 중 하나라도 1단계 이상이면 자식 표시, 모든 부모가 각각 1단계 이상이면 구매 해금.
- 부모 최대 단계는 요구하지 않는다. 골드·건물·게임 진행 상태는 별도로 검사한다.
- 노드를 클릭하면 한 단계 구매. 잠긴 노드도 설명 및 부족한 부모를 확인할 수 있다.
- 가격과 효과 값은 각 단계의 총효과이며 단계별 합산 값이 아니다.
- 노드 위치는 정수 격자. 런타임과 에디터에서 X/Y 및 셀 간격을 동일하게 사용한다.
- 환생 및 새 판에서 일반 강화와 제단 스킬 단계/대기시간/버프를 초기화한다. 기존 기억 강화·에테론 규칙은 유지한다.

연구소: R1 주거 개선, R2 작업 도구 개량, R3 작업 반경 확장, R4 주민 숙련 교육, R5 표준 건축 공법, R6 강화 골조, R7 타격 도구 강화, R8 작업 동선 최적화, R9 마을 구획 정비, R10 협동 작업 체계.

제단: A1 낙뢰, A2 풍요의 기도, A3 수호의 불꽃, A4 연쇄 번개, A5 감전 낙인, A6 잔향의 축복, A7 영혼의 보살핌, A8 영혼 수확, A9 축복받은 결계, A10 천벌의 의식.

기본 수치는 앞선 제안의 초기값이며 플레이 밸런스 검증은 하지 않았다. 주거 개선은 집당 인구를 늘리되 기존 농장의 인구 상한을 유지한다. 현재 농장은 생산기가 아니라 인구 상한 건물이므로 풍요는 채집량/시간 및 자원 재생 속도를 높인다. 주문 기본 피해는 24이며 커서 물리 피해 연구와 별개다. 감전은 물리 피해만 증폭한다. 연쇄는 주변 3타일 안의 중복되지 않는 적에게 50% 피해를 준다. 영혼 수확은 낙뢰 한 번 또는 의식 전체에서 풍요 대기시간을 최대 3초 줄인다. 축복받은 결계 보호막은 10초, 수호 보호막은 밤 종료까지 유지하며 큰 보호막만 적용한다.

## 사용법

1. Unity가 새 스크립트/asmdef를 임포트하면 `Resources/AfterlifePrototype/Progression.asset`이 없는 경우에만 기본 데이터를 생성한다. 기존 에셋은 덮어쓰지 않는다. `.meta`는 Unity가 생성한다.
2. `Window → Afterlife → 강화 에디터`를 연다. 새 Tools 메뉴는 추가하지 않았다.
3. 위에서 연구소/제단을 선택한다. 노드를 왼쪽 드래그하면 격자에 스냅된다. 다른 노드 또는 중심과 겹치면 드래그 시작 위치로 복원한다.
4. 빈 곳 드래그로 캔버스를 이동하고 휠로 확대/축소한다. 중앙 복귀 버튼을 제공한다.
5. 오른쪽 선택 노드를 펼쳐 제목, 설명, Grid, Parents, EffectId, SkillId, 단계별 Cost/Value, 표시 형식을 수정한다. 부모는 같은 트리의 노드 ID를 입력한다. 노드 추가·삭제도 지원하며 삭제 시 해당 ID의 부모 연결을 제거한다.
6. 변경 후 0.6초, 포커스 상실 또는 창 닫기 시 자동 저장한다. Undo/Redo 결과도 자동 저장한다. 오류가 있는 데이터도 편집 초안으로 보존하고 화면에 오류를 표시한다. 해결되지 않은 오류가 있으면 게임 조립을 중단해 잘못된 데이터를 실행하지 않는다.
7. 게임에서 완성된 연구소 또는 제단을 클릭하면 전체 화면 트리가 열린다. 노드 클릭은 구매, 빈 곳 드래그는 이동, 휠은 커서 위치 기준 확대/축소다. 런타임 기본 범위는 60~160%, 에디터는 35~160%다.
8. 제단 능력 해금 후 Q=낙뢰, W=풍요, E=의식. HUD 버튼도 제공한다. 공격 스킬 버튼은 마지막으로 가리킨 유효한 월드 위치를 사용한다. 대상이 없으면 최초 발동과 대기시간 소모를 거부한다. 의식의 후속 낙뢰는 현재 커서를 사용하며 유효한 적이 없는 회차는 건너뛴다.

`EffectId`는 게임 어댑터의 효과 계약이다. 새 이름만 입력해서 새로운 게임 로직을 만드는 것은 지원하지 않는다. 새 효과/스킬 행동은 어댑터의 이벤트 처리에 추가하고 데이터와 연결한다. 일반 강화 코어는 해당 효과의 의미를 알지 못한다.

## 화면과 기존 정책

연구소/제단은 `PrototypeModalSurface.Presentation = Screen`과 전체 화면 앵커를 사용한다. 배경은 연구소의 배양관·상승 기포, 제단의 원형 룬·영혼 불꽃·입자다. 외부 이미지 의존성 없이 UI 메시로 표현하며 트리 이동과 별개로 움직인다.

기존 `PauseGameplay` 설정은 변경하지 않는다. 화면이 전체를 가려도 기본 false인 경우 게임이 계속 진행한다. 필요하면 해당 모달 Inspector에서 true로 지정한다. 모달 스택, 아래 화면 입력 차단, ESC 한 단계 복귀 정책을 유지한다. 런타임 트리 객체만 한 번 생성하며 저장된 기존 목록/프리팹은 파괴하지 않고 숨긴다.

## 검증 증거와 수동 확인

`Tools/AfterlifePrototype/Build-Modules.ps1`로 5개 어셈블리를 각각 `dotnet build --no-restore`했다. 마지막 결과 모두 오류 0, 경고 0. 순수 코어 빌드에서는 Unity 참조를 제거한다. 기존 통합 검증 스크립트도 신규 모듈 소스를 포함하도록 갱신했다.

프로젝트 지침에 따라 Unity Test Runner, EditMode/PlayMode 테스트, 플레이 모드 스모크, Windows 플레이어 빌드는 실행하지 않았다. 다음은 사용자가 Unity에서 확인할 항목이다.

| 대상 | 절차 | 기대 결과 |
| --- | --- | --- |
| 임포트/에디터 | 새 스크립트 임포트 완료 후 강화 에디터 열기 | 오류 없는 기본 에셋 생성, 연구소/제단 각 10노드 |
| 자동 저장 | 노드 이동 → 1초 대기 → 창 닫기/재열기; Undo/Redo 반복 | 격자 위치 및 되돌린 결과 유지 |
| 격자 충돌 | 노드를 중심/다른 노드에 드롭 | 기존 위치 복원, 중복 배치 방지 |
| 복수 부모 | R2만 구매해 R8 확인 → R3 구매 | R8 표시/잠김 → 구매 가능. 부모 최대 단계 불필요 |
| 단계/재화 | 노드 반복 구매와 부족 골드 상태 클릭 | 1단계씩 적용, 최대 단계/부족 골드에서 지출 없음 |
| 모달 | 두 건물 열기, 드래그/휠, 제단에서 환생 기록 열고 ESC | 전체 화면, 줌 제한, 아래 UI 입력 차단, 이전 모달 복귀 |
| 스킬 | 각 능력 해금, Q/W/E 사용, 대상 없는 곳에서 Q | 재사용 시간 표시, 실제 피해·생산 효과, 대상 없는 최초 낙뢰는 소모 없음 |
| 효과 조합 | A4/A5/A8 구매 후 번개와 물리/마법 공격 비교 | 연쇄, 물리만 감전 증폭, 풍요 대기시간 감소 상한 |
| 수호 | A3/A7/A9 구매 후 밤/풍요/피격 | 보호막·회복·만료 동작, 큰 보호막 유지, 툴팁/피격 표시 |
| 초기화 | 환생 또는 새 판 | 노드/스킬/잔향 초기화, 기존 기억·환생 흐름 보존 |

기술 컴파일 결과는 실제 화면 품질이나 게임 밸런스 검증을 대신하지 않는다.

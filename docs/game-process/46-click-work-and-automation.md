# 직접 클릭 작업과 자동화 강화

> **이전 구현 기록.** 2026-09-23 영력 기반 자동 상호작용 필드가 대상 클릭 작업과 R8 호버 자동화를 대체했다. 아래 수동 클릭·호버 테스트 절차는 현행 게임의 검증 기준이 아니다. [현재 규칙·수치·검증](47-divine-interaction-fields.md)

## 당시 사용자 확정 규칙

초반에는 플레이어가 직접 클릭하여 작업하고, 이후 자동화 강화를 얻으면 마우스를 올려두는 주기 작업으로 전환한다. 적용 대상은 **모든 커서 상호작용**이다: 나무/바위 채집, 건설 지원, 이전 지원, 수리, 커서 공격, 상자 작업 및 귀중품 획득.

수동 단계에서는 클릭한 한 대상에 1회 작업한다. 버튼을 누른 채 유지하거나 마우스를 올려두기만 해서는 반복 작업하지 않는다. 드래그 선택/이동, 건물 배치, UI 조작은 작업 클릭에서 제외한다. 손상/미완성 건물은 클릭 작업을 우선하고, 완성·정상 건물의 기존 기능 창은 유지한다.

자동화 해금 후에는 기존 커서 원형 범위의 유효 대상 전체에 설정된 주기마다 기여한다. 수동 작업을 추가 중첩하지 않는다. 주민의 작업 효율/반경, 치명타, 작업량 강화는 기존 계산을 공유한다. 병력·타워 자동 전투, 건물 자동 건설·생산, 능동 스킬은 커서 작업과 별개로 유지한다.

## 당시 프로토타입 구현안

- 연구 트리 R8을 **커서 자동화**로 변경했다. 첫 레벨부터 모든 커서 호버 작업을 해금한다. 기존 부모 R2/R3·비용·주기 감소 수치는 유지했다. 접근 시점/가격/밸런스는 이번 사용자 확정 사항이 아니며 체감 후 조정한다.
- 호환 경로인 기존 Upgrade.Pulse 첫 구매도 자동화를 해금한다. 새 플레이/환생/판 초기화 때 연구와 해당 일반 강화가 초기화되어 수동으로 돌아온다.
- 유효한 클릭을 놓으면 0.12초 준비 동작 후 실제 작업·채집량·자국·반동을 함께 적용한다. 수동 클릭 쿨타임은 자동화 주기의 절반인 `Interval × 0.5`이다. 승인된 클릭의 준비 동작 시작부터 계산하며, 대상 종류와 무관한 공통 쿨타임이다. 쿨타임 중 클릭은 큐에 쌓지 않는다. 접촉 전 대상 소멸/작업 불가로 취소되면 쿨타임도 되돌린다. 주기 변경은 남은 시간 계산에 즉시 반영하고 게임 일시정지 중에는 시간이 흐르지 않는다.
- 도끼·곡괭이는 실제 메시 접촉점을 사용한다. 수동 작업은 클릭한 표면 좌표를 기억하고, 자동화 작업은 도구 접근 방향의 교차점을 사용한다. Day01 공용 타이밍으로 접촉 정지(0.045초), 방향성 흔들림/회전, 짧은 밝은 섬광, 누적 표면 자국을 적용한다. 작은 파편은 공용 풀에서 재사용하고 시야와 일시정지를 따른다.
- 자원 소진 후 나무 쓰러짐→유지→디졸브, 바위 조각 튕김/구름→디졸브를 공용 파괴 모듈로 연결했다. 게임 자원 소진 시점과 시각 제거 완료 시점을 분리하며 추가 보상은 없다. Unity 화면 검증은 대기 중이다.

## 이전 규칙과 기록 해석

기존 문서의 ‘시작부터 주기 기여’, ‘클릭 없이 마우스만 올리기’, ‘기여 주기 강화만 존재’ 설명은 이 결정으로 대체한다. 1/2/3초 수치는 과거 버전 또는 설정값이며 초반 자동화가 활성화되어 있다는 의미가 아니다. 과거 QA 성공 결과는 새 클릭 규칙의 검증 증거가 아니다.

## 검증과 체감 확인

C# 빌드 통과. 프로젝트 지침에 따라 Unity Play/Test Runner/HLSL 실행 검증은 하지 않았다.

1. 새 판에서 호버만 하면 채집/공격/수리가 일어나지 않아야 한다. 클릭하면 한 대상에 한 번 동작하며 도구 접촉 순간 수치가 바뀌어야 한다.
2. 나무/바위를 반복 타격하면 흔들림·섬광·파편·누적 자국이 보이고, 호버 색이나 시야 전환에도 일관되어야 한다.
3. 공사/수리/상자/적 클릭, UI 클릭·드래그와의 충돌을 확인한다. 작업 불가 건물의 기능 창은 기존처럼 열려야 한다.
4. R8 첫 구매 후 호버 자동 작업이 시작되고 이후 단계는 간격을 줄여야 한다. 환생/새 판은 다시 수동이다.
5. 메뉴 일시정지/대상 소멸/빠른 연타/재시작 후 잔여 모션·파편·자국·중복 기여가 없어야 한다.

도구 모션 보정: 무작위 등장 방향과 추정 날 좌표를 제거했다. Day01의 카메라 기준 방향/접근 벡터, FBX ImpactPoint 정렬, 제곱 가속·접촉 정지·회수 궤적을 적용한다. 카메라 회전 후 클릭해도 화면 기준 같은 쪽에서 나타나야 한다. 원본 FBX의 축과 크기를 보존한다.

추가 확인: 설정의 작업 주기를 1초/2초로 바꿔 서로 다른 대상에 연타해도 각각 0.5초/1초보다 빠르게 다음 동작을 시작할 수 없는지 확인한다. 빈 곳/UI/드래그 입력은 작업 쿨타임을 소모하지 않아야 한다.

## 상호작용별 모션·피드백

- 공격: 검 휘두르기는 우상단 대각 베기, 좌상단 대각 베기, 위에서 내려베기 3종 중 무작위 선택이다. 같은 스윙 도중 모션이 바뀌지 않으며, 카메라 기준 궤적과 대상 표면 접촉점을 사용한다. 접촉 후 잠깐 정지하고 베는 방향으로 빠져나온다.
- 망치 작업: 건설·수리·이전 지원은 채집 도구와 같은 카메라 기준 접근/접촉/회수와 날 끝 정렬을 사용한다. 기존 검/망치 FBX에 ImpactPoint가 없으면 보존된 축 기준 메시 경계로 런타임 마커를 만든다.
- 채집: 도끼·곡괭이의 Day01 궤적, 방향성 반동, 섬광, 파편, 자국을 유지한다.
- 공격 대상: 접촉 시 섬광과 방향성 피격 반동·밝은 타격 입자. 같은 프레임의 작업/피해 이벤트가 피격 방향을 덮어쓰지 않도록 유지한다.
- 건설·수리·이전 지원: 작업 반동과 녹색 입자. **피격 플래시와 파괴 자국은 적용하지 않는다.** 별도로 실제 피해를 받는 이벤트는 피격 반응을 사용할 수 있다.
- 보물 상자: 손 도구 없이 클릭 지점 반대 방향의 이동/기울기 반동과 타격 플래시, 금색 입자를 사용한다. 소진 시 기존 열림을 유지한다. 귀중품은 기존 손 동작·금색 입자·획득 반응을 유지한다.

수동과 자동 모두 준비 .12초 → 접촉 정지 .045초 → 회수, 총 .285초의 타이밍을 공유한다. 접촉 프레임은 최소 한 번 표시한다. 실제 작업/피해는 접촉 이벤트에서 한 번만 적용하며, 수동 쿨타임은 자동화 Interval의 절반이다. 게임 규칙과 타격 자국의 대상 범위(나무·바위)는 변경하지 않는다.

나무·바위 이외에도 읽기 가능한 메시 표면을 선택에 사용한다. 메시를 읽을 수 없는 대상은 기존 콜라이더/기준 접촉점으로 처리한다. 단위 개체의 움직임은 클릭한 표면의 로컬 좌표를 따라간다.

확인 절차: 적을 여러 번 클릭하여 3종 궤적·접촉 순간 피해·섬광·반동을 확인한다. 손상된 건물 수리/미완성 건물 공사에서는 작업량 증가와 망치 반동·녹색 입자만 보이고 밝은 피격 섬광은 없어야 한다. 상자 작업·귀중품 획득, 카메라 회전, 자동화 전후, 일시정지/재시작도 확인한다. C# 빌드 통과, Unity/HLSL/체감 검증은 미실행이다.

검 모션 후속 보정: 3종 모두 칼끝 이동 보정을 제거하고 손잡이 지점을 축으로 회전한다. 준비 후 접촉 직전 삼차 가속, .045초 접촉 정지, 관성 마무리 베기를 사용한다. 좌/우 대각 베기와 전후 축 내려베기의 회전면을 구분한다. 클릭한 표면이 움직이면 손잡이 기준점도 그 표면을 따른다. 칼날의 중상단이 접촉 시 타격점에 닿는다. 상자는 손 모델 생성 없이 마우스로 맞은 지점 반대 방향으로 튕기고 플래시한다. 건설/수리 무플래시는 유지한다. C# 빌드 통과, Unity 모션 확인 대기.

상자 반동 방향 보정: 화면에 보이는 메시 경계 중심의 수평면에 클릭 광선을 투영하고 중심에서 클릭 반대 방향을 구한다. 시작 시 방향을 고정하며 중앙 클릭은 카메라에서 멀어지는 지면 방향으로 처리한다. 최대 0.14m 이동 후 약 0.265초에 원위치로 돌아오고 반대편으로 재진동하지 않는다. 플래시/기울기/상자 열림은 유지한다. Unity에서 상자 왼쪽·오른쪽·위·아래를 클릭해 반대쪽 반동이 보이는지 확인한다. C# 빌드 통과, 화면 확인 대기.

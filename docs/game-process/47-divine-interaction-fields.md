# 영력 기반 자동 상호작용 필드

## 의도와 현재 규칙

플레이어는 직접 반복 작업하는 대신 영력을 어디에 투자할지 판단한다. 기존 46 문서의 대상 클릭 1회 작업과 R8 이후 커서 호버 자동 작업은 이 구현에서 대체된다.

- 작업 가능한 나무·바위·공사/수리 건물·상자·귀중품·적을 클릭하면 클릭 위치에 고정 필드를 설치한다. 빈 타일이나 기능 창이 있는 건물은 `Shift+클릭`으로 설치한다. 빈 타일 일반 클릭의 건설 메뉴, 완성 건물 기능 창, 병력 선택/드래그, 배치 입력은 유지한다.
- 기본 영력은 최대 100, 설치 비용 30, 초당 회복 3이다. 필드는 8초 유지되며 1초마다 범위 안의 모든 유효 대상에 기존 기여량·치명타·채집·건설·수리·공격 계산을 적용한다. 영력 부족이나 지나치게 가까운 중복 설치는 거부한다. 수치는 `PrototypeSettings`에서 조정한다.
- 필드는 커서 이동 뒤에도 제자리에 남고 시야를 제공한다. 작업 반경은 기존 커서 반경의 1.8배를 설치 시점에 고정한다. 작업 간격은 현재 강화값을 사용하므로 R8 또는 기존 Pulse 강화가 활동 중인 필드에도 즉시 적용된다.
- 설치 가능한 입력에서는 커서 위치에 반경을 미리 보여 주고, 영력이 부족하거나 물 타일이면 붉게 표시한다. 설치된 필드는 별도 테두리와 영력 HUD로 확인한다.
- R8은 **필드 동조**로 변경되어 필드 작업 간격을 단축한다. 기존 반경·효율·치명타·협동 강화는 필드 작업에 적용된다. Q/W/E 능동 스킬의 커서 지정은 독립적으로 유지한다.
- 판 시작·환생·판 종료 시 필드와 영력을 초기화한다. 정산·환생·일시정지 중에는 필드 수명과 영력 회복이 진행되지 않는다.

## 구현 경계

`Afterlife.DivineFields` 순수 C# 어셈블리는 영력 잔액, 설치, 수명, 주기, 이벤트만 소유한다. `PrototypeDivineFields.cs`는 필드의 펄스를 기존 `ContributeBody`에 연결한다. Unity 뷰는 입력, 필드 테두리, 영력 HUD, 기존 타격 연출을 맡는다. Unity 에디터가 새 스크립트와 어셈블리의 `.meta`를 자동 생성해야 실제 씬에서 사용할 수 있다.

## 검증 상태

새 코어를 기존 순수 C# 프로젝트에, 새 뷰/어댑터를 프로토타입 프로젝트에 임시 포함하여 `dotnet build --no-restore`를 실행했다. 경고 0개, 오류 0개. 생성된 `.csproj`는 원상복구했다. Unity 에디터 실행과 플레이 검증은 프로젝트 규칙에 따라 수행하지 않았다.

Unity에서 직접 확인할 항목: 새 판에서 대상 클릭으로 영력 30 감소와 필드 생성, 커서를 옮긴 뒤 자동 채집·건설·수리·공격, 빈 타일 `Shift+클릭`과 일반 클릭 건설 메뉴, 영력 부족·중복 거부, 8초 만료·회복, R8 구매 전후 주기, 메뉴 일시정지와 환생/새 판 초기화, 영력 HUD·필드 테두리 표시.

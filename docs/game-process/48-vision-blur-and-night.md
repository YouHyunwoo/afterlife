# 48 · 시야 밖 블러와 밤 밝기 분리

## 2026-10-09 · 낮·밤 시야 밖 20% 어두움

### 변경 전후

이전에는 시야가 물체 노출만 결정해 지면에서 안팎을 구별하기 어려웠다. 이제 마을의 상시 시야와 건물·커서·유닛·필드·잔상을 합친 전체 시야 밖에 낮·밤 모두 20% 어두움을 적용한다. 시야 안의 추가 어두움은 0이며, 겹친 시야는 최댓값으로 합쳐 중복 적용하지 않는다. 어두움 정도와 마을 상시 시야 포함은 사용자 선택이다.

### 사용법·설계

- 기존 `PrototypeView` 경로에 자동 적용한다. 씬·프리팹·Inspector 참조나 추가 컴포넌트 설치는 필요 없다.
- `Lighting/Shaders/Vision.hlsl`의 순수 GPU 함수 `ApplyVisionDimming`이 조명이 계산된 RGB에 `lerp(0.8, 1, visibility)`를 곱한다. 상태·Unity 객체·게임 모델 의존성이 없는 기존 Lighting 모듈의 표현 규칙이다. 별도 컴포넌트나 코어 어셈블리를 만들 필요 없이, 다른 셰이더에서도 해당 include와 함수 호출로 재사용한다.
- 프로토타입의 `PrototypeWorldLighting`은 기존 낮밤 색·건물/마을 조명을 계산한 다음 어두움을 곱한다. 조명(G)으로 시야 밝기를 결정하지 않아, 마을 불빛의 1.8칸 감쇠와 시야 경계가 각각 누적된다. 커서는 새 광원을 만들지 않는다.
- 마을 시야(R)는 밝기에만 Linear Clamp 샘플링하여 1/8칸 마스크 경계를 보간한다. 물체 노출용 Point 샘플과 표시 반경은 유지한다. 건물·이동 시야는 기존 0.65칸 감쇠를 사용한다.
- 일반 표면·지면·눈·풀·나뭇잎·물과 해당 식생 출력 경로를 사용하는 연기·먼지에 동일 적용한다. 월드 오버레이와 HUD는 기존 표시를 유지한다. 물체 숨김·물 투명도·마우스 거리 블러는 기존 규칙을 따른다.
- 공용 `SurfaceLighting`도 시야 활성 시 같은 함수를 사용한다. 시야를 끄면 추가 어두움이 해제된다. 밝기 규칙은 새 리소스나 전역 상태를 만들지 않으며 기존 시야 갱신·해제 수명을 따른다.
- 적용 해제는 `PrototypeWorldLighting`의 `ApplyVisionDimming` 호출과 공용 `SurfaceLighting`의 해당 호출을 제거하면 된다. 기존 시야·조명 데이터 연결은 유지된다.

### 검증

- `dotnet build Afterlife.Lighting.csproj --no-restore`는 기존 복원 자산 누락(NETSDK1004)으로 실패했다. Unity 생성 소스/참조를 복사하고 프로젝트 의존성을 기존 `Library/ScriptAssemblies` DLL로 대체한 `Afterlife.Lighting.VisionDimmingValidation.csproj`, `Afterlife.Prototype.VisionDimmingValidation.csproj`에 `dotnet build --no-restore`를 수행했다. Lighting 경고/오류 0, Prototype 기존 직렬화 필드 CS0649 경고 30개·오류 0으로 통과했다. 검증 프로젝트와 출력은 임시·Git 제외 파일이다.
- C# 빌드는 HLSL 컴파일·GPU 결과를 검증하지 않는다. Unity Test Runner와 자동 플레이는 실행하지 않았다. 아래 화면 확인은 사용자 수동 검증 대상이다.

1. 프로토타입에서 낮에 게임을 시작하고 커서를 마을에서 멀리 옮긴다. 커서·집/건물·마을 전체 시야 밖 지면과 물은 조명이 적용된 색의 80%로 표시되어야 한다. 시야 안쪽은 원래 밝기를 유지하고 경계는 부드럽게 이어져야 한다.
2. 밤에 같은 위치를 확인한다. 기존 마을·건물 불빛 감쇠를 유지하면서 전체 시야 밖의 추가 어두움이 함께 적용되어야 한다. 마을 상시 시야 안은 커서가 멀어져도 추가로 어두워지지 않아야 한다.
3. 시야 원들이 겹치게 하고, 마을의 오목한 경계와 떨어진 마을도 확인한다. 겹친 내부에 어두운 이음새나 20% 중복 감쇠가 없어야 한다. 마을 조명 끝과 시야 끝이 각각 자연스럽게 보여야 한다.
4. 건설 모드·UI 위 커서·모달 열기를 확인한다. 현재 커서 시야는 기존 차단 조건을 따르고 잔상은 수명에 따라 어두워져야 한다. HUD·표시 링은 기존 밝기를 유지해야 한다.
5. 집 완공·이전·철거 및 새 판·환생 후 시야 경계가 갱신되는지 확인한다. 줌·회전 시 지면·물·식생이 같은 월드 시야를 따라야 하며 기존 블러도 유지되어야 한다.
6. 공용 시야 표현을 사용하는 장면에서 시야를 켠 채 낮·밤을 비교하고 다시 끈다. 활성 시 시야 밖만 어두워지고, 해제 시 전체가 기존 조명 밝기로 돌아와야 한다.

## 2026-09-29 · 마을 외곽 2칸 시야·빛

### 조명 가장자리 보정

후속 오목 경계 보정: 기존의 원래 타일 거리 기반 감쇠를 전체 확장 영역의 최종 경계 기준으로 교체했다. 반경 2 합집합을 먼저 만든 뒤, 밖까지의 유클리드 거리로 안쪽 1.8칸을 감쇠한다. 오목한 곳에서 확장 영역이 만나는 부분도 하나의 외곽선을 따르며, 오브젝트 표시 범위·건물 조명·마우스 블러는 그대로다. 기존 참조 기반 스크립트에 모듈 선택 인자를 추가해 코어·프로토타입만 `dotnet build --no-restore` 검증했다. 코어 경고/오류 0, 프로토타입 오류 0·기존 CS0649 경고 30개. Unity 자동 플레이는 실행하지 않았으며 ㄱ자·ㄷ자/좁은 틈의 밤 경계는 수동 확인 대상이다.

최초 마을 조명이 시야의 0/1 마스크를 그대로 사용해 밝기 경계가 끊기던 문제를 수정했다. 시야(R)와 조명(G)을 분리하고, 조명은 기존 건물과 같은 바깥 1.8칸 smoothstep 감쇠와 선형 샘플링을 적용한다. 마을 외곽 거리 0.2까지 최대 조도, 1.1에서 절반, 2에서 0이다. 일반 표면·풀·물에 동일 적용하며 기존 건물 조명·시야 반경·마우스 블러는 유지한다. 수동 검증 시 밤의 경계가 점차 어두워지고 내부 타일 이음새가 없는지 확인한다.

- 현재 마을 타일 사각형 외곽에서 XZ 거리 2까지 둥글게 확장하여 상시 오브젝트 표시와 밤 조도를 제공한다. 실제 마을 영역과 건설 가능 범위는 그대로다.
- 기존 건물·유닛·커서·필드 시야와 최댓값으로 합친다. 빛도 기존 건물 조명과 최댓값으로 합치며, 마을 조도는 기존 건물 최대 조도 수준이다. 일반 표면·풀·물에 적용한다.
- **블러는 기존 마우스 위치 기반 동작 그대로다. 마을 안도 마우스에서 멀면 흐려진다.** 블러 코드·셰이더는 이번 작업에서 수정하지 않았다.
- 설치는 기존 PrototypeView를 통해 자동 적용된다. 순수 코어 `Afterlife.TerritoryVision`과 게임 어댑터의 사용법·수명·해제·검증은 [모듈 README](../../impls/unity/Afterlife/Assets/Modules/TerritoryVision/README.md)에 기록했다.
- 검증 명령 `dotnet build Afterlife.Prototype.csproj --no-restore`는 복원 자산 누락(NETSDK1004)으로 컴파일 전에 실패했다. 신규 코어 프로젝트 파일도 Unity 생성 전이다. Unity 자동 테스트는 실행하지 않았다.
- 직접 확인: 밤에 마우스를 마을에서 멀리 이동했을 때 외곽 2칸까지 오브젝트가 **보이고 밝지만 흐려지는지** 확인한다. 마우스를 가까이 가져오면 선명해야 한다. 집 완공·이동·철거와 새 판·환생 후 범위 갱신, 기존 건물 시야·빛 유지도 확인한다.

아래는 이전 구현 기록이며, 마을의 상시 시야·조명은 위 변경이 추가 적용된다.

2026-09-24. Day01에서 확인한 부드러운 블러를 프로토타입에 적용했다.

## 변경 전후

- 이전 커밋의 프로토타입은 시야 계수가 밤의 밝기를 바꾸었다. 이제 물체 표시 여부는 기존 시야 합집합이, 밝기는 낮밤과 건물 조명이 각각 결정한다. 커서는 광원이 아니다.
- 모든 건물은 시야를 제공한다. 집·연구소·병영·시장 같은 건물은 넓은 시야와 그 절반 반경의 조명을 제공하고, 성벽·농장 등은 좁은 시야만 제공한다. 조명은 완성된 건물에서만 켜진다.
- 마우스가 가리킨 지면의 XZ 위치에서 시야 반경 안은 선명하고, 밖부터 반경 3배까지 점차 흐려진다. 그 너머는 최대 블러를 유지한다. 집·유닛·필드의 시야로 보이는 물체도 마우스에서 멀면 흐리다.
- 시야 밖 물체를 숨기는 기존 셰이더 판정은 유지한다. 지형은 밤에도 어두운 색으로 남는다.
- 월드 RawImage에만 적용하므로 HUD·메뉴는 선명하다. 일반 작업·건설 모드 모두 마우스 시야와 블러 초점을 유지한다. UI·모달 등으로 월드 입력이 차단되면 현재 커서 시야와 블러 초점을 함께 끈다. 기존 시야 잔상은 수명에 따라 사라진다.
- `PrototypeSettings.VisionBlur`는 기본 켜짐이며 Inspector에서 비교할 수 있다. 커서 반경 기본값은 4다.

## 소유권과 수명

`Afterlife.VisionBlur`는 카메라·원본 프레임·초점·반경을 주입받는 독립 표현 모듈이다. 게임 모델이나 Day01/UI에 의존하지 않는다. `VisionBlurRenderer`가 머티리얼 두 개와 임시 프레임 두 개를 소유하고, 카메라 렌더 완료 후 연속 텍셀 가우시안 블러를 계산한다. 선형 Clamp 샘플러와 축별 필터 후 축소로 격자를 억제한다. 직교 카메라가 투영한 지면 X/Z 축을 역변환하므로 회전·확대에도 같은 월드 반경을 따른다.

Day01은 `Day01PixelOutput`, 프로토타입은 `PrototypeVisionBlur` 어댑터가 연결한다. 원본은 카메라의 기존 프레임을 재사용한다. 해상도 변경 시 블러 프레임을 교체하고, 비활성화·파괴 시 이벤트 구독과 생성 리소스를 해제한다. 새 판/환생에서 초점을 초기화한다. 모듈은 기존 전역 시야·조명 값에 쓰지 않는다.

## 검증

- 공용 블러 모듈·Day01·프로토타입 C# `dotnet build --no-restore`: 현재 작업 폴더에서 경고·오류 0. 기존 프로젝트 파일의 이동 전 경로는 Temp의 임시 참조/소스 목록으로 보완했다.
- 다른 작업을 제외하고 선별한 커밋 소스도 별도로 컴파일했다. 프로토타입은 경고·오류 0, Day01은 기존 `ShowcaseTarget.cs`의 참조 비교 경고 CS0252 1개·오류 0이다. 이 검증은 이동 전 모듈의 원본 소스를 함께 사용했다.
- Unity Play/Test Runner는 프로젝트 규칙에 따라 실행하지 않는다. 프로토타입의 GPU 화면 검증은 대기 상태다.

직접 확인 절차:

1. 프로토타입에서 게임을 시작하고 마우스를 집에서 멀리 이동한다. 마우스 반경 안은 선명하고, 집 시야로 보이는 먼 물체는 부드럽게 흐려져야 한다. 시야 합집합 밖 물체는 숨겨져야 한다.
2. 밤에 마우스를 이동한다. 커서가 지형을 밝히지 않고 건물 조명만 유지되어야 한다. `VisionBlur`를 껐다 켜도 밤의 밝기 규칙과 물체 숨김은 바뀌지 않아야 한다.
3. 카메라 회전·줌·창 크기 변경 후 마우스 중심과 XZ 반경을 확인한다. UI·모달은 선명하고 화면 전체 암전/격자가 없어야 한다.
4. 집 시야 밖에서 건설 모드로 전환하고 마우스를 이동하거나 왼쪽 버튼을 누른 채 이동한다. 마우스 주변 물체가 계속 보이고 같은 중심·반경 안의 블러가 해제되어야 한다. 작업 모드로 돌아와도 유지되어야 한다.
5. UI 위 이동·모달 열기·앱 포커스 해제 시 현재 커서 시야와 블러 초점이 함께 꺼져야 한다. 월드로 돌아오면 함께 복원되고, 타이틀 복귀 후 새 판에서는 이전 초점이 남지 않아야 한다.

## 2026-09-29 · 건설 모드 커서 시야 일치

- 입력 어댑터의 `UpdatePointer` 두 호출에서 Work 모드 제한을 제거했다. 유효한 월드 위치와 기존 입력 차단 판정으로 시야 활성 여부를 결정하며, 작업 기여 인자는 기존처럼 false다. 별도 설치나 씬 변경 없이 적용된다.
- 블러 어댑터는 `PointerVisible`, `WorkCenter`, `CursorVision`을 사용한다. 건설 모드 전용 우회와 비활성 시 마지막 초점 유지를 제거하여 현재 커서 시야와 활성 조건·중심·반경을 공유한다.
- 건물·유닛·필드·잔상의 시야 합집합과 마우스 거리 기반 블러의 기존 역할은 유지한다. 블러가 전체 시야 합집합을 선명하게 만드는 변경은 아니다.
- Unity Play/Test Runner는 실행하지 않는다. 위 4~5번 화면 확인은 사용자 검증 대상이다.
- 이번 변경의 `dotnet build Afterlife.Prototype.csproj --no-restore`는 `Temp/obj/Afterlife.Prototype/project.assets.json` 누락(NETSDK1004)으로 컴파일 전에 실패했다. Temp 내 기존 검증용 복원 파일도 없어 컴파일 검증은 미완료다.

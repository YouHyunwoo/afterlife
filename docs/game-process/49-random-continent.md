# 49 · 대륙 전체 구도의 시드 기반 생성

2026-09-24. 사용자 요청: GPT-6 Astra의 가벼운 추론 설정으로 계획하고 GPT-6 Sol high로 구현한다. 실행 도구가 제공하는 Astra의 해당 추론 단계 이름은 `low`다.

## 변경 목표와 계획

기존 생성기는 동쪽 바다, 북쪽 눈 지대, 서쪽 호수와 동쪽으로 향하는 강을 고정하고 세부를 시드로 변형했다. 이번에는 대륙의 윤곽과 방향, 바다·바이옴·수계의 배치까지 시드에 따라 달라지게 한다. 같은 반경과 같은 0이 아닌 시드는 같은 결과를 재현한다. `MapSeed=0`의 새 시드 선택은 기존 게임 어댑터가 담당한다.

Astra low가 관련 코드와 소비자를 검토한 구현 계획:

1. 기존 순수 C# Terrain 모듈의 `WorldMapLayout` 안에서 대륙 → 바이옴 → 수계 → 시작 공간 보호 → 해안 → 탐험 목적지와 도로 순서로 생성 단계를 분리한다. `Radius`, `Size`, `Seed`, `Tiles`, `Roads`, `Landmarks` 계약을 유지한다.
2. 회전된 타원 거리와 저주파 노이즈에 시드별 종횡비·중심 오프셋·육지 돌출부·해안 굴곡을 섞는다. 단순 회전만으로 지도를 바꾸지 않으며, 원점의 시작 공간과 충분한 연결 폭을 확보한다.
3. 눈 지대의 기후 방향과 노이즈, 숲·암석 패치의 위치·규모를 시드로 결정한다. 시작점에서 접근 가능한 육지에 주요 자원 바이옴을 확보한다.
4. 호수 후보를 육지 내부에서 고르고 실제 해안까지 강을 연결한다. 시작 공간을 가로지르거나 주요 육지를 단절시키는 수계는 후보 교체·되돌리기 등 유한한 처리로 복구한다. 작은 지도에서는 부가 수계를 줄이거나 생략한다.
5. 시작점에서 이동 가능한 육지와 충분한 폭을 확인한다. 기존 적·상자 생성은 전역 연결성을 검사하지 않으므로, 생성 결과에 고립된 육지를 남기지 않거나 필요한 소비자에 연결성 제한을 연결한다.
6. 전체 연결 육지에서 시작점과 다른 목적지에서 멀리 떨어진 목적지를 최대 4개 선택한다. 물을 회피하는 경로가 확정된 뒤 목적지를 등록한다. 시작 집과 고정 초기 자원의 공간을 보존한다.

지도 시드와 무관한 미세 높이장·풀·장식 패턴은 이번 범위에서 유지한다. 대륙과 바이옴 배열의 변화는 기존 지형·물·자원 뷰에 전달한다. 새 UI·Tools 메뉴·씬 설치는 필요하지 않다.

## 적용한 생성 구조

- 시드별 주축 회전·종횡비·중심 이동, 1~4개의 반도 또는 만, 큰 해안 굴곡과 반경에 맞춘 노이즈로 육지를 만든다. 플레이 불가능한 외곽 한 줄은 물이며, 시작점과 연결되지 않은 육지는 제거한다.
- 눈 지대의 방향을 시드로 정하고 초원 후보에 숲·암석 패치를 배치한다. 수계·도로 생성 후 부족한 자원 바이옴을 도로와 시작 공간 밖의 연결된 육지에서 보충한다. 좁은 지도에서의 보충량은 남은 후보 공간에 제한된다.
- 반경 16 이상에서 호수와 강을 시도하고, 35 이상에서는 두 번째 수계를 시도한다. 호수의 위치·크기·방향·종횡비가 달라진다. 맵 경계 바다와 연결된 수역에서 강 종점을 고른다. 시도마다 육지 연결성과 남는 육지 면적을 확인하고 부적합 결과는 되돌린다. 각 수계는 최대 24회 시도하고 실패하면 생략한다.
- 시작점 중심 11×11 영역은 초원으로 보호한다. 도로도 이 영역의 타일을 흙으로 바꾸지 않으므로 초기 집·나무·바위 자리를 유지한다.
- 연결된 육지의 건조한 후보에서 서로 떨어진 탐험 목적지를 최대 4개 선택한다. 기존 물 회피 경로 탐색을 사용하고 게임에서 이동할 수 없는 외곽은 경로에서 제외한다.
- 변경 코드는 기존 `Afterlife.Terrain` 독립 모듈의 `WorldMapLayout.cs`에 한정한다. `TerrainMap`의 시드 선택·Revision 갱신과 프로토타입의 뷰 재생성 경로를 그대로 사용한다.

## 구현 및 검증 상태

- 계획: Astra low 완료.
- 구현: Sol high 완료. 구현 파일은 `Assets/Afterlife/Modules/Terrain/Runtime/WorldMapLayout.cs` 하나다. 부모 리뷰 후 대륙 변화 범위, 목적지 간격, 외곽 이동 제한, 자원 바이옴 보충 및 강의 실제 바다 연결 판정을 보완했다.
- 변경 전 기본 Terrain 프로젝트 빌드: `NETSDK1004`로 중단. 기존 `Temp/obj/Afterlife.Terrain/project.assets.json`이 없어 프로젝트의 직접 어셈블리 참조를 사용하는 복원 없는 컴파일 방식으로 확인했다.
- 최종 Terrain 독립 재빌드: 경고 0, 오류 0.
- 실제 `PrototypeTerrain.cs`와 Terrain DLL의 소비자 컴파일: 경고 0, 오류 0. Temp 검증 프로젝트에서 `Point`의 X/Z 필드만 임시 대체했으므로 전체 게임 통합 빌드 성공을 의미하지 않는다.
- 전체 `Afterlife.Prototype.csproj` 빌드: 기존 `PrototypeRelicData.cs:5`와 `PrototypeRelicCatalog.cs:7`의 같은 형식 중복 정의 `CS0101`로 실패. 이 작업에서는 해당 파일을 수정하지 않았다.
- Unity 실행·Test Runner·배치모드는 프로젝트 규칙에 따라 수행하지 않는다.

## 사용자 직접 확인 절차

1. 프로토타입 설정 에셋의 `MapSeed`를 서로 다른 0이 아닌 값 5개 이상으로 바꾸고 각각 새 게임을 시작한다. F4 지도 시드와 콘솔의 실제 시드를 확인한다. 대륙 윤곽·바다 방향·눈/숲/암석·호수와 강의 배치가 달라져야 한다.
2. 같은 시드와 같은 반경으로 다시 시작한다. 지형·길·탐험 목적지가 재현되고 이전 지형이 남지 않아야 한다. 생성 알고리즘을 바꿨으므로 변경 전 버전의 같은 시드와는 지도가 달라진다.
3. 반경 8과 기본 45, 더 큰 반경에서 시작 집·초기 나무와 바위·건설 공간을 확인하고 유닛을 탐험 목적지로 보낸다. 주요 육지와 목적지가 고립되지 않아야 한다.
4. 시드 `1`, `-1`, `-2147483648`, `2147483647`을 포함한다. 물 위 도로와 흙/물 위 나무·바위가 없어야 하며, 밤의 적이 물로 분리된 곳에 갇히지 않아야 한다.

컴파일은 알고리즘의 실제 지도 다양성·플레이 가능성·생성 시간의 실측 증거가 아니다. 이 항목은 Unity 직접 확인 대기 상태로 남긴다.

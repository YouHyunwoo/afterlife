# 첫 공개 준비와 새 규칙 밸런싱 절차

> 확정 기획 · 2026-10-03: 채집·건설·수리·공격은 버튼을 누르고 있는 동안 작업 주기에 맞춰 반복하고, 강화는 작업 1회당 효과을 높인다. 자동 수입은 농장 건설·생산 강화로 확장한다. 본편 상호작용 필드·슬롯·충전·호버 자동 작업은 폐기한다. [새 규칙·사용법·검증](71-click-work-and-farm-automation.md). 새 규칙은 게임 코드·에셋에 아직 적용하지 않았다. 이전 규칙·수치·QA는 당시 기록으로 보존한다.

- 상태: 새 규칙에 맞춘 공개 준비·측정 계획. 공개 배포·게임 변경은 수행하지 않음.

## 현재 공개 후보 경험

버튼 유지 작업 채집 → 첫 농장 자동 생산 → 시설/병력 투자 → 밤 방어·직접 수리/공격 → 회당 작업량/생산 강화 → 명확한 승패와 새 판. 10일·25~30분은 목표이며 공개 안내에는 실제 확인한 범위와 시간을 사용한다. 필드 투자·슬롯·환생을 현재 MVP의 핵심으로 홍보하지 않는다.

## 조정 순서

기준 빌드/시드 고정 → 버튼 유지 반복 작업·회당 양/피드백 → 첫 농장 구매/완공/회수 → 첫 병력과 방어 → 회당 작업량/생산 강화·새 보상·풍요 조건 → 1~10일 경제/침공 → 후반 직접 작업 부담 → 초심자 관찰과 수정. 최종 배포 권한과 후보 검증은 별도다.

측정은 첫 누르기·첫 작업·첫 생산·구매·완공·충원·방어·강화 시각, 직접/자동 수입과 지출, 일차별 유효 작업 횟수·버튼 유지 시간·채집 시간·피로감·대기·잔여 적 처리·완주 시간이다. 필드 공급량과 예전 클릭/호버 QA를 새 균형 증거로 재사용하지 않는다.

## 이전 기획·구현 기록

아래는 규칙 변경 전 기록이다. 날짜와 당시 검증 결과를 보존하며 새 규칙의 완료 증거로 사용하지 않는다.

> 2026-09-28 갱신: 사용자가 환생 없는 6일 MVP와 슬롯·자동 스킬 개편을 채택했다. 아래 환생 포함 시간·절차는 초기 제안 이력이다. 현재 구현과 검증은 [63 MVP 슬롯·자동 스킬](63-mvp-slots-and-auto-skills.md)을 따른다.

2026-09-26. 사용자 목적: itch.io에 플레이 가능한 버전을 올려 반응을 확인한다. 이 문서는 추천 초안이며 공개 형태·시간·수치의 채택이나 배포 승인을 뜻하지 않는다. 게임 구현과 설정은 변경하지 않았다.

## 공개 형태

무료 공개 플레이테스트용 프로토타입을 추천한다. 설명 예시: “Afterlife — 개발 중인 마을 성장·방어 게임의 무료 플레이테스트. 영력 투자와 환생 선택에 대한 의견을 받고 있습니다.” 예상 시간은 실제 측정 후 표기한다.

프로토타입은 재미·규칙의 검증 목적, 데모는 완성작을 대표하는 체험 목적, MVP는 핵심 가치를 전달하는 최소 제작 범위다. 서로 배타적인 배포 형식은 아니다. 이번에는 내부적으로 작은 MVP 범위를 정하고 외부에는 개발 중인 플레이테스트로 안내한다. 향후 핵심 재미와 품질이 확인되면 데모로 다듬는다.

최소 체험 범위: 실행 → 조작 이해 → 영력 필드 투자 → 채집·건설 → 첫 방어 → 강화 선택 → 환생 검토 또는 계속 도전 → 명확한 승패 → 재시작. 신규 콘텐츠 확대보다 이 흐름을 타인의 설명 없이 경험할 수 있는지가 우선이다.

## 시간 예산

아래 수치는 업계 표준이나 측정 결과가 아닌 이 게임의 첫 실험 가설이다.

| 기준 | 목표 |
|---|---|
| 조작 시작 후 첫 필드 효과 이해 | 30~60초 |
| 첫 건설·투자 결정 | 1~2분 이내 |
| 첫 방어 결과 | 2~3분 이내 |
| 환생을 이해하고 선택할 기회 | 4~6분 전후 |
| 환생 없이 6일 진행하여 승리 | 8~12분 |
| 환생 1회 후 최종 결과까지 한 판 체험 | 15~20분 |

현재 System 에셋의 낮 35초 + 황혼 5초 + 밤 35초를 6일 합치면 타이머 합계는 450초(7분 30초)다. 실제 시간에는 초기 안내, 정산·강화 선택, 밤의 잔여 적 처치가 더해진다. 환생하면 같은 판 안에서 첫날부터 진행하므로 구간 시간과 판 전체 시간을 구분한다. 패배한 판은 더 짧을 수 있고 반복 환생에는 총 시간 상한이 없다. 15~20분은 강제 종료 제한이 아니다.

기본 타이머를 일괄 늘려 목표 시간을 맞추지 않는다. 아무 결정도 없는 대기 시간을 별도 기록하고 줄인다. 기존 6일 구성을 먼저 측정한 뒤 부족한 준비 구간만 조정한다.

## 밸런싱 순서

| 순서 | 작업과 조정 위치 | 다음 단계로 넘어가기 위한 관찰 |
|---|---|---|
| 1. 기준 고정 | 버전, 설정 사본, 고정 지도 시드, 초기 해금·환생 상태, 6일 승리 조건, 시간 기록 방식 고정 | 동일 조건으로 비교 가능. 실행·조작·종료 장애는 먼저 수정 |
| 2. 영력과 필드 | System의 최대 영력·비용·회복·지속·기여 주기·채집량, 필드 반경 | 플레이어가 필드 위치·채집/방어 투자 차이를 이해. 영력 부족으로 아무것도 못 하는 구간 확인 |
| 3. 초반 경제 | Resources 판매 단가·자원 배치, 건물 가격·공사 시간, 모집 비용 | 첫 집·병영 또는 타워의 구매/완성 시점. 수리비 때문에 회복 불가능한 빈곤 순환이 없는지 |
| 4. 첫날 전투 기준 | Units, 타워 성능, Waves 첫날 수·간격, System 낮 길이 | 초심자가 한 가지 합리적인 방어로 첫밤을 넘길 기회가 있고, 실패 이유를 이해 |
| 5. 성장 선택 | Research/Altar 비용·효과·선행, Skills 쿨다운, 주민 효과 | 경제/병력/타워 투자에 서로 다른 이점. 한 선택이 항상 모든 면에서 우월하지 않은지 |
| 6. 일차별 난이도 | Waves의 구성·방향·수·성장, 각 일차 준비 시간 | 2~6일차마다 새 대응 과제가 있고 중간 난이도 절벽·막판 청소 지연이 없는지 |
| 7. 환생 | Rebirth 보상·비용·효과, 제단 가격·접근 시점 | 첫 환생에서 실제 강화 구매 가능. 같은 구간 재돌파가 체감상 빨라지고 계속 도전도 유효 |
| 8. 변동성과 악용 | Chests/Relics/Loot 보상, 지도 시드, 자원 밀집·범위·작업 주기 조합 | 평범한 운으로 진행 가능. 행운이 결과를 독점하거나 무한 환생 파밍만 유리하지 않은지 |
| 9. 사람 검증·재조정 | 초심자 3~5명으로 첫 관찰, 문제 수정 후 새 참가자에게 비교 | 조작 막힘·지루한 시점·환생 이해·자발적 재시도 확인. 소표본을 모집단 성공률로 해석하지 않음 |

## 계산 시 주의점

- 최신 주 조작은 영력 필드다. 이전 조사에서 언급한 수동 클릭 간격은 공개 버전의 핵심 조정 대상으로 삼지 않는다. `PrototypeDivineFields.cs`의 현재 필드 반경은 Radius × 1.8이다.
- 최대 영력 100, 비용 30, 회복 3/초, 수명 8초: 초기에는 3개를 연달아 설치할 수 있으나 소진 후 공급은 평균 10초당 1개다. 지속 공급만 보면 평균 활성 필드 수는 약 0.8개다. 실제 효과는 대상 수·이동·작업 종료와 설치 타이밍에 따라 달라진다.
- 필드는 범위 안 여러 대상을 처리한다. 자원 밀집도와 반경을 고정하지 않은 상태에서 골드/초를 단일 숫자로 확정하지 않는다. 한 필드당 실제 획득 골드와 작업 대상 수를 함께 기록한다.
- 침공 체력은 기본 체력 × [1 + HealthGrowth × (일차−1)²], 피해는 기본 피해 × [1 + DamageGrowth × (일차−1)]. 현재 6일차는 각각 4배·1.9배다. 적 수 증가와 함께 난이도를 만든다.
- 연구 단계 Value는 해당 단계의 값을 사용한다. 단계별 값을 전부 누적하는 것으로 계산하지 않는다.
- 환생 보상은 클리어 일차별 2w²의 합과 제한된 보너스다. 현 기본값에서는 1일 클리어 기본 2, 2일 누적 10이며 기억 강화 첫 비용은 8이다. 첫 환생 안내는 강화 구매가 가능한 시점과 맞춰야 한다.
- 환생은 같은 판 내부 진행이다. 최종 패배/승리 뒤 새 판으로 기억 강화가 유지된다고 안내하지 않는다.

## 측정과 피드백

세션별로 버전·시드·플레이 경험, 첫 필드/건설/방어/강화/환생 시각, 일차별 골드·병력·집 체력, 패배 원인, 최종 종료 시각, 자발적 재시작 여부를 기록한다. 실제 경과 시간과 일시정지·메뉴 시간을 구분한다. 처음에는 관찰표와 동의받은 녹화로도 충분하며 온라인 분석 도구 설치가 선행 조건은 아니다.

첫 플레이 중 해답을 계속 알려 주지 않는다. 종료 후 “가장 재미있었던 순간”, “막히거나 지루했던 순간”, “다시 하면 무엇을 바꾸고 싶은지”를 묻는다. 튜토리얼/입력 오류와 실제 경제·전투 난이도 문제를 분리한다. 한 번의 수정에서는 한 가설에 관련된 수치를 묶고 변경 전후를 기록한다.

공개 전 제한 공유로 실행·이해·완주 흐름을 확인한다. 공개 페이지에는 실제 게임 화면, 현재 제공 범위, 조작, 측정한 예상 시간, 피드백 경로를 준비한다. 다운로드가 적으면 유입 부족과 게임 반응을 분리한다. 방문 → 다운로드/실행 → 첫 방어 → 종료/재시도의 각 구간을 구별해야 한다. 실제 공개 준비에서는 기존 `docs/audio-credits.md`도 확인한다.

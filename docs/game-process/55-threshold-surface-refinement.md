## 결과 화면 제안과 설정

기본값은 `ThresholdProfile.ResultBackdrop = KeepWorld`다. 자신이 지킨 마을 또는 실패한 현장을 보면서 결과를 읽는 편이 건설·생존 게임의 인과관계를 잘 전달한다. 배경 중심은 어둡게 낮추고 외곽은 거의 검정으로 덮으며 결과 글자는 선명하게 유지한다.

`Blackout`으로 바꾸면 가장자리부터 완전히 어두워지는 안을 비교할 수 있다. 시험 결과는 현장 위에서, 실제 몸으로 귀환하는 서사적 순간은 전체 암전으로 구분하는 방향을 추천한다. 귀환 서사 자체는 이번 구현 범위가 아니다.

`ResultTransitionSeconds` 기본 0.8초, `CameraTravelSeconds` 0.95초다. 카메라 이동 설정은 런타임에도 1초 이하로 제한한다. 움직임 줄이기 옵션은 기존처럼 별도 감쇠를 적용한다.

## 재사용 경계

- `ThresholdSession`은 순수 상태/경로와 결과 배경 상태만 결정한다.
- `ThresholdPresentationSystem`은 등록된 페이지·카메라 포즈를 처리한다. 결과는 Playing 카메라 포즈를 재사용한다.
- `ThresholdVeil`은 결과·모달·전환 어둠을 처리한다. 월드 캡처 뒤에 UI를 그린다.
- `ThresholdPuddleSurface`는 물과 반사 렌더러에 동일한 로컬 좌표계를 전달한다. 프리팹을 이동해도 마스크가 일치하며 비활성화 시 이전 프로퍼티 블록을 복원한다.
- `ThresholdPuddle.cginc`는 파문과 반사의 공통 경계다. 셰이더의 매끈한 내부 영상과 외곽 잉크 마스크를 분리한다.
- `ThresholdPortal`의 SourceCamera 교체로 다른 실제 마을을 연결할 수 있다. RenderTexture는 창 비율을 따르며 해제 시 원래 카메라 타깃과 재질을 복원한다.
- Day01 원본은 수정하지 않는다. 샘플에 중첩한 저장 아트의 MonoBehaviour는 비활성화해 촬영·게임 로직을 실행하지 않는다. Day01 전체 런타임 쇼케이스 효과를 이식한 것은 아니다.
- 실제 게임 연결 시 `TrialStopped`에서 시뮬레이션을 멈추더라도 결과가 끝나기 전 월드 렌더러를 제거하지 않아야 한다.

## 에셋 작성과 검증

기존 씬과 프리팹 GUID를 유지하고 열린 에디터에서 `ThresholdLabRefinement`로 샘플 프리팹만 갱신한다. 새로 설치할 때도 같은 구성을 적용한다. `.meta`는 Unity가 생성한다.

C# 검증 명령: `& impls/unity/Afterlife/Tools/Threshold/Build-Threshold.ps1`. 관련 4개 어셈블리를 `dotnet build --no-restore`로 빌드한다. Unity Play Mode/Test Runner는 프로젝트 규칙에 따라 실행하지 않는다. 실제 렌더링 품질은 사용자 확인 대기다.

직접 확인 절차:

1. `Assets/Samples/ThresholdLab/Scenes/Afterlife_ThresholdLab.unity`를 열어 재생한다.
2. 타이틀에서 약 10초 관찰한다. 파문이 불규칙한 웅덩이 밖으로 이어지지 않고 밝은 부분만 남아야 한다.
3. 새 게임 → 타이틀 귀환을 반복한다. 왕복 각각 0.95초 안에 가속·감속하며 같은 경로를 되짚어야 한다.
4. 로비 창에는 Day01 After 저장 아트가 보이고 내부 조각선 없이 외곽만 찢어지고 번져야 한다. 마을은 창 밖에 나오지 않아야 한다.
5. 시험 진입 후 실패/클리어를 선택한다. 카메라가 바뀌지 않고 가장자리 어둠 뒤에 결과가 나와야 한다.
6. 재생을 중지하고 Profile의 ResultBackdrop을 Blackout으로 바꿔 비교한다. 기본 추천은 KeepWorld다.

열린 Unity 에디터에서 `refine-surfaces` 요청 처리가 완료되어 프리팹·Profile 저장을 확인했다. 관련 4개 C# 어셈블리 빌드 오류 0·경고 0. 사용자가 실행 중이던 Play Mode는 사용자가 직접 중지했으며 에이전트는 플레이·테스트를 실행하지 않았다.

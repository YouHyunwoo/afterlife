# 타이틀 가시성·카메라 수정과 인트로

> 후속 [57 입력 대기 대화](57-threshold-dialogue-input.md)에서 자동 진행을 클릭/Enter로 대체했다. Esc 스킵과 사각형 진행도가 최신 기준이다.

2026-09-26. 이번 범위는 ThresholdLab의 웅덩이·파문, 화면 출력 카메라, 로비를 대체하는 인트로다. 조작 튜토리얼이나 실제 게임 연결은 추가하지 않는다.

## 변경 전후

- 모든 월드 카메라가 RenderTexture로만 출력해 Game 뷰에 직접 출력하는 카메라가 없었다. `DisplayCamera`를 프리팹에 추가했다. 이 카메라는 월드 오브젝트를 중복 렌더링하지 않고 디스플레이 0의 배경을 출력하며, Overlay Canvas가 월드 캡처와 UI를 표시한다. AudioListener는 기존 카메라 하나만 유지한다.
- 파문은 매우 얇은 선에 0.82 임계값을 적용해 대부분 제거됐다. 파문의 폭을 화면 미분(fwidth)으로 보정하고 파문에는 별도 밝기를 사용한다. 일반 반사의 높은 임계값과 불규칙한 웅덩이 클리핑은 유지한다. 웅덩이 가장자리 일부에 희미한 반사와 타이틀 카메라 구도 보정을 더했다.
- `Lobby` 상태와 기존 프리팹 GUID는 직렬화 호환성을 위해 유지하되 사용자에게는 인트로로 표시한다. 시험 시작 버튼과 로비 정보 패널은 없애고 대리자 이름·자막·건너뛰기를 배치한다.

## 인트로 흐름

타이틀 → 0.95초 공간 이동 → 대리자 자막 5문장(기본 26초) → 균열로 가속 진입 → 짧은 완전 암전 → 중앙부터 가장자리로 어둠이 걷히며 빈 인게임 표시.

인트로에서 `건너뛰기`는 자막을 종료하고 동일한 진입 연출을 보여준다. 마지막 문장이 끝나도 같은 경로로 자동 이동한다. 설정 모달을 열면 자막 시간과 연결된 음성을 일시 정지한다. 인트로를 다시 방문하면 처음부터 재생하고 결과 화면의 다시 도전은 바로 인게임으로 간다.

균열 진입은 1.8초 전환의 전반부에 카메라를 `PortalEntry`로 가속시킨다. 가까워진 후 34~43% 구간에서 암전하고 48%에서 인게임 포즈로 교체한다. 53%부터 어둠을 걷는다. 움직임 줄이기 옵션에서는 급격한 카메라 진입을 생략한다. 게임 시작 이벤트는 전환 완료 시 발생한다.

## 대사와 설정

1. 눈을 떴구나. 두려워 말거라. 네 몸은 아직 저편에서 잠들어 있다.
2. 나는 신의 뜻을 전하는 자. 너는 태어나던 날, 영웅의 시험을 치를 후보로 뽑혔다.
3. 저 틈 너머는 네가 살던 세계다. 저 마을은 밤마다 마물의 습격을 받고 있지.
4. 네게 잠시 영력을 빌려주겠다. 마을을 일으키고, 다가올 밤들을 견디게 하거라.
5. 시험을 마치면, 돌아갈 길이 열릴 것이다.

신의 대리자가 무작위로 후보를 선발한다는 최신 사용자 설정을 따른다. 기존 출생 시 운명 설정과 연결해 태어날 때 후보를 뽑는 것으로 구성했다. 시험 마을은 실제 세계에 있다. 정확한 생존 일수와 조작 설명은 이번 범위에 넣지 않는다.

현재는 **자막 인트로이며 음성 녹음은 포함하지 않는다**. `LobbyPage`의 `ThresholdIntro`에서 Lines/Durations를 조정하고 `VoiceClips`에 문장별 녹음을 연결할 수 있다. 연결된 음성이 더 길면 자막 표시 시간이 자동 연장된다. 음성 시작/정지/모달 일시 정지를 처리한다.

## 모듈과 프리팹

`ThresholdIntroTimeline`은 Unity 비의존 시간/문장 진행 로직이다. `ThresholdIntro`는 자막·선택적 음성·Host 전환을 연결한다. `ThresholdPresentationSystem`이 주입된 `PortalEntry`를 기준으로 진입 카메라를 처리하며 `ThresholdVeil`이 암전과 복귀를 처리한다. 공용 모듈은 Day01 코드에 의존하지 않는다.

에디터의 명시적 `create-intro` 요청은 기존 프리팹에 구성을 저장한다. 기존 씬을 덮어쓰거나 Play Mode를 실행하지 않는다. 새 샘플 설치에도 같은 구성을 적용한다. 신규 .meta는 Unity 에디터가 생성한다.

## 검증과 직접 확인

관련 4개 어셈블리를 `Tools/Threshold/Build-Threshold.ps1`의 `dotnet build --no-restore`로 빌드: 오류 0·경고 0. 프로젝트 지침에 따라 Unity Play Mode/Test Runner는 실행하지 않았다. 시각적 완성도와 입력 검증은 사용자 확인 대기다.

1. `Afterlife_ThresholdLab.unity`에서 재생한다. Game 뷰의 `No cameras rendering` 문구가 없어야 한다.
2. 타이틀에서 8~10초 관찰한다. 동심원이 보이고 불규칙한 웅덩이 경계에서 잘려야 한다.
3. 새 게임을 누른다. 자막 5문장 후 자동 진입해야 한다. 별도의 시험 시작 버튼은 없어야 한다.
4. 인트로 다시 보기에서 건너뛰기를 누른다. 자막은 종료되지만 균열 진입·암전·중앙부터 열리는 전환은 보여야 한다.
5. 인트로 중 ESC로 모달을 열었다 닫는다. 설명이 대기했다 이어져야 한다.


에셋 작성 결과: 열린 Unity 에디터의 `create-intro` 처리 보고가 SAVED로 완료됐다. DisplayCamera·PortalEntry·자막·SkipIntro 직렬화와 신규 Unity 생성 메타데이터를 확인했다. 첫 작성 시 AudioSource의 Unity null 처리 문제를 수정한 뒤 재실행해 저장했다.

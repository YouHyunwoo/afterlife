# 빛을 반사하는 파문과 변형되는 균열 표면

2026-09-26. 기존 흰 선 파문과 무작위 테두리 발광을 실제 메쉬 변위·법선·씬 조명 기반 반사로 교체한다. ThresholdLab만 대상으로 하며 기존 프로토타입과 Day01 원본은 수정하지 않는다.

## 구현

- 웅덩이: 128×192 분할 메쉬를 에셋으로 저장했다. 3.2초마다 무작위 내부 위치에서 최대 반경 2.2의 높이 파동이 퍼진다. GPU에서 꼭짓점 높이를 움직이고 같은 높이 함수의 미분으로 픽셀 법선을 계산한다. 흰 선이나 발광색을 직접 그리지 않는다.
- 균열: VillageGlass에 96×128 분할 메쉬를 연결했다. 외곽 주변 높이를 변화시키고 높이 함수에서 표면 법선을 구한다. 외곽 클리핑과 잉크 모양, 안쪽으로 복원되는 짙은 암부, 중앙 마을 영상은 유지한다. 무작위 위치·시간 기반 흰빛 펄스는 제거했다.
- 조명: 표준 URP 메인/추가 광원의 방향·색·거리 감쇠를 읽어 스페큘러를 계산한다. 검은 표면에는 확산색·자체 발광을 더하지 않는다. 샘플 프리팹에 흰색 Point Light 두 개를 연결했다. Day01 프리뷰 레이어 30은 제외한다.
- 재사용: 표면 메쉬는 `Samples/ThresholdLab/Meshes` 에셋이다. 에디터 작성 도구는 기존 프리팹 GUID와 Surface 참조를 유지한다. 셰이더 공용 광원 계산은 `ThresholdSpecular.hlsl`, 균열 높이·윤곽 함수는 `ThresholdPortalShape.hlsl`로 분리했다. GPU 변위 범위를 포함하도록 메쉬 bounds를 넓혔다.

## 표현의 차이와 조정

빛 반사로 표현하므로 원 전체가 항상 하얀 실선으로 보이지 않는다. 광원·카메라·표면 방향이 맞는 일부 호와 면만 밝아지는 것이 의도다. 실제 유체 물리나 레이트레이싱 반사를 구현한 것은 아니다. 수식으로 만든 높이 파동과 URP 직접광 스페큘러다. 새로운 표면의 그림자 패스나 자체 그림자는 이번 범위가 아니다.

`Pool` 재질의 WaveHeight(기본 0.035), WaveWidth(0.12), Specular power(96)로 수면 변위와 반사 날카로움을 조정한다. `Portal`의 Specular power는 72다. 더 촘촘한 물리 표면을 표현하기 위해 파동 높이의 폭과 화면에서 보이는 반사선 두께를 구분한다. 640×320 최종 출력은 유지하며 실제 반사 가시성은 사용자 화면에서 조정해야 한다.

프리팹의 `PuddleReflectionLight`, `PortalReflectionLight`를 이동하거나 강도를 낮추면 하이라이트도 달라진다. 랜덤 발광처럼 조명과 무관하게 켜지지 않는다. 현재 씬의 다른 광원 역시 영향을 줄 수 있으므로 두 조명을 끄는 것만으로 모든 반사가 사라진다고 보장하지 않는다.

## 검증

관련 C# 4개 어셈블리 `dotnet build --no-restore`: 오류 0·경고 0. Unity의 에셋 임포트/프리팹 작성은 실행하지만 프로젝트 지침에 따라 Play Mode·Test Runner·실행 시각 검증은 하지 않는다. C# 빌드가 셰이더 렌더링 성공을 검증하는 것은 아니다.

사용자 확인 절차:

1. 테스트 씬에서 타이틀을 15초 이상 관찰한다. 파문이 흰 도형 대신 빛을 받는 굴곡으로 보여야 한다.
2. 새 게임 후 첫 대사에서 대기한다. 균열의 검은 외곽이 입체적으로 움직이고 마을 내부는 유지되어야 한다. 랜덤 흰빛 펄스가 없어야 한다.
3. 실행 중 프리팹 인스턴스의 두 Point Light 위치·강도를 바꿔 반사 위치와 밝기가 따라가는지 확인한다. 재생 종료 후 실험값은 원복된다.
4. 움직임 줄이기 옵션에서 균열 표면이 정지하는지 확인한다. 물의 파문은 기존과 같이 별도 시간 흐름을 사용한다.

## 사용자 화면 오류 수정 · 분홍색 웅덩이

사용자가 제공한 화면과 Unity Editor.log에서 Pool 셰이더의 `unexpected token point` 컴파일 오류를 확인했다. HLSL 예약어 `point`를 보간 데이터 필드 이름으로 사용한 것이 원인이다. 해당 필드와 참조를 `puddlePosition`으로 바꿨다. 물결 수치나 조명 설정은 변경하지 않았다. 에셋 새로고침을 요청했으며 Unity 플레이·Test Runner는 실행하지 않았다. C# 변경은 없고 기존 C# 빌드 통과를 셰이더 검증으로 간주하지 않는다.

재생을 중지한 뒤 에디터 임포트가 끝나면 테스트 씬을 다시 재생해 분홍색 면이 없어지고 조명 기반 수면이 표시되는지 확인한다.

## 후속 · 평면 반사 억제와 진입 중 겹침

월드 Y축과 표면 법선의 차이로 수면 반사를 마스킹했다. 평평한 면은 검정이고 기울기가 생긴 파동 부분에서만 반사가 부드럽게 나타난다. 균열 외곽 스페큘러는 기존의 18%로 낮췄다. 조명과 메쉬 변형 자체는 유지한다.

진입 전환에 사용하던 9탭 블러는 640×320 텍스처에서 멀리 떨어진 샘플들을 겹쳐 균열이 여러 장처럼 보일 수 있었다. 균열 접근 구간에서는 블러를 0으로 두고, 암전 후 인게임이 나타날 때만 흐림이 풀리게 했다. 공통 블러도 인접 5×5 텍셀의 이항 가중치 필터로 바꿔 멀리 떨어진 복제상이 생기는 원인을 제거했다. UI에는 블러를 적용하지 않는다.

관련 C# 빌드 오류·경고 0. Unity 실제 플레이는 프로젝트 규칙상 미실행. 타이틀에서 평평한 수면 반사가 없어졌는지, 인트로에서 외곽이 덜 밝은지, Enter/Esc로 진입할 때 균열이 겹쳐 보이지 않는지 확인한다. 실제 화면에서 다른 원인의 겹침이 남는지는 재확인이 필요하다.

## 후속 · 균열 바로 앞에서 암전

코드 확인 결과 기존 접근 끝점은 균열 기준면에서 0.16 거리였고, 이동은 전환 40%에 끝나지만 완전 암전은 43%였다. 변형 표면과 near clip을 고려한 여유가 부족해 가까이서 표면이 잘리거나 넘어간 것처럼 보일 수 있었다. 실제 플레이로 관찰한 원인은 아니다.

접근 끝점은 진입한 쪽 기준으로 최소 0.5 거리로 제한했다. 메쉬 Z 스케일·최대 변위·카메라 near clip도 반영한다. 접근 완료와 암전 시작은 공통 PortalArrival(38%)을 사용하며 그 시점에 즉시 완전 검정으로 전환한다. 카메라는 표면 앞에 머물다가 48%에서 암전 속 인게임 포즈로 바뀌며 53%부터 기존처럼 중앙에서 어둠이 걷힌다.

관련 C# 4개 어셈블리 빌드 오류·경고 0. Unity 플레이 검증 미실행. 인트로 마지막 입력 또는 Esc로 진입해 표면 앞에서 즉시 암전하고, 균열 뒷면이나 near clip 잘림이 노출되지 않는지 확인한다.

## 후속 · 균열 중앙 구멍 수정

사용자의 Scene 뷰에서 중앙에 배경색이 드러나는 다각형 구멍을 확인했다. 재질 GUID를 대조해 Portal과 Pool이 다른 셰이더를 사용하는 것을 확인했다. 공통 include의 웅덩이 클리핑은 Portal의 바닥 반사 분기에만 적용되므로 VillageGlass 본체의 중앙 구멍을 의도한 코드가 아니다.

PortalShape의 중앙 atan2(0,0)와 음수가 될 수 있는 값에 대한 pow(x,2)가 비정상 수치를 만들 수 있었다. 각도 계산 전에 중앙 입력을 유효한 방향으로 바꾸고, 제곱은 x*x로 변경했다. 높이 계산은 중심 반경 0.35 내부에서 정확히 0을 반환하며 0.35~0.5 구간에서 부드럽게 외곽 변형에 연결한다. 내부 영상·색·외곽 반사는 유지한다. 이는 NaN으로 인한 중앙 꼭짓점/주변 삼각형 손실 경로를 제거하는 수정이며 실제 렌더링으로 원인 확정을 한 것은 아니다.

셰이더 변경만 수행했다. 에디터 에셋 새로고침을 요청했고 Play Mode/Test Runner는 실행하지 않았다. Scene 뷰에서 중앙에 회색 배경이 새지 않는지, 재생 후 마을 영상 중앙이 끊김 없이 보이는지 확인한다. 편집 모드의 넓은 검정 영역은 런타임에 연결되는 마을 RenderTexture가 아직 없는 상태와 구분해야 한다.

## 후속 · 균열 조명 반사 제거

사용자가 중앙 구멍이 사라졌음을 확인했다. 이후 요청에 따라 Portal 셰이더의 스페큘러 조명 계산을 제거했다. 외곽 메쉬 변형·잉크 마스크·어두운 가장자리·내부 마을 영상은 유지한다. 웅덩이 반사 셰이더는 유지한다. 샘플 작성 도구에서는 PortalReflectionLight를 비활성화한다. 다른 조명이 있더라도 Portal 표면 자체는 더 이상 조명 반사를 출력하지 않는다. 실제 변경 화면은 사용자 확인 대기다.

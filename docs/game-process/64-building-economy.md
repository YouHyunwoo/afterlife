## 2026-10-03 확정 설계와 기존 구현의 차이

농장 자동 골드 생산을 본편 자동화의 중심으로 삼고 생산량/주기 강화를 추가할 방향을 채택했다. 현재 아래 기본3초·회당1G·인접/비옥 보너스는 기존 구현값이며 새 강화 수치와 가격은 미정이다. 첫 농장은 강화 없이도 생산하고 강화 구매 경로는 기존 제단/성소 에테론 접근을 기본 연결 후보로 둔다.

건설·수리·공격은 대상에서 버튼 유지 중 주기별 작업으로 전환할 계획이다. 기존 자동 공사·마을 건설 배율·군사 무료 충원/골드 가속·합체·시야·주민 제거 규칙은 유지한다. 농장 생산은 다른 버튼 유지 작업 중에도 진행하며 기존 정지/파괴/이전 수명 정책을 따른다. 후반 기본 운영이 농장 수입으로 가능한지는 가격·회수 시간·필요 작업 횟수·유지 시간와 함께 새로 검증한다.

## 채택 규칙

주택은 영역 밖에도 지을 수 있으며 다른 건물은 부지 전체가 마을 안에 있어야 한다. 완공 주택 중심 반경 2, 회관 중심 반경 4 Unity 유닛 이내에 중심점이 있는 타일이 영역이다. XZ 평면에서 `거리² ≤ 반경²`로 경계를 포함하며, 건물 크기를 반경에 더하지 않는다. 실제 포함 타일이 겹치거나 상하좌우로 이어지면 하나의 마을이다. 대각선 접촉은 연결하지 않는다. 마을 내부 건설 속도는 기본 속도에 `1 + 주택×0.1 + 회관×0.6`을 곱한다. 기존 건설 강화와 중첩하며 영역 밖 공사는 기본 속도로 진행한다. 마을 분리 시 다시 계산한다.

주민/인구 상한은 제거한다. 주택 4채 2×2가 완공되면 회관, 제단 4개면 성소가 된다. 합체는 이전 중 건물을 제외하고 현재·최대 체력을 합산한다. 성소는 재료 제단의 평균 생산 진행률을 이어받는다. 회관도 주거 건물로 취급한다.

| 건물 | 주기/정원 | 현재 회차 1초 가속 |
|---|---|---|
| 농장 | 3초마다 보리 1개=1원 | 없음 |
| 병영 | 전사 3명, 10초 | 5원 |
| 궁수 훈련장 | 궁수 3명, 10초 | 5원 |
| 기사단 본부 | 기사 3명, 18초 | 5원 |
| 마법사 탑 | 마법사 3명, 15초 | 5원 |
| 제단 | 30초마다 에테론 1개 | 50원 |
| 성소 | 20초마다 에테론 4개 | 40원 |

생산은 완공 후 시작한다. 군사 건물은 자신의 생존 병력만 집계하며 정원 충족 시 정지하고 결원 발생 시 새 주기를 시작한다. 건물이 파괴되어도 생존 병력은 남는다. 가속은 다음 주기에 이월하지 않고 자금 부족·정원 충족·정지 상태에서 비용을 청구하지 않는다.

농장은 통행을 막지 않으며 공격·선택·점유 대상은 유지한다. 상하좌우 완공 농장마다 생산 속도 +25%, 최대 +100%다. 비옥한 땅에서는 회당 2원을 얻는다. 영맥에서는 제단 회당 2에테론, 성소 전체 부지가 영맥 안이면 8에테론이다.

지도 시드로 고정된 비옥한 땅과 영맥을 종류별 2개, 3×3 크기, 시작점에서 최소 8칸 떨어진 연결된 육지에 배치한다. 물·다른 지대와 겹치지 않는다. 공간이 부족한 소형 지도에는 가능한 수만 배치한다.

연구소는 건설 목록에서 제거하고 강화 접근을 제단/성소로 통합한다. 기존 트리 노드/선행 관계/참조를 보존하며 비용은 기존 골드÷30 올림으로 한 번만 이전한다. 주민 강화는 직접 작업 범위·효율 강화로 바꾼다. 에테론은 돈 아래 표시하며 제단 버튼은 처음부터 잠겨 있고 제단/성소 완공 시 활성화한다. 건물 소실 후에도 잔고와 구매 효과는 남고 버튼만 잠긴다. 새 게임은 잔고를 초기화한다.

## Inspector 편집과 적용

- 건물: `Assets/_AfterlifePrototype/Resources/Data/Buildings/*.asset`의 `Stats`. 프리팹에 수치를 저장하지 않는다.
- 주택/회관: 영역 반경·시야 반경·건설 속도 기여량을 편집한다. 두 반경은 소수 입력 가능한 Unity 월드 단위이며 서로 독립적이다. 0 이하이면 해당 기능이 비활성화된다.
- 생산: 생산 종류, 주기, 수량, 소속 병종/정원, 가속 가격을 편집한다. 합체 대상과 2×2 점유 깊이도 건물 SO로 전달한다.
- 지도: `SettingsData/World.asset`의 Economic sites 그룹에서 지대 수·크기·최소 거리를 설정한다.
- 강화: `ProgressionData/MvpResearch.asset`(본편)의 비용은 에테론 개수다. 기존 Research/Altar 소비자도 해당 트리 SO를 사용한다.
- 변경은 다음 플레이 시작에 스냅샷으로 복사한다. 원본 SO에는 잔고·타이머·체력·강화 레벨을 기록하지 않는다.
- 설치는 명시적 에디터 API `PrototypeBuildingEconomySetup.Apply()` 및 `ConnectHud()`로 수행한다. 새로운 Tools 메뉴·자동 import 마이그레이션은 추가하지 않는다. 본편 씬이 저장된 상태여야 HUD를 연결한다.

| Inspector 필드 | 사용 방법 |
|---|---|
| `Stats.VisionRadius` | 모든 건물의 중심 기준 원형 시야 반경. Unity 월드 단위, 소수 허용, 0은 시야 없음 |
| `Stats.LightRadius` | 광원 기준 3D Unity 월드 반경. 시야와 독립적으로 밤의 주변 밝기를 조절. 0 이하이면 조명 없음 |
| `Stats.TerritoryRadius` | 주택·회관 중심 기준 원형 영역 반경. 기본 2/4 Unity 유닛, 타일 중심이 반경 이내이면 포함, 0은 영역 없음 |
| `Stats.ConstructionSpeedBonus` | 연결 마을에 기여하는 건설 배율. 주택 0.1, 회관 0.6 |
| `Stats.Width` / `Depth` | 점유 폭/깊이. 주택·제단 1×1, 합체 결과 2×2 유지 |
| `Stats.BlocksMovement` | 통행 차단 여부. 농장 false, 건설 점유와 공격 대상은 유지 |
| `Stats.Production` / `ProductionSeconds` | 생산 종류와 기본 주기 |
| `Stats.ProductionAmount` | 보리·에테론 회당 수량. 병력은 회차당 1명 고정 |
| `Stats.ProducedUnit` / `TroopCapacity` | 병종 및 해당 시설 소속 생존 정원 |
| `Stats.AccelerationGoldCost` | 현재 회차 1초 가속 가격. 0이면 가속 없음 |
| `Stats.CanMerge` / `MergeTarget` / `DirectBuild` | 1×1 네 채 자동 합체와 결과. 합체 결과는 DirectBuild=false |

기존 `Economy.asset` 주민·인구 필드와 건물 `PopulationCapacity`는 참조 호환용이며 본편 계산에 사용하지 않는다. 수동 모집 가격·시간 대신 건물 SO의 자동 생산 설정을 편집한다. `R1` 주민 강화와 기존 영역 강화는 직접 작업 범위, `R4` 주민 교육은 직접 작업 효율로 이전했다. 노드 ID는 유지한다.

## 모듈 경계와 적용

`Afterlife.Buildings`는 Unity 참조 없이 건물 점유·원형 거리·마을 연결·생산 회차·합체 검색을 처리한다. `CircularRange`의 원형 거리와 시야 감쇠 계산을 모델·표시가 공유한다. `TownSource`는 점유 타일들의 중심을 건물 중심으로 사용하며, `TownNetwork`는 포함 타일의 중첩/상하좌우 접촉으로 연결 성분을 구성한다. `Afterlife.EconomicSites`는 같은 시드와 지형 입력에서 보너스 지대를 생성한다. 시작 보호 반경은 주택 영역 반경을 올림하여 기존 정수 API로 전달한다. `PrototypeBuildingSystems`/`PrototypeEconomicSites`가 게임 모델과 연결하고 기존 `PrototypeView`가 표현을 담당한다. 본편 씬의 기존 `PrototypeScene`/`PrototypeView` 구성을 그대로 사용하며, 새 표시 요소는 `Prefabs/BuildingEconomy/`의 프리팹으로 연결했다.

에테론 HUD는 프리팹 인스턴스 한 개와 `HUD.Etheron`/`HUD.Altar` 두 바인딩으로 설치한다. 다른 씬에서는 동일 인스턴스를 자원 HUD에 배치하고 `PrototypeCanvas` 바인딩을 연결한다. 제거할 때는 해당 바인딩·카메라 입력 차단 참조와 인스턴스를 함께 제거한다. 새 건물 표현은 기존 모델을 조합한 초기 프리팹이며 수치 설정은 포함하지 않는다.

건물 시야는 개수 제한 없는 원형 합집합 텍스처로 표시한다. 타일당 4픽셀(기본 반경45에서 364×364 RGBA32)이며 건설·파괴·합체·이전 등 소스 변경 시만 다시 업로드한다. 모델과 표시 마스크는 동일한 원형 함수와 경계 안쪽 0.65유닛 감쇠를 사용한다. 화면의 텍스처 보간으로 경계에는 픽셀 수준의 차이가 있을 수 있다. 기존 병력·커서·필드의 원형 시야는 기존 동적 경로를 유지한다. 영역은 원 안에 중심점이 있는 타일 집합이므로 외곽이 계단 형태로 보이는 것은 정상이다.

### 반경 변경의 호환성과 확인

빛과 시야는 독립 설정이다. 이전의 집 고정 반경 및 다른 발광 건물의 `시야×0.5` 계산을 제거하고 `Stats.LightRadius`만 사용한다. 기존 SO의 빛 초기값은 집 1.95, 회관 2, 병영 0.5, 나머지 0이다. 데이터 기본값에서 시장·대형 테스트 건물도 기존 값 0.5를 유지한다. 건물 종류 제한 없이 양수이면 발광할 수 있으며, 미완공·이전·파괴 상태의 빛은 꺼진다. 기존 셰이더 조명과 Unity Light가 동일한 반경 설정을 사용한다. 광원 위치·밤의 강도와 발광 창문 표현은 기존 방식이다. 별도 컴포넌트 설치는 필요 없다.

플레이어 블러는 커서만 기준으로 삼는다. 건물 시야 안이더라도 커서에서 멀면 흐리게 보여야 하므로 건물 시야를 블러의 선명 영역에 연결하지 않는다.

빛 분리 수동 확인: 플레이를 종료하고 House SO에서 Vision Radius=2, Light Radius=5로 설정한 뒤 새 게임의 밤에 밝힘을 확인한다. Light Radius를 유지한 채 Vision Radius만 바꿔 새 게임을 시작하면 빛 범위는 같아야 한다. 반대 변경에서는 오브젝트 노출 범위와 블러가 같아야 한다. Light Radius=0이면 주변 조명이 꺼져야 하고, Vision Radius=0/Light Radius>0이면 주변 지형은 밝아질 수 있지만 숨겨진 오브젝트를 드러내지 않아야 한다. 커서가 추가 시야를 주므로 비교 시 위치를 고정한다. 이번 빛 분리의 `dotnet build Afterlife.Prototype.Editor.csproj --no-restore` 역시 NETSDK1004로 컴파일 전에 중단됐으며 Unity 플레이는 실행하지 않았다.

필드 이름과 기존 반경 숫자는 유지하고 `int`를 `float`로 변경했다. 기존 `VisionMatchesTerritory` 필드는 제거했으며 이전 에셋에 남은 직렬화 값은 더 이상 읽지 않는다. 원본 SO·씬·프리팹·메타데이터를 일괄 재작성하지 않는다. 기존 건물 규칙 마이그레이션은 이미 이전된 에셋의 값을 덮어쓰지 않는다. 기존 사각형 확장보다 시야와 영역이 작아지는 것은 의도된 변경이다.

1. 플레이를 종료한 상태에서 House SO의 `Stats`를 편집하고 새 게임을 시작한다. 고립된 1×1 주택의 Territory Radius=2는 중심 포함 13타일이어야 한다. 상대 좌표 (2,0)은 포함하고 (2,2)는 제외한다. 건설 모드의 영역 표시로 확인한다.
2. Territory Radius=1.5는 중심 포함 9타일이다. 2×2 회관은 네 타일 사이의 실제 중심을 기준으로 대칭이어야 한다. 반경이 0이면 점유 타일도 영역으로 강제 포함하지 않는다.
3. Territory Radius를 고정하고 Vision Radius만 바꾼 새 게임에서 영역은 같고 원형 시야만 변해야 한다. 반대 변경은 시야를 유지해야 한다. 시야 0 확인 시 커서·병력·다른 건물 시야가 겹치지 않게 한다. 조명은 시야와 별도이므로 광원 밝기만으로 판정하지 않는다.
4. 주택 영역을 중첩/상하좌우 접촉시키면 건설 보너스가 합산되고 대각선만 닿으면 분리된다. 이전·철거·합병 후 잔여 영역과 시야가 없어야 한다.

이번 반경 수정 검증: `Afterlife.Buildings.csproj`, `Afterlife.Prototype.Data.csproj`, `Afterlife.Prototype.csproj`, `Afterlife.Prototype.Editor.csproj`에 `dotnet build --no-restore`를 시도했으나 각 `Temp/obj/<프로젝트>/project.assets.json` 부재로 NETSDK1004가 발생해 컴파일에 도달하지 못했다. 아래 과거 빌드 기록과 구분한다. Unity Test Runner·자동 플레이는 실행하지 않았으며 위 수동 확인은 대기 상태다.

## 직접 검증 절차

프로젝트 규칙에 따라 자동 Unity Play/Test Runner는 실행하지 않는다. 아래 항목은 실제 플레이에서 확인해야 한다.

1. 주택을 멀리 1채 지으면 별도 마을이 된다. 각 마을의 집 수만 건설 속도에 적용된다. 연결 주택 완공과 파괴로 연결/분리를 확인한다.
2. 주택과 제단을 각각 2×2로 완공한다. 2×2 부지·체력 합산·회관의 4칸 영역을 확인한다. 회관만 남아도 패배하지 않아야 한다.
3. 농장 1개는 3초마다 1원, 인접 4개면 1.5초마다 1원, 비옥한 땅이면 회당 2원이어야 한다. 아군·적이 농장을 통과하고 적은 농장을 파괴할 수 있어야 한다.
4. 병영을 완공하고 30초 뒤 소속 전사 3명으로 멈추는지 확인한다. 한 명을 잃으면 10초 뒤 충원한다. 병영 두 개의 정원은 독립적이다.
5. 생산 중 가속을 눌러 비용 차감과 정확한 현재 회차 단축을 확인한다. 자금 부족·정원 충족 상태에서는 차감되지 않아야 한다.
6. 제단 30초/성소 20초 지급량과 영맥의 두 배 효과를 확인한다. 합체 직전 진행률이 새 성소에 평균값으로 이어지는지도 확인한다.
7. 에테론 표시·제단 HUD 잠금/해금·강화 결제를 확인한다. 제단을 모두 잃어도 이미 구매한 효과와 재화는 유지되어야 한다.
8. 건물 SO 시야 반경 변경 후 재시작한다. 모델의 적 탐지와 화면 밝힘이 일치하며 완공/파괴/이전/합체 시 잔상이 남지 않아야 한다.
9. 새 게임 시작과 종료 후 SO 원본을 확인한다. 경제·생산 상태가 초기화되고 SO 원본은 플레이 전 값이어야 한다.
10. 이전 시작 시 원래 주택 영역/시야가 사라지고 완공 시 목적지에 생기는지 확인한다. 생산 진행과 병력 소속이 목적지로 옮겨져야 한다. 이전 공사 파괴 시 원본 복귀도 확인한다.
11. 남은 시간 0.5초에서 가속하면 표시된 1회 비용만 내고 해당 회차만 끝나야 한다. 병력 출구가 막히면 완료 회차를 대기하고 추가 생산/결제를 쌓지 않아야 한다.
12. 건물 수가 128개를 넘어도 모든 완공 건물의 시야가 유지되어야 한다. 파괴한 건물의 밝힘은 다음 화면 갱신에 제거되어야 한다.

## 검증 기록

코어는 Astra high, UI·시야와 지대는 Sol high 에이전트에 분담했다. 부모 통합 검토와 지대 담당자의 독립 읽기 리뷰로 생산 초과 시간 손실, 농장 경로 차단/대체 표현 충돌체, 성소 툴팁 원점, 128개 건물 시야 한도, 기존 영역 강화의 무효 효과를 찾아 수정했다.

Unity 에디터 API로 신규 SO 5개·표현 프리팹·HUD 인스턴스/참조와 기존 SO를 저장했고 `.meta`는 에디터가 생성했다. 기존 연구소 에셋과 enum 번호는 보존했다. 비용 변환 플래그로 에디터 설정을 다시 실행해도 비용이 반복 축소되지 않는다.

HUD 참조가 각각 1개인지, 자원 행이 돈→에테론→병력 순서로 겹치지 않게 직렬화되는지 확인했다. 기존 비활성 레이아웃을 활성화하고 자원 패널을 확장했으며, 수정 후 에디터 어셈블리 단독 no-restore 빌드도 오류·경고 0개다. 에디터 재컴파일 오류는 없고 셰이더 진단에는 오류 없이 `PrototypeGrass`의 `GrassAlpha` 미초기화 가능성 경고 1개가 남는다.

`Tools/AfterlifePrototype/Build-ScriptableData.ps1`에서 기존 Unity 참조 기반 검증 프로젝트를 만들고 14개 관련 어셈블리에 `dotnet build --no-restore`를 수행했다. 전부 오류 0개이며 Unity 직렬화 필드의 CS0649 경고는 Progression.Unity 22개, Prototype 30개다. 일반 생성 csproj 직접 빌드는 `project.assets.json` 부재로 NETSDK1004가 발생해 저장소의 기존 참조 기반 빌드 경로를 사용했다. 최종 로그는 Unity 프로젝트 `Temp/BuildingEconomyBuild.log`에 있다.

초기 병종 가격 및 외곽 보너스 수치, 실제 UI 배치·게임플레이·시야 렌더링은 사람 플레이 검증 대기다. Unity Test Runner와 자동 Play Mode는 실행하지 않았다.

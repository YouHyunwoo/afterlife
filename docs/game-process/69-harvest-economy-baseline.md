# 버튼 유지 채집 가치와 농장 경제 기준

> 확정 기획 · 2026-10-03: 채집·건설·수리·공격은 버튼을 누르고 있는 동안 작업 주기에 맞춰 반복하고, 강화는 작업 1회당 효과을 높인다. 자동 수입은 농장 건설·생산 강화로 확장한다. 본편 상호작용 필드·슬롯·충전·호버 자동 작업은 폐기한다. [새 규칙·사용법·검증](71-click-work-and-farm-automation.md). 새 규칙은 게임 코드·에셋에 아직 적용하지 않았다. 이전 규칙·수치·QA는 당시 기록으로 보존한다.

- 상태: 새 측정·계산 기준 정리 · 수입 수치/가격 재산정 전 · 게임 변경 없음.

## 1. 측정 기준

**작업 1회당 가치 V0:** 강화 0·충분한 자원 잔량에서 완료된 유효 작업 1회의 실제 골드. 나무는 기존 사용자 지정 작업량 1과 단가 1G를 계산 후보로 연결하면 1G/작업이다. 바위 등은 실제 작업량·단가 설정을 별도 확인한다.

**채집 전용 Hd:** 같은 시드·자원 배치·강화에서 오직 직접 채집한 수입/비정지 시간. 작업 횟수·유효 유지 시간·자원 고갈·대상 이동을 함께 기록한다. 무입력 수입이나 필드 공급량이 아니다.

**정상 운영 Nd:** 채집·공사·수리·공격·배치 중 실제 직접 수입과 농장/기타 수입·지출. 농장 수입을 직접 채집 분자에 포함하지 않는다.

## 2. 계산식과 미정 수치

- 직접 채집 골드 = 대상별 완료된 유효 작업 횟수×실제 회당 채집량×단가. 치명타·강화·잔량 절삭은 실제 지급량 기준.
- 직접 채집 속도 = 측정 구간 직접 골드/비정지 시간. 반복 간격·첫 실행 정책은 설계 미정이며 유효 유지 시간은 사람 측정 대상이다.
- 농장 골드 = 농장별 완료 생산 회차×회당 지급량. 완공/파괴/이전/정지·인접/비옥·강화를 반영.
- 시설 가격의 기준 작업 횟수 = 가격/V0. 필요한 유지 시간은 정한 반복 간격·첫 실행 정책·유효 유지 시간을 반영해 계산.
- 농장 투자 회수 시간 = 가격/순증 자동 수입률. 단순 평균이며 착공/완공·회차·보너스와 강화 비용은 별도 반영.
- 에테론은 제단/성소 생산 회차로 계산한다. 골드나 작업 횟수로 자동 환산하지 않는다.

슬롯 수/충전×필드 작업 횟수 계산과 R0=0.8/1.6G/초는 폐기된 전제의 기록이다. 지속 작업률 후보는 회당 채집량×단가/반복 간격이며 실제 수입에 유효 유지 시간·중단·고갈을 반영한다. 반복 간격과 첫 실행 정책이 미정이므로 G/초를 확정하지 않는다. 70의 이전 가격·농장 5초 후보와 64의 실제 3초 설정을 혼동하지 않는다.

## 3. 일차별 조절과 성장 상태

공통 설정은 작업 1회당 채집/공사/수리/피해, 단가·수리비, 농장 기본 생산량/주기와 강화 효과, 가격/선행 조건이다. 일차별 설정은 낮/밤 시간·자원 공급/잔량·침공·보상 후보다. 회당 작업량 강화와 농장 강화 상태를 날짜 변경으로 덮어쓰지 않는다.

측정 프로필에는 시드·자원 잔량·회당 작업량 강화·농장 수/배치/생산 강화·기존 전투/보상 상태를 넣는다. 측정용 상태는 플레이어 자동 지급이 아니다. SO 스냅샷·일차 어댑터·순수 경제 분석 분리 원칙은 유지하고 실제 타입/필드는 개발 전 정의한다.

## 4. 생산과 직접 개입의 균형

첫 농장은 제단 강화 전에도 생산한다. 중후반 기본 시설/방어 운영은 자동 수입으로 유지하고 직접 채집은 구매 가속·긴급 자금 확보를 담당하는 목표다. 장시간 직접 작업 유지가 필수이거나 클릭 강화가 농장을 무의미하게 만들면 가격·수입·회수 시간을 조정한다.

공사/수리/공격에 쓴 조작 시간은 직접 채집 기회비용이다. 같은 시간 농장 생산·자동 공사·군사 충원은 계속되므로 자동 수입을 다시 차감하지 않는다. 군사 충원은 무료이고 유료 시간 가속만 실제 골드 지출로 넣는다.

## 5. 검증과 이전 계산의 지위

고정 시드·같은 성장 상태에서 채집 전용과 정상 운영을 각각 기록한다. 일차별 유효 작업 횟수·버튼 유지 시간·직접 채집 시간·직접/농장/기타 수입·구매/착공/완공/충원 시각·수리/가속/시설 지출·이월을 측정한다. 장시간 유지 작업 사례와 운영/방어 개입 사례를 구분하며 사람의 피로감·조작 이해를 함께 확인한다.

아래 R0·가격 시간 환산·10일 낮 예산은 필드 모델의 과거 계산이다. 새 규칙의 수입·구매 가능성으로 사용하지 않는다. 가격/일차별 예산은 클릭 측정과 농장 성장 수치가 정해진 뒤 다시 계산한다.

## 1. 기준의 정의

‘채집만’은 시작 주택을 제외한 건설·수리·공격·생산·강화 없이 준비된 슬롯을 계속 자원에 설치하는 기준이다. 아무 입력 없이 방치하는 수입은 아니다. 농장, 처치 골드, 상자, 발견물, 정산 귀중품은 따로 집계한다.

기준은 세 종류를 구분한다.

1. **고정 단위 R0:** 초기1슬롯·자원1개·강화0·공급 충분 상태의 계산값. 가격의 공통 단위이며 일차가 올라가도 바꾸지 않는다.
2. **같은 상태의 채집 전용 수입 Hd:** 그 날의 슬롯·반경·강화·자원 배치를 고정하고 오직 채집하는 고정 시드 수입. 실제 자원 고갈/재배치/설치 실패를 반영한다.
3. **정상 플레이 수입 Nd:** 건설·수리·전투에 필드를 분배한 실제 수입. 농장 등 다른 수입과 지출도 별도 측정한다.

Hd를 시설 구매 여건의 상한 참고로 사용하고 Nd로 실제 달성 여부를 검증한다. ‘초기 능력 그대로10일’과 ‘성장한 능력의 해당 일차’를 같은 표본으로 섞지 않는다.

## 2. 현행 계산값

확인 경로:

- 필드·채집 수치: Resources/AfterlifePrototype/SettingsData/System.asset
- 자원 단가·재고: SettingsData/Resources.asset
- 채집/변환: Runtime/PrototypeModel.cs의 ContributeBody·GatherGold
- 필드 처리: Modules/DivineFields/DivineFieldService.cs, Runtime/PrototypeDivineFields.cs
- 가격: Resources/Data/Buildings/*.asset

위 경로는 Unity 프로젝트의 Assets/_AfterlifePrototype 아래 기준이며 Modules는 Assets/Afterlife/Modules 아래다.

| 항목 | 현행 기본값 |
|---|---:|
| 시작 슬롯 | 1 |
| 충전 | 10초 |
| 필드 수명 | 8초 |
| 작업 간격 | 1초 |
| 나무 작업량·단가 | 작업당2 × 1G |
| 바위 작업량·단가 | 작업당1 × 2G |
| 초기 필드 반경 | 0.5 × 1.8 = 0.9 |
| 초기 골드 | 0G, 시작 주택은 이미 완공 |

초기 치명타 확률은0, 작업/풍요/교역/환생 보너스도0으로 둔다. 충분한 잔량의 자원 하나는 작업당2G, 필드 하나가8번 작업하면16G다.

**R0 = 16G / 10초 = 1.6G/초 = 96G/분.**

이는 자원이 항상 공급되고 배치 실패·빈 작업·입력 지연이 없다는 장기 평균 계산이다. 실제 시작 지도에서의 분당 수입 측정값이나 전체 채집의 최대값은 아니다. 한 필드는 범위 안 여러 자원을 모두 처리하므로 같은 조건에서 자원2개를 계속 처리하면 이론값은3.2G/초다. 재고가 부족하면 작업량이 잘리고, 고갈 후 남은 필드 작업이 낭비될 수 있다.

신규 자원의 잔량은 현행 AddResource에서 나무70×일차, 바위50×일차로 생성된다. 일차 상승으로 총 채집 가능량은 달라지지만 작업당 골드가 자동 증가하는 것은 아니다. 수익 예측에는 이러한 공급 규칙도 포함한다.

일반화한 단순 계산은 ‘슬롯 수 / 충전 시간 × 필드당 작업 횟수 × 작업당 대상별 골드 합계’다. 작업 횟수는 수명/작업 간격의 정수 부분이며, 치명타·강화·풍요·잔량·공급을 적용하면 별도 보정이 필요하다. 반경을 면적으로 환산해 수입에 그대로 곱하거나 동시 필드를 슬롯 수로 제한하지 않는다.

## 3. 가격을 채집 시간으로 읽는다

**가격의 기준 채집 시간 = 골드 가격 / R0.** 후반에는 수입이 커져 같은 가격을 더 빨리 지불할 수 있게 한다.

| 시설 | 현행 가격 | R0 기준 시간 |
|---|---:|---:|
| 주택 | 20G | 12.5초 |
| 농장 | 30G | 18.75초 |
| 병영 | 80G | 50초 |
| 궁수 훈련장 | 120G | 75초 |
| 제단 | 120G | 75초 |
| 화살 타워 | 95G | 약59.4초 |
| 마법사 탑 | 240G | 150초 |
| 기사단 본부 | 320G | 200초 |

이는 가격 환산이며 건설시간은 포함하지 않는다. 필드가 건설을 돕는다면 그동안 포기한 채집도 기회비용으로 본다. 초반 구매 순서는 농장·병영, 다음 궁수/제단 등을 합산해 단계별로 검토한다. 시작 주택 가격을 첫날 필수 지출에 다시 더하지 않는다.

1일 낮120초 × R0는192G라는 예산 지표다. 농장30G+병영80G를 빼면82G지만, 이것만으로 첫날 정상 플레이에서82G가 남는다고 주장할 수 없다. 건설 작업·자원 고갈·동시 채집·농장 생산이 결과를 바꾼다.

에테론 노드는 골드 가격으로 자동 환산하지 않는다. 일반 제단은30초당1에테론이므로 한 제단 기준 연구 비용4에테론은120초 생산에 해당한다. 여러 제단·영맥·성소와 건설 시점에 따라 달라지며, 채집 자금과 강화 생산 시간은 별도 제약으로 설계한다.

|---|---|---|
| Day / DaySeconds / DuskSeconds / NightSeconds | 투자·방어 시간 | 해당 일차의 단계 시작 |
| HarvestGoldMultiplier | 직접 채집 골드만 조절, 기본1 | 채집 보너스와 명시적인 곱 관계 |
| ResourceSpawnInterval / CapacityMultiplier | 자원 부족·빈 필드 제어 | 자원 생성과 개수 제한 |
| NewResourceStockMultiplier | 새 자원의 고갈까지 지속 시간 | 이미 생성된 자원은 소급 변경하지 않음 |
| EnemyCount / Composition / SpawnDirections | 필요한 방어 수준 | 침공 규칙의 일차별 행 |
| MeasurementProfile | 비교할 슬롯·반경·효율·보상 상태 | 측정용이며 플레이어에게 자동 지급하지 않음 |
| PurchaseTargets / ReserveTarget | 구매·예비비 목표 | 분석용, 자동 지급/강제 지출 아님 |

처음에는 모든 날 HarvestGoldMultiplier=1로 두고 기본 수입·성장·가격부터 맞춘다. 이후 특정 날 수입 문제가 남을 때만 일차별 계수를 사용한다. 가격도 일차마다 자동 인상하지 않는 방향을 추천한다. 커진 필드와 생산 투자의 성과가 상쇄되지 않게 하기 위해서다.

실제 적용 시 판 시작에 SO 스냅샷을 만들고 게임 어댑터가 일차 프로필을 선택한다. 기본 슬롯·반경 등 플레이어의 성장 상태는 기존 모듈에서 가져오며 프로필이 덮어쓰지 않는다. 설치된 필드 반경·진행 중 충전은 기존 규칙을 보존한다. 가격을 나중에 일차별로 변경한다면 건설 주문 당시 가격 저장과 취소 환급 기준도 함께 설계해야 한다.

## 6. 생산 투자와 방어 기준

농장30G는 인접/비옥 보너스 없이3초당1G를 생산하므로, 완공 후 비용 회수까지90초가 계산값이다. 인접·비옥 보너스와 건설 비용의 기회비용은 따로 본다. 기준 채집으로 벌 수 있는 금액과 생산시설 투자 수익을 혼동하지 않는다.

군사 시설은 현재 소속 병력3명까지 자동 충원하므로 현행 건설비를 병사당 모집 가격으로 표시하지 않는다. 시설 가격·정원·충원 시간·가속비를 함께 비교한다. 유료 모집을 채택하면 이후에는 ‘병사 모집비/R0’도 추가한다.

5~6일 위기는 수입을 갑자기 줄여 만드는 것을 첫 수단으로 삼지 않는다. 예고된 방어 요구량·전선 손실·복구 비용을 통해 경제 편중의 결과를 드러낸다. 단순 채집과 최소 방어로 버티는 경로는 가능해야 하지만 좋은 운영의 성장 경로보다는 여유가 적도록 맞춘다.

## 7. 검증 절차와 현재 한계

고정 시드별로 첫날/각 성장 단계에서60~120초 채집 전용 구간을 기록한다. 모든 자원 위치·슬롯/반경/효율/보상·초기 충전·시작 필드·자원 잔량을 동일하게 유지한다. 기준 구간은 밤 공격을 제거한 별도 수동 측정 상황으로 만들거나 낮 안에서 수행하며, 적 때문에 패배한 시간을 채집 성능으로 해석하지 않는다.

채집 직접 골드만 분자에 쓰고 시뮬레이션의 비정지 시간을 분모에 쓴다. 귀중품 정산·농장·전리품은 별도 열이다. 여러 시드의 중앙값과 낮은 수입 사례를 같이 본다. 같은 상태에서 정상 플레이의 건설·수리·전투 시간과 실제 구매 시점도 기록한다.

일차별 예산은 ‘이전 잔고 + 직접 채집 + 농장/기타 수입 − 건설/모집/가속/수리 지출’로 계산한다. 매일 잔고를0으로 가정하지 않고, 귀중품처럼 늦게 지급되는 돈은 지급 시점에 넣는다. 설치1회16G나 R0×시간으로 경제 전체를 확정하지 않는다.

검증 순서는 R0 계산 확인 → 실제 채집 Hd → 첫날 구매·건설 → 농장 회수와2~4일 강화 → 5~6일 방어/복구 → 후반 수입과10일 전투다. 실제 수입과 재미는 이번 작업에서 측정하지 않았다.

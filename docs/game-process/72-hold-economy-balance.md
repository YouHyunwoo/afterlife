## 1. 이번 추천의 결론

첫 농장과 병영은 직접 작업으로 빠르게 준비하고, 3일 제단으로 다음 날 강화에 접근한다. 5~6일에는 자금과 병력 손실의 복구를 요구한다. 7일 이후 농장 생산으로 직접 채집 부담을 줄여 배치·수리·중요 적 대응에 시간을 쓴다.

기본 경로는 계산에서 모든 예정 구매·완공과 가정한 복구/가속 지출을 충족했다. 농장 파괴 후 기존 확장 순서를 그대로 쓰는 경로는 부족했고, 농장부터 복구하는 대안은 예산에 맞았다. 전투 승리 여부는 계산하지 않았다.

시작 슬롯·충전·필드 수명·범위는 입력값에서 제외한다. 시작 조건은 **나무 작업당1·단일 대상 버튼 유지·무료 군사 충원**이다. 현행 본편은 아직 이전 방식이므로 아래 결과를 현재 빌드의 성능으로 읽지 않는다.

| 농장 파괴 후 복구 우선 | 6일 농장2개 건설·병영은7일로, 예정 복구/가속비40G. 부족 경고0 | 6일 정원12명으로 복구를 선택하는 대안 |

파괴 후 복구 경로는6일에 잃은 농장을 대체하고 새 농장을 더해 총3개를 되찾는다. 원래6일의 병영55G를7일로 미루고6일 예정 지출70G를40G로 줄였다.7일에는 병영+궁수장에125G를 쓴다.6일 군사 정원은15명 대신12명,7일18명으로 회복한다.10일 이월은114G다.

30G 지출 축소는 피해가 자동으로 줄어든다는 뜻이 아니다. 긴급 가속 등 선택 지출을 줄이고 재건·병력 회복을 기다리는 경로다.6일 전투를12명과 이 지출로 버틸 수 있는지는 후속 검증 항목이다. 소유 농장 수에 따라 적을 자동으로 약화하지 않는다.

작업 주기1.25초 경로는 미지급 지출 합계298G, 농장 파괴 후 기존 순서는195G 부족했다. 계산은 자금을 넘는 지출을 가능한 만큼만 지급하고 경고를 남긴다. 따라서 그 경로의 양수 종료 잔고를 성공으로 읽지 않는다. 미구매한 시설은 다음 날에 자동 추가하지 않는다. 복구 우선처럼 명시적으로 투자 순서를 바꾼 별도 경로로 확인한다.

**이번 조정 우선순위:** 초반 기본 경로부터 사람 검증한다. 농장 인접·추가 농장 경로가 실제로 방어 위험 없이 유리하면 농장 가격/생산 주기로 투자 회수 시간을 늘리거나 강화 상승폭을 줄이는 후보를 재계산한다. 확정 규칙인 인접 보너스를 이번에 임의 제거하지 않았다. 현 후보5→4→3초는 성장 확인용이며 최종값이 아니다. 시설 수를 강제 제한하거나 정답 구매 순서를 퀘스트로 강제하지 않는다.

## 8. 계산 사용법·설계·검증

입력은 [hold-economy.json](balance/hold-economy.json), 계산기는 [calculate_hold_economy.py](balance/calculate_hold_economy.py), 전체 결과는 [hold-economy-results.json](balance/hold-economy-results.json)이다. 외부 라이브러리 없이 Python 표준 라이브러리로 실행한다.

```powershell
python docs/game-process/balance/calculate_hold_economy.py --output docs/game-process/balance/hold-economy-results.json
```

`starting_gold`, `work_interval`, 시설 가격/공사 분모, 생산 주기, 날별 낮/밤/작업 유지 시간/시설 순서/강화 비용/효과/지출을 바꾸면 다시 계산할 수 있다. 계산 도구는 Unity를 참조하지 않고 본편 파일이나 에셋을 바꾸지 않는다. 분석 결과를 SO에 자동 쓰는 기능은 없다.

0.25초 계산 틱으로 골드·에테론·잔여 생산 비율·공사 진행·살아 있는 군사 정원과 작업 잔량을 이월한다. 정산/결과 동안에는 시간이 진행되지 않는다. 농장 주기 변경은 생산 완료 비율을 보존한다. 비용은 착공 시, 생산은 완공 후 회차가 끝날 때 지급한다. 작업 주기는 대상 변경으로 우회하지 않는다.

손실은5일 전사4/궁수2,6일3/2,8일5/3,9~10일6/4를 밤10초에 시설별로 분산하는 **외부 가정**이다. 군사 자동 보충을 확인하기 위한 입력이며 실제 적의 피해·손실 예측이 아니다. 생산 위치가 막히거나 이동 중 사망하는 경우는 모델링하지 않는다. 복구·가속 지출도 생산 가속/회복 효과 자체를 실행하지 않으므로 이를 전투 승리로 연결하지 않는다.

검증한 내용: 기본/복구 경로의 구매·예정 지출 부족 경고0, 모든 경로/일차의 시작+직접 수입+농장−시설−실제 지출=이월 산식,27:15 시간 합계. 별도 Unity 빌드·Test Runner·자동 플레이·사람 플레이는 실행하지 않았다.

직접 확인 순서:

1. 나무1·기본1초 유지 작업에서 실제 유효 작업 횟수와 수입을 기록한다. UI/해제/전환/고갈 때문에 잃은 시간도 측정한다.
2. 1~2일 농장/병영/궁수장 착공·완공·첫/세 번째 생산·배치 시각을 확인한다. 처음부터 모든 작업을 쉬지 않고 유지해야 한다면 가격/시작금보다 설명·대상 공급과 조작 부담도 확인한다.
3. 3일 확장과 제단 재화,4일 강화 선택이 낮의 남는 시간에 들어오는지 본다.
4. 5~6일 실제 수리HP·소모G·가속 초·손실·농장 파괴와 회복 시간을 측정한다. 기본 경로와 복구 우선 경로 둘 다 확인한다.
5. 인접/비옥·초반 농장 확대·직접 작업 강화·방어 강화 선택을 비교한다. 경제 성장만으로 중반 위기가 사라지는지 본다.
6. 7~10일 채집 유지 시간이 줄고 배치/전투에 시간이 쓰이는지, 전체25~30분과 승리·패배·재시작이 이어지는지 확인한다.

실측 전에는 적 수·보스 체력·건물 가격을 최종 확정하지 않는다. 다음 밸런싱의 핵심은 **초반 조작 여유와 농장 최적화 이익에 맞는 방어 위험**이다.

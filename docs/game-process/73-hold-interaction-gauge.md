# 프로토타입 좌버튼 유지 작업과 내부 게이지

2026-10-09. 사용자 확정 규칙을 본편 프로토타입에 적용했다. 기존 클릭 해제 시 필드 설치를 현재 커서의 단일 대상에 대한 유지 작업으로 바꿨다.

경제 후속은 [74 유지 작업·완충 게이지 밸런스](74-gauge-balance-redesign.md)다. 10일 시간·새 가격/강화·구매/복구 경로는 미채택 설계이며 이 문서의 입력 구현이나 기존 SO 값에 자동 적용된 것이 아니다.

## 작업 목록

- [x] 독립 충전 코어와 프로토타입 입력/효과 어댑터 연결
- [x] 필드·슬롯 HUD 숨김, 입력 차단·포커스 상실 처리
- [x] 사용법·설계·검증 문서 갱신
- [x] 독립 모듈·프로토타입 C# 빌드 결과 기록

## 확정 동작과 사용법

| 상태 | 결과 |
|---|---|
| 판 시작·재도전·환생 초기화 | 게이지 100%, 누르기 전에는 작업하지 않음 |
| 유효 대상에서 좌버튼 누르기 | 완충이면 즉시 1회 작업, 게이지 0% |
| 좌버튼 유지 | 현재 커서의 단일 대상에 1초마다 작업하고 0%부터 재충전 |
| 버튼 해제 | 충전은 계속됨. 100%에서 대기하며 작업은 실행하지 않음 |
| 충전 도중 다시 누르기 | 남은 충전 시간이 지난 뒤 작업. 재입력으로 주기 우회 불가 |
| 누른 채 대상 변경 | 게이지 유지, 다음 작업은 현재 커서 대상에 실행 |
| 빈 땅·고갈/사망 대상·완공된 정상 건물·수리비 부족 | 작업/게이지 소비 없음. 완충 상태로 유효 대상을 기다림 |
| UI·모달·포커스 상실·카메라 조작·건설 모드 전환 | 직접 작업 입력 취소. 버튼을 다시 눌러야 재개 |
| 정지·정산·판 종료 | 게임 시간 정지 정책에 따라 충전/작업도 정지 |
| 농장 완공 | 버튼·커서와 무관하게 기존 주기와 보너스로 골드 생산 |

나무·바위 채집, 공사 지원, 손상 건물 수리, 적·동물 공격, 상자 작업·귀중품 획득에 같은 게이지를 사용한다. 회당 작업량·수리비·피해·농장 가격/생산·자동 공사·병력/타워 자동 전투는 기존 계산을 사용한다. 초반에는 직접 채집으로 골드를 마련하고 농장 완공 이후 자동 수입을 얻는다.

좌버튼 건물 이전·병력 영역 선택·공격 이동 드래그는 제거했다. 우클릭 정보·관리, Ctrl/Shift 건설 모드의 기존 클릭 배치, 우버튼/중버튼 카메라 조작은 기존 경로를 사용한다. 일반 빈 땅 클릭에는 작업이나 필드 생성이 없다. HUD에는 상호작용 주기·게이지·필드 슬롯·영력 설치 비용을 표시하지 않는다.

## 모듈과 적용 경로

- `Assets/Modules/HoldInteraction/InteractionCharge.cs`: 순수 C# 충전 상태. `Advance`는 100%에서 멈추고, `TryConsume`는 입력과 준비 상태가 맞을 때 0%로 초기화한다. `Reset` 초기 충전량은 소비자가 지정한다.
- `Afterlife.HoldInteraction.asmdef`: 다른 시스템과 Unity를 참조하지 않는 독립 어셈블리. 입력·대상·보상·씬·HUD를 알지 않는다.
- `PrototypeManualWork.cs`: 1초/시작 100% 설정, 대상 유효성, 실제 작업 효과·이벤트 연결. `UpdateManualWorkInput`은 입력만 바꾸며 게이지를 초기화하지 않는다. `VillageModel.Tick`에서 충전하고 작업한다. 완충 재누르기는 입력 전달 시 즉시 처리한다.
- `PrototypeInteraction.cs`: 버튼 시작/유지/해제·현재 커서 선택·차단 상태만 전달한다. 해제 시 추가 작업은 없다. UI/포커스 차단은 시작 입력을 취소하고, 되돌아와도 유지 중인 버튼을 새 입력으로 취급하지 않는다.
- `PrototypePresentation.cs`: 기존 타격·도구·채집 피드백을 재사용한다. 준비 동작은 표현이며 작업/지급을 예약하지 않는다. 버튼 해제 후 표현이 남아도 추가 작업은 없다.

**기본 적용:** 기존 `Afterlife_PixelPrototype` 씬의 `PrototypeView`와 `PrototypeScene` 구성을 그대로 사용한다. 컴포넌트·프리팹·외부 직렬화 참조를 추가로 설치할 필요가 없다. 기존 컴포넌트 하나가 새 순수 코어 어댑터를 함께 소비한다. 게이지를 HUD에 바인딩하지 않는다.

다른 게임에 코어만 적용할 때는 해당 게임의 입력 컴포넌트 하나에서 인스턴스를 소유하고 `Advance(gameDeltaTime)`을 호출한다. 대상이 유효할 때만 `TryConsume(held)` 후 작업을 실행하며, 차단/비활성화 시 유지 입력만 취소한다. 코어에는 GameObject가 없으므로 독립 프리팹 설치는 필요하지 않다. 판 초기화 때 `Reset(initialFraction)`을 호출하고 해제 시 인스턴스를 폐기한다. 코어의 이벤트 구독과 외부 서비스 참조는 없다.

`DivineFields`·`RechargeSlots`와 기존 직렬화 참조는 촬영 등 기존 소비자를 위해 보존한다. 본편에서는 필드 설치 API를 거부하고 필드 틱을 실행하지 않는다. `PrototypeCapture`만 기존 필드 모드를 명시적으로 선택하며 촬영 종료 시 입력·필드를 비우고 본편 모드/HUD로 복귀한다. Day02/Day03 원본은 수정하지 않았다.

기존 필드 간격/반경/슬롯 강화·보상·풍요의 효과를 새로운 작업량/농장 강화로 바꾸는 설계는 아직 미정이다. 이번에는 노드 ID·비용·효과·농장 밸런스를 바꾸지 않았다. 필드 전용 효과는 유지 작업의 고정 1초 주기에 적용되지 않으며 후속 재설계·검증 대상이다. [72 경제 후보](72-hold-economy-balance.md)는 기본 작업 주기 1초를 제외하고 여전히 미채택이다.

## 컴파일 검증

Unity 프로젝트 폴더에서 실행한다. Unity 테스트·PlayMode·자동 플레이는 실행하지 않는다.

```powershell
dotnet build Afterlife.HoldInteraction.csproj --no-restore --nologo -v minimal -p:SkipResolvePackageAssets=true -p:GenerateDependencyFile=false -p:EnableSourceControlManagerQueries=false
dotnet build Afterlife.Prototype.csproj --no-restore --nologo -v minimal -m:1 -p:SkipResolvePackageAssets=true -p:GenerateDependencyFile=false -p:EnableSourceControlManagerQueries=false
```

검증 결과: `Afterlife.HoldInteraction.csproj`와 현재 Unity가 생성한 `Afterlife.Prototype.csproj` 모두 경고 0개·오류 0개로 성공했다. 최초 시도한 과거 `Afterlife.Prototype.Validation.csproj`는 이전 `Moonstone.dll`/`Mono.Cecil` 경로가 남아 참조 오류로 실패했으며, 현재 생성 프로젝트로 전환해 해결했다. 과거 검증 프로젝트나 패키지 원본은 수정하지 않았다.

신규 스크립트·asmdef·폴더의 `.meta`는 현재 열린 Unity 에디터가 자동 임포트로 생성했다. 에이전트가 직접 생성/수정하지 않았다. 모듈 README의 메타데이터는 다음 에디터 자동 임포트 대상이다. 수정 문서 6개의 로컬 링크 117개는 누락 0개이며 게임 진행 대시보드도 재생성했다. Unity 테스트·Play·자동 플레이는 실행하지 않았다.

## 사용자 플레이 검증

1. `Assets/Prototype/Scenes/Afterlife_PixelPrototype.unity`를 열고 게임을 시작한다. HUD에 게이지·주기·필드 슬롯이 없어야 한다.
2. 나무를 처음 누르면 즉시 1회 채집하고, 3초간 유지하면 이후 약 1초 간격으로 반복해야 한다. 주변 나무에는 동시에 작업하지 않아야 한다.
3. 작업 직후 놓고 2초간 호버한다. 직접 추가 채집/타격/필드는 없어야 한다. 다시 누르면 즉시 1회 작업해야 한다.
4. 작업 직후 0.3초 후 다시 누른다. 남은 약 0.7초 뒤 작업해야 한다. 빠른 재누르기로 작업량이 늘지 않아야 한다.
5. 누른 채 다른 나무·바위·공사·손상 건물·적·상자로 커서를 옮긴다. 주기를 초기화하거나 추가 작업하지 않고 현재 단일 대상만 처리해야 한다. 고갈·완공·사망·수리비 부족이면 충전 소비/초과 지급이 없어야 한다.
6. 누른 채 빈 땅으로 이동해 완충을 기다린 후 유효 대상에 이동한다. 유효 대상에서 즉시 1회 작업하고 다시 충전해야 한다. 건물/병력 위 이동으로 이전·영역 선택·공격 이동이 발생하지 않아야 한다.
7. 누른 채 HUD·모달로 이동하거나 앱 포커스를 잃는다. 복귀 후에도 누른 상태로는 재개하지 않아야 한다. 버튼을 놓았다가 다시 누르면 현재 충전량으로 재개해야 한다.
8. 공사/수리/공격을 확인하고, 농장을 완공한 뒤 버튼을 놓고 다른 조작을 한다. 직접 작업은 멈추고 농장 생산은 계속되어야 한다. 메뉴·정산 정지는 기존 정책과 같아야 한다.
9. 재도전하면 게이지는 다시 100%, 자동 작업은 없어야 한다. 기존 촬영 소비자를 사용하는 경우 촬영 종료 후 필드 작업이 본편에 남지 않아야 한다.

컴파일 성공은 위 조작·화면·경제 검증의 완료를 의미하지 않는다.

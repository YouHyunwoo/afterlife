## 1. 새 규칙이 바꾸는 가치

현재 커서의 **단일 대상**을 좌버튼 유지로 작업한다. 기본 간격은 1초, 새 판은 완충이다. 완충에서 누르면 즉시 작업하고, 놓은 동안에도 충전하되 완충에서 기다린다. 대상 변경·재누르기로 충전이 초기화되지 않는다. 실패한 작업은 충전을 소비하지 않고, 정지/정산 동안 작업과 충전이 멈춘다. UI·포커스에서 돌아온 뒤에는 다시 눌러야 한다.

충분한 나무에 완충으로 시작해 0·1·2·3초에 작업하면 4회다. 그러나 계속 작업할 때 수입의 기울기는 여전히 회당 작업량/1초다. 새 규칙은 **첫 작업 대기와 대상 사이 낭비를 줄이는 효과**이며, 매 클릭마다 추가 수입을 주는 규칙이 아니다. 동일 수치에서 판 시작 충전만 바꾼 계산의 최종 잔고는 163→165G였다. 이를 큰 경제 상향으로 해석하지 않는다.

가격의 공통 단위는 `기본 나무 작업 1회 = 1개 × 1G`, 충분한 공급에서 약 1G/유효 작업초로 둔다. 실제 지도에서는 이동·고갈·대상 변경·공사 때문에 낮 전체가 채집 시간이 되지 않는다. 농장은 그 시간을 되돌려 주는 투자다. 후반에는 직접 작업을 수리·공사·중요 적 공격에 쓸 수 있어야 한다.

좌버튼 병력 선택·공격 이동·건물 이전 드래그는 제거됐다. 이번 경험은 **시설 위치와 생산 투자, 자동 병력, 직접 수리/공격**으로 설계한다. 병력을 드래그로 재배치해야 성립하는 밤 과제는 넣지 않는다.

시작 30G라도 농장에는 5G가 더 필요하므로 직접 채집을 먼저 경험한다. 기본 경로의 농장 완공은 약 13초다. 농장 회수 기간은 완공 후 **175초**로 늘려, 초반에 농장만 추가하는 투자와 첫 병력을 마련하는 선택을 구분한다. 기존 72 후보의 25G·125초 회수와 비교해 자동 경제의 초기 가속을 낮춘다.

돌은 현재 기본 작업당 2G여서 나무보다 빠른 수입을 낼 수 있다. 이 계산의 1G/초는 나무 가격 환산 기준이며 모든 자원의 실제 수입 상한이 아니다. 처음 90초는 나무만 채집한 값과 나무/돌을 선택한 값을 따로 측정한다. 돌만 고르는 경로가 경제/방어 선택을 무의미하게 만들면 돌 단가·작업량·공급을 후속 조절하며, 나무 기준 결과만 보고 전체 가격을 확정하지 않는다.

공사 분모는 농장/궁수장/제단/주택/타워 10, 병영 15를 유지한다. 자동 공사 기여 0.25/초와 시작 주택의 지역 배율 1.1을 계산에 사용한다. 직접 공사는 기본 작업당 1이다. 배치·대상 선택은 시설당 3초, 병력 합류는 생산 후 8초로 가정했다. 추가 주택/합체에 따른 건설 가속과 유리한 실제 이동 경로는 계산에 넣지 않았다.

밤 난도는 아래 준비 목표에 맞춰 후속 조절한다. 적 수·HP·보스 패턴은 이번 경제 산술로 확정할 수 없다. 농장이 많다고 적이 자동으로 강해지는 보정은 제안하지 않는다.

## 4. 강화의 역할과 비용

현재 강화 접근은 완공된 제단/성소와 에테론이다. [64](64-building-economy.md) 이후 연구소 건물은 건설 목록에서 제거됐다. 이전의 연구소 별도 건설 비용/조건을 이 예산에 다시 넣지 않는다.

| 새 계열 후보 | 단계별 효과 | 해당 단계 비용 | 선행 |
|---|---|---:|---|
| 채집 작업량 | 1→1.5→2 | 1 / 2E | 완공 제단/성소, 이전 단계 |
| 농장 생산 주기 | 5→4.5→4초 | 2 / 3E | 완공 제단/성소, 이전 단계 |
| 공사·수리 작업량 | 1→1.5배 | 2E | 완공 제단/성소 |

직접 채집의 회당 양, 자동 농장 생산, 마법/방어의 세 역할로 나눈다. **1초 게이지 간격 감소는 도입하지 않는다.** 농장 5→4→3초였던 72 후보 대신 최대 생산 속도 +25%로 완만하게 만든다. 인접/비옥 보너스가 별도로 크기 때문이다. 공사/수리 강화는 나무 양과 공격 피해까지 자동으로 올리는 공용 배율로 연결하지 않는다.

| 구매 일차 | 대표 구매 | 총 E | 정산 E 잔고 |
|---|---|---:|---:|
| 4 | 채집 1단계 1E + 기존 A1 낙뢰 1단계 1E | 2 | 6 |
| 5 | 농장 1단계 2E + A3 보호 1단계 1E | 3 | 8 |
| 6 | 공사/수리 1단계 2E + A7 회복 1단계 2E | 4 | 9 |
| 7 | 채집 2단계 2E + 농장 2단계 3E | 5 | 9 |
| 8 | A1 낙뢰 2단계 2E + A3 보호 2단계 2E | 4 | 14 |
| 9 | A3 보호 3단계 3E + A7 회복 2단계 4E | 7 | 17 |
| 10 | A1 낙뢰 3단계 3E | 3 | 26 |

기존 노드의 단계 비용은 현재 카탈로그를 확인했다. A7은 A3 선행을 지킨다. 신규 계열에는 아직 ID를 부여하지 않았고 기존 ID를 재사용하지 않았다. 계산기는 일차별 E 비용 합계와 효과를 반영하며 노드별 구매 조건을 자동 실행하지 않는다.

8일 두 번째 제단은 이 대표 경로의 비교용 구매다. 기본 강화에 필수는 아니며 마법 선택 폭을 늘리고 싶은 경우에 둔다. 채집이 적은 대안은 하나의 제단으로 제시된 강화를 모두 지불했다. 영맥 2배 생산은 계산에서 제외했다.

| 필드 범위·슬롯·충전 일일 보상 | 본편 추첨에서 제외. 효과 없는 선택지를 남기지 않음 |
| 풍요 A2 | 활성 필드 자원 조건 때문에 현재 새 입력에서 발동 불가. 마을 안 완공 농장이 있으면 자동 발동하고 농장 생산에만 적용하는 후보 |

풍요의 새 대상/적용 범위는 **미채택**이다. 기존 쿨타임·지속 시간·효과 크기를 출발점으로 검토하되 이번 수입에는 넣지 않았다. 낙뢰/의식은 기존 마을 안 적 조건과 공용 쿨타임, 제단 유무 정책을 보존하는 방향이다.

일일 3택1의 대체 후보는 채집 작업량 +5%씩 최대 3단계, 농장 생산 속도 +5%씩 최대 3단계, 건물 최대 체력 +10%씩 최대 3단계다. 작업량/농장 보상은 연구로 정한 기준에 각각 합산 보너스를 적용하고 인접/비옥 효과와 구분한다. 최대 체력 증가 시 현재 체력 처리는 구현 전 별도 결정한다. 후보 보상을 기준 예산에 넣지 않아 특정 보상이 없다는 이유로 계획이 깨지지 않도록 검토한다. 상자 유물 목록에 자동 편입하거나 기존 ID를 교체하지 않는다.

자원 생성/최대 개수 보상은 **채집할 대상이 부족한 시간을 줄이는 효과**다. 단일 대상·1초 작업에서 대상이 이미 충분하다면 수입 속도를 추가로 늘리지 않는다. 자원 공급 측정 후 효과/상한/추첨 제외를 정한다.

## 5. 연결 경제와 수리 시간

`정산 잔고 = 시작 잔고 + 직접 수입 + 농장 수입 − 건설비 − 수리/가속비`다. 처치·상자·귀중품·정산 골드, 치명타·돌의 유리한 수입·일일 보상은 제외했다. 밤 직접 채집도 넣지 않았다.

| 일차 | 직접 채집 시간 | 직접 / 농장 수입 | 건설비 | 수리 / 가속비 | 정산 잔고 | 수리 작업 시간 상한 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 65초 | 66 / 28G | 90G | 0 / 0G | 34G | 0초 |
| 2 | 45초 | 45 / 26G | 70G | 3 / 0G | 32G | 3초 |
| 3 | 65초 | 65 / 42G | 110G | 4 / 0G | 25G | 4초 |
| 4 | 50초 | 75 / 58G | 105G | 6 / 10G | 37G | 5초 |
| 5 | 40초 | 60 / 66G | 70G | 12 / 20G | 61G | 10초 |
| 6 | 40초 | 60 / 93G | 90G | 18 / 25G | 81G | 10초 |
| 7 | 35초 | 70 / 105G | 70G | 9 / 10G | 167G | 5초 |
| 8 | 25초 | 50 / 108G | 140G | 24 / 30G | 131G | 14초 |
| 9 | 20초 | 40 / 117G | 125G | 30 / 40G | 93G | 17초 |
| 10 | 15초 | 30 / 128G | 0G | 36 / 50G | 165G | 20초 |

수리할 HP 목표는 일차별 `0/30/40/60/120/180/90/240/300/360`이다. 이는 실제 피격 결과가 아니라 방어 경험을 설계할 **총 복구량 후보**다. 비용은 HP/10, 시간은 `ceil(HP/(12×공사·수리 배율))×1초`로 계산한다. 여러 건물 전환/최종 부분 수리 때문에 실제 시간이 더 길 수 있고, 첫 충전이 준비돼 있으면 더 짧을 수 있다.

5~6일의 위기는 잔고를 무조건 바닥내는 방식보다 **병력이 비는 시점에 농장/시설까지 피해를 입어 복구와 확장 중 선택하는 상황**으로 만든다. 기준 손실은 5일 전사4/궁수2, 6일 전사3/궁수2, 8일 전사5/궁수3, 9~10일 전사6/궁수4를 입력했다. 전투가 이 손실을 발생시킨다는 증거는 없다. 밤 시작+10초에 손실/지출을 넣어 생산 재개와 이월만 계산했다.

가속은 현재 회차 시간을 돈으로 줄이는 **선택 비용**이다. 무료 충원 시간을 모집비로 추가 차감하지 않는다. 계산기는 가속 예산을 차감하지만 가속 클릭·시간 절약·생존 효과를 실행하지 않는다. 낮 준비 목표는 가속 없이도 맞추는 쪽으로 계산했다.

기준 수입에서 농장 비중은 1일 약 30%, 7일 60%, 10일 81%로 늘어난다. 후반 채집 시간이 15~25초로 줄어드는 만큼 방어 관찰·수리·직접 공격에 시간을 쓸 수 있다는 가설이다. 선택 시간을 제외한 낮에서 계산상 채집+공사 점유는 약 68%→25%로 감소한다.

## 6. 다른 선택을 할 수 있는가

| 비교 경로 | 경제·준비 산술 결과 | 설계 의미 |
|---|---|---|
| 기본 | 지출/구매 부족 0, 준비 목표 미달 0 | 기준 흐름을 연결할 수 있음 |
| 채집 시간만 20% 감소, 동일 구매 순서 | 부족 경고 10, 9~10일 준비 미달 | 시간 합계가 같아도 동일한 소비를 강요하면 막힘 |
| 채집 20% 감소 + 투자 순서 변경 | 부족 0, 준비 미달 0, 최종 153G | 3일 두 번째 농장을 4일로, 초기 타워/주택을 늦추고 두 번째 제단 생략. 공사 순서 변경으로 대응 |
| 5일 농장 파괴, 기존 확장 유지 | 부족 경고 3, 9~10일 준비 미달 | 경제 손실을 방치한 비용 |
| 5일 농장 파괴, 복구 우선 | 부족 0, 준비 미달 0, 최종 133G | 6일 농장 2개, 병영은 7일. 가속 예산 25→10G. 6일 전사6/궁수6으로 버틸 선택 |
| 1일 농장 2개부터 | 지출 부족 0, 첫 밤 전사 0명 | 병영 완공 약 121초, 첫 전사 약 139초. 밤 시작 130초의 방어 공백과 장기 이익 교환 |
| 농장 인접 보너스 예시 | 부족 0, 최종 479G | 최대 3농장의 +50% 속도만으로도 이익이 큼 |
| 3일 이후 두 번째 농장 비옥 상한 | 부족 0, 최종 427G | 추가 접근비 제외 상한. 실제 경로 검증 필요 |
| 위 비옥+인접 상한 | 부족 0, 최종 847G | 두 보너스 중첩의 과잉 경제 위험 |

초기 집 영역에는 비옥한 땅이 생성되지 않는다. 시작 보호 범위와 지대 최소 거리 조건이 있으므로 **첫 농장을 바로 비옥한 땅에 짓는 경로는 기준으로 쓰지 않는다.** 두 번째 농장의 비옥 비교도 영역 확장용 추가 주택·공사·접근 비용을 넣지 않은 상한 계산이다. 고정 시드에서 실제 배치 가능한 부지와 접근 비용을 확인하기 전에는 실행 가능한 대안으로 주장하지 않는다. 인접 경로도 전 농장이 해당 인접 수를 만족할 수 있는 실제 배치를 확인해야 한다.

수입은 남아도 준비가 늦을 수 있다. 실패 비교에서는 부족한 지출을 잔고까지로 잘라 계산하므로 마지막 잔고가 양수여도 성공한 예산이 아니다. 현재 에셋 값을 같은 10일 계획에 넣은 비교 역시 **현재 6일 게임 실측이 아니다.** 해당 비교에서 지출/구매 경고 7개와 미지급 예산 약 471G가 발생했다.

이 산술로 확인한 것은 돈·E·완공·합류 목표의 연결뿐이다. 실제 전투에서 기본/적은 채집/복구 경로가 모두 돌파 가능하고 농장 몰빵이 위험을 감수한 선택인지 확인한 뒤 적 구성·시설 내구·생산 보너스를 조절한다.

## 7. 계산 도구 사용법과 경계

- 입력: [gauge-economy.json](balance/gauge-economy.json). 시간·가격·작업량·연구 비용·복구 HP·가속 초·손실·구매 순서를 편집한다.
- 실행: `python docs/game-process/balance/calculate_gauge_economy.py --output docs/game-process/balance/gauge-economy-results.json`
- 결과: [11경로 계산 결과](balance/gauge-economy-results.json). `issues`는 지출/구매 부족, `preparation_issues`는 밤 준비 목표 미달이다. 두 항목을 함께 확인한다.
- 구조: [완충 규칙 어댑터](balance/calculate_gauge_economy.py) → [공통 경제 계산기](balance/calculate_hold_economy.py). 기존 72 입력/결과는 보존하며 새 옵션 기본값은 과거 계산을 유지한다.

0.25초 틱으로 직접 작업 잔량·공사·생산 회차·재화·살아 있는 병력을 이월한다. 완충 시작은 첫 시각 0초의 유효 작업을 허용하고, 작업 불가/배치 대기 동안 충전은 유지한다. 강화로 농장 주기가 바뀌면 생산 완료 비율을 유지한다. 시설별 최대 병력 3명, 정원 충족 시 생산 대기, 손실 후 새 생산을 반영한다. 정산 동안에는 모든 시간이 멈춘다.

지도·실제 자원 고갈/재생·UI·병력 AI·시설 피격·자동 스킬·회복·보스는 실행하지 않는다. 수리와 가속은 예정 예산이며 전투에 미치는 효과는 계산하지 않는다. 합체·추가 주택 건설 배율·영맥·일일 보상도 제외했다. 타워/마법의 효율과 실제 낮 조작 여유는 별도 검증 대상이다.

## 8. 검증과 후속 적용 순서

문서 작업에서 확인한 범위는 11경로×10일 = 110개 행의 골드 이월 산식, 전체 시간 합계, 대표/적은 채집 순서 변경/복구 경로의 구매·준비 목표다. 새 옵션을 사용하지 않았을 때 이전 72의 6경로 결과도 동일하게 재현했다. 73의 C# 빌드 기록은 입력 구현의 별도 증거다. 이번에는 Unity Test Runner·자동 플레이·C# 빌드·실제 플레이를 실행하지 않았다.

후속 적용 순서:

1. 회당 나무 1·시작 골드·농장/병영 가격·농장 생산·군사 가속 후보를 확정한다. 기존 1초/완충 입력은 유지한다.
2. 필드 전용 구매/보상을 제거하고 신규 작업량/농장 강화의 효과·비용·선행·중첩을 확정한다. 풍요/체력 보상의 미정 처리도 결정한다.
3. 에디터 직렬화 API로 SO를 적용하고 실제 10일 진행·마지막 클리어를 연결한다. GUID와 과거 소비자는 보존한다.
4. 고정 시드에서 처음 90초 직접/농장 수입, 농장/병영 완공, 첫 3명 합류를 측정한다. 목표 시각과 실제 고갈/선택 시간을 비교한다.
5. 3~4일 강화 접근·경제 부지 비용·농장 인접, 5~6일 병력 손실·수리 HP/유지 시간·농장 복구 선택을 확인한다.
6. 7~10일 직접 채집을 줄이고도 증원·복구가 가능한지, 자동 스킬/타워·보스 대응을 체험할 여유가 있는지 확인한다.
7. 기본·채집 적은 경로·농장 손실 경로의 실제 승패 원인을 비교하고 25~30분에 맞춘다. 가격/적 수/체력을 동시에 바꾸지 말고 원인별로 조절한다.

직접 입력 점검은 완충 첫 작업, 누른 채 대상 이동, 반복 재누르기, 빈 땅/수리비 부족, UI 복귀 재누르기, 정지/정산/새 판 순서로 한다. 모든 경우 1초 공용 충전과 유효 작업 소비가 유지돼야 한다.

채집 공급이 부족하면 먼저 자원 접근/재생을 확인하고, 조작 시간이 부족하면 불필요한 공사/선택을 줄인다. 위기에서 수리만 하다 밤이 끝나면 시설 피해량과 수리 작업량을 조절한다. 후반 돈이 남아도 직접 작업을 놓을 수 없으면 자동 병력/마법/시설의 실제 역할을 확인한다. 수입 증가만으로 재미가 검증된 것으로 기록하지 않는다.

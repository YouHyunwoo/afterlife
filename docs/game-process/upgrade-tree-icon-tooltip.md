## 변경 전후

오른쪽 고정 설명 패널과 노드의 제목/가격 텍스트를 제거했다. 강화 노드는 픽셀 아이콘과 단계 칸으로 표시하고, 이름·설명·현재/다음 효과·가격·선행 조건·구매 불가 이유는 호버 툴팁으로 보여준다. 툴팁은 포인터가 나가거나 드래그/줌/모달 전환 시 숨긴다. Raycast를 차단하지 않고 화면 가장자리에서는 반대편으로 배치하거나 안쪽으로 제한한다.

트리 viewport는 모달의 전체 영역에 stretch한다. 패널 때문에 오른쪽 295픽셀이 비던 영역을 없앴다. 전체 노드의 격자 위치와 노드 외곽을 포함한 bounds를 계산하며, 제목/닫기/하단 조작을 위한 여유만 두고 처음 열기·전체 보기·해상도 변경 때 맞춘다. 숨겨진 노드도 bounds 계산에 포함하므로 나중에 해금되어도 기존 전체 보기 범위를 벗어나지 않는다. 기존 부모 OR 표시/AND 해금 규칙을 유지하므로 아직 발견되지 않은 노드를 미리 노출하지는 않는다.

기본 셀 간격은 런타임/에디터 모두 120×100, 노드는 88×88, 아이콘 표시 영역은 64×64다. 실제 PNG는 48×48이며 Point 필터로 표시한다. 확대 상한은 기본 160%, 최소 배율은 기본 60%와 전체 맞춤 배율 중 더 작은 값이다. 큰 트리 때문에 전체 맞춤이 최소 배율에 막혀 잘리는 것을 방지한다. 사용자가 편집한 격자 좌표는 바꾸지 않는다.

## 축소 및 적용 게이트

재현 스크립트: `tools/art/build_upgrade_icons.py`.

1. 고해상도 원본 20개를 `res/art-source/ui/upgrades-v1/source/`에 보존한다.
2. 원본의 실제 알파가 없으면 재생성을 요구하고 중단한다. 알파 유효 영역을 자르고 긴 변 40px로 면적 평균 축소한 뒤 48px 캔버스 중앙에 배치한다.
3. 8색 팔레트, 디더링 없음, 알파 0/255로 정리한다. 최종 파일은 사방 최소 4px 투명 여백을 가진다.
4. `candidates/`와 [검수표](../../res/art-source/ui/upgrades-v1/review-sheet.png)를 생성한다. 검수표는 3배 Nearest 확대, 실제 48px 및 32px 표시를 함께 제공한다.
5. 20개 모두 실제 크기/축소 표시에서 실루엣·유사 아이콘 구분·외곽선·여백·잘림을 시각 검사했다. 집/구획/결계, 낙뢰/연쇄/감전/의식, 협동/보살핌은 서로 구분된다.
6. 기술 결과는 `technical-report.json`, 아이콘별 시각 판정과 승인 PNG 해시는 `visual-approvals.json`에 기록했다. `--apply`는 20개 전체의 기술 통과·시각 통과·승인 해시가 일치할 때만 게임 폴더에 복사한다.

결과: 20/20 통과. 게임 자산은 `impls/unity/Afterlife/Assets/_AfterlifePrototype/Resources/UI/Upgrades/R1.png`~`R10.png`, `A1.png`~`A10.png`다. 생성 이미지의 큰 원본을 게임에 직접 적용하지 않았다.

Unity importer는 Sprite Single, Point, 무압축, mipmap 없음, NPOT 크기 유지, FullRect, PPU 48로 설정한다. 기존 Catalog의 빈 Icon 필드만 연결하며 사용자가 지정한 Sprite는 유지한다. 런타임 기본 데이터도 게임 어댑터의 Resources resolver로 같은 승인 에셋을 찾는다. 공통 트리 모듈 자체는 프로젝트 리소스 경로에 의존하지 않는다.

## 검증과 남은 확인

### 툴팁과 강화 성공 연출

- 툴팁은 unscaled time 기준 0.36초 진행값으로 0.5→1 스케일 바운스와 감쇠 회전을 적용한다. 숨김은 동일한 진행값을 역으로 이동하며, 중간 취소/재진입에도 초기화하지 않는다. 모달 비활성화 시에는 즉시 초기화한다.
- 구매 결과가 Success일 때만 0.55초 젤리 바운스를 재생한다. 가로·세로 변형이 엇갈리고 마지막에는 원래 크기로 복원된다.
- 노드보다 앞선 sibling의 전용 그래픽에서 연구소 물방울/제단 크리스탈 16개를 방사형으로 발생시킨다. 0.8초 동안 감속 이동하며 페이드아웃한다. 128개 고정 풀을 재사용하고 닫을 때 초기화한다.
- 검증: UI 모듈 `dotnet build --no-restore` 통과, 경고·오류 0. Unity 플레이 검증은 수행하지 않았다.
- 직접 확인: 빠른 호버 진입/이탈/재진입에서 역재생의 연속성, 화면 모서리 툴팁 잘림, 구매 성공/실패 시 연출 구분, 연속 구매 및 모달 재개방 후 스케일 복원, 파티클이 노드 뒤에서 출력되는지 확인한다.

### 정산 우선 표시 및 툴팁 정리

- 정산 진입 시 연구소·제단을 닫고 스택에서도 제거한다. 필수 보상 선택과 정산 완료 후 강화 화면을 자동으로 다시 열지 않는다.
- 툴팁을 340×260 카드로 통일했다. 이름·설명·현재 수치 → 다음 수치를 분리하고 선행 조건, 강화 상태, 클릭 안내를 제거했다. 작은 화면은 카드 전체를 같은 비율로 축소한다.
- 하단 중앙에 금화 도형과 가격을 배치한다. 조건·진행 상태·잔액이 모두 구매 가능하면 민트색, 아니면 붉은색이다. 최대 단계는 현재 수치만 표시하고 가격은 숨긴다.
- 화살표는 글꼴에서 지원하면 `→`, 지원하지 않으면 `->`를 사용한다. 비율은 `10% → 20%`처럼 불필요한 소수점 없이 표시한다.
- 기본 정의와 저장된 카탈로그의 설명 20개를 쉬운 문장으로 정리했다.
- UI 및 게임 모듈의 `dotnet build --no-restore` 통과, 경고·오류 0. Unity 실행 검증은 수행하지 않았다.
- 직접 확인: 연구소/제단 중 정산 발생 시 해당 화면이 닫히는지, 보상 선택 후 돌아오지 않는지 확인한다. 두 트리에서 긴 설명의 잘림, 가격 중앙 정렬, 잔액·잠금에 따른 가격 색상, 최대 단계의 가격 숨김을 확인한다.

### 배경 애니메이션 비용 절감

- 매 프레임 물방울의 약 48,216개 정점과 크리스탈의 38,400개 정점을 다시 만들던 방식을, 런타임 텍스처 캐시와 각각 최대 96개 정점으로 변경했다. 개수 24개와 깊이별 크기·블러·색상은 유지한다.
- 물방울은 깊이별 이미지 3개를 처음에만 계산한다. 크리스탈의 입체 회전·블러 계산은 4개씩 분산하며, 낙하 위치는 매 프레임 갱신한다. 회전 이미지 갱신은 이동보다 낮은 빈도이며 처음 표시할 때 최대 6회 갱신에 걸쳐 준비된다.
- 배경을 별도 Canvas로 분리했다. 캐시 버퍼는 재사용하고 생성한 텍스처는 컴포넌트 파괴 시 해제한다.
- 검증: 관련 UI 모듈 `dotnet build --no-restore` 성공, 경고·오류 0. 플레이 실행 및 FPS 측정은 수행하지 않았다.
- 사용자 확인: 연구소·제단을 각각 열어 배경 24개, 원근감, 색상, 회전을 확인한다. 같은 해상도에서 트리를 드래그·확대/축소하며 이전과 비교해 프레임 시간과 조작 반응을 확인한다. 특히 크리스탈 회전이 낮아진 갱신 빈도에서도 자연스러운지 확인한다.

### CanvasRenderer 누락 수정

- 사용자 실행에서 `주거 개선` 노드의 `RectMask2D` 클리핑 중 `MissingComponentException`이 발생했다.
- 수정 전: 직접 만든 `MaskableGraphic`인 `UpgradeNodeVisual`과 `ProgressionBackdrop`에 렌더러 필수 지정이 없어 런타임 생성 시 `CanvasRenderer`가 누락됐다.
- 수정 후: 두 클래스에 `[RequireComponent(typeof(CanvasRenderer))]`를 선언했다. 노드, 상태 배지, 배경 생성 시 Unity가 렌더러를 함께 추가한다.
- 검증: `Afterlife.Progression.Unity.ModuleValidation.csproj`의 `dotnet build --no-restore` 성공, 경고 0·오류 0. Unity 실행 검증은 수행하지 않았다.
- 직접 확인: 플레이를 종료하고 스크립트 컴파일 완료 후 다시 실행한다. 연구소와 제단을 각각 열고 트리를 드래그·확대/축소했을 때 누락 예외 없이 노드와 상태 배지가 표시되어야 한다. 이미 생성된 오브젝트에는 필수 컴포넌트 선언이 소급 적용되지 않으므로 플레이를 재시작한다.

- `Build-Modules.ps1`: 관련 모듈 모두 `dotnet build --no-restore` 성공, 오류·경고 0. 최종 상태 배지 수정 후 공통 UI 어셈블리 재빌드 성공.
- 이미지 검사: 원본 투명도, 48×48, 최대 8색, 알파 0/255, 최소 4px 여백, 20개 시각 검사 및 적용 해시 일치.
- `AGENTS.md`에 따라 Unity Test Runner, PlayMode 및 플레이어 빌드는 실행하지 않았다. 이미지 검수표는 실제 게임 화면 캡처가 아니다.

Unity에서 확인할 절차:

1. 임포트 완료 후 강화 에디터에서 20개 Icon 참조 및 픽셀 표시를 확인한다.
2. 연구소/제단을 연다. 오른쪽 고정 설명 패널이 없고 첫 화면에 현재 표시 가능한 노드가 전부 들어와야 한다.
3. 각 모서리 노드를 호버한다. 이름/효과/비용/부모가 툴팁에 표시되고, 툴팁이 화면 밖으로 잘리지 않으며 포인터를 빼면 사라져야 한다.
4. 노드를 0→1→최대 단계로 구매한다. 빈 칸→민트/단계 채움→금색 이중 테두리/체크로 변해야 한다. 부모 미충족 노드는 잠금 배지를 보여야 한다.
5. 드래그/줌 후 전체 보기를 누르고 화면 크기를 바꾼다. 전체 노드 범위가 다시 들어오며 새 자식이 표시되어도 화면 경계 밖으로 벗어나지 않아야 한다.

# Unity 플레이 시작 최적화 (2026-09-24)

## 확인한 원인

- `PrototypeView.SetUp()`은 타이틀을 표시하기 전에 지형, 물, 풀, 장식과 모든 오브젝트를 동기 생성했다. 타이틀에서는 카메라가 꺼져 이 월드는 보이지 않는다.
- 인트로 완료 시 `IPrototypeGameSession.Begin()`이 모델을 초기화하고 맵을 다시 생성했다. 따라서 첫 게임까지 월드 표현을 두 번 생성했다.
- 현재 맵 반경은 45(91×91 타일)이다. 지표 색상/법선 텍스처만 365×365 지점을 계산하며, 육지 법선은 각 지점에서 높이를 네 번 조회한다. 각 높이 조회는 다시 네 격자 꼭짓점을 계산했다.
- 지형 장식은 같은 원본 메시의 정점·법선·색상·삼각형 배열을 배치할 때마다 다시 복사했다.
- 에디터 설정은 이미 도메인/씬 리로드를 모두 생략한다. 기존 로그의 5.832초 Asset Refresh는 스크립트/셰이더 변경 처리이며 매번 플레이 시작 비용으로 해석하면 안 된다. Day01 씬 반복 열기도 발견했지만 플레이 지연 기여도를 확정하지 못해 이번에는 변경하지 않았다.

## 변경

- 타이틀에서는 UI, 카메라, 오디오와 공통 상호작용만 준비한다. 지형·식생·오브젝트는 실제 세션 시작 시 한 번 생성한다. 재시작/환생의 기존 맵 재생성 경로는 유지한다.
- 지형 높이의 1/4·1/16 격자 꼭짓점을 정수 키로 캐시한다. 보간식·해안 형태·해상도는 유지하고, 캐시는 지형 인스턴스와 함께 해제한다. 반복 계산 대신 맵 수명 동안 캐시 메모리를 사용한다.
- 장식 원본 배열과 변환 행렬은 맵 생성당 한 번 읽고 모든 배치에 재사용한다. 이 임시 데이터는 생성 후 보관하지 않는다.
- 에디터/개발 빌드에서 `[Prototype.Startup]` 로그와 `Prototype.Startup.*` Profiler 구간을 추가했다. `ViewSetup`, `Ground`, `Decorations`, `Vegetation`, `Objects`를 구분한다. 실제 화면 표시까지의 전체 시간은 별도로 측정해야 한다.

## 검증 및 사용자 확인

- 오래된 검증 프로젝트의 소스 목록/참조를 현재 프로젝트에 맞춘 임시 csproj로 `dotnet build --no-restore` 수행: TerrainView 및 Prototype 모두 경고 0, 오류 0. 임시 프로젝트는 검증 후 삭제했다.
- 프로젝트 규칙에 따라 에디터 테스트/플레이 모드는 실행하지 않았다. 실제 시간 단축 수치는 미측정이다.
- 스크립트 컴파일이 끝난 뒤 `Afterlife_PixelPrototype` 씬에서 Play를 누른다. 타이틀까지는 `ViewSetup`만 출력되고 월드 생성 로그는 없어야 한다.
- 타이틀 → 인트로 → 게임으로 진입한다. 지형/식생/오브젝트 생성 로그가 각 한 번 출력되고 기존 외관, 지면 클릭, 채집, 물결과 풀이 정상이어야 한다.
- 타이틀 복귀 후 새 게임, 환생, Play 종료 후 재진입도 확인한다. 새 맵 생성과 UI/오디오가 정상이며 오류/중복 월드가 없어야 한다.
- 전후 시간 비교는 같은 MapSeed·MapRadius·컴파일 완료 상태에서 Play→타이틀과 인트로 완료→게임 표시를 각각 측정한다. 최초 에셋/셰이더 로딩과 반복 실행을 구분한다.

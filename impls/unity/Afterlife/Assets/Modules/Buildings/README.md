# 건물 규칙 코어

`Afterlife.Buildings`는 Unity·씬·게임 enum에 의존하지 않는 순수 C# 모듈입니다.

- `BuildingFootprint`: 타일 기준 직사각형 점유와 상하좌우 접촉을 판정합니다. 대각선 접촉은 연결하지 않습니다.
- `CircularRange`: XZ 평면의 원형 포함 판정과 시야 감쇠를 모델·표시에서 공유합니다. 반경과 좌표는 Unity 월드 단위이며 0 이하 반경은 비활성입니다.
- `TownSource`: 건물 점유 중심과 소수 반경을 받아 중심점이 원 안에 있는 타일만 열거합니다. 경계는 포함하며 건물 크기를 반경에 더하지 않습니다.
- `TownNetwork`: 완공 주거 건물 영역의 연결 성분을 다시 계산하고 해당 마을의 건설 속도 배율을 반환합니다. 주택이 파괴되거나 이전되면 전체 연결을 다시 계산해 분리된 마을에 보너스가 남지 않게 합니다.
- `ProductionCycle`: 회차의 정규화 진행률과 초과 시간을 보관합니다. 일반 생산은 초과분을 다음 회차로 넘기며, 완료 회차를 소비한 호출자가 생산 결과를 지급합니다.
- `BuildingMerge`: 완공·정지·1×1인 후보에서 동일 종류/대상의 2×2 합체를 찾습니다. 후보 순서와 무관하게 Z, X 순서로 처리합니다. 농장 인접 속도 계산도 제공합니다.

## 게임에 연결

기본 적용 경로는 기존 `Afterlife_PixelPrototype` 씬의 `PrototypeView` 구성입니다. 별도 설치 컴포넌트나 추가 전역 서비스는 필요하지 않습니다. 모델 조립 시 건물 SO의 `ToRule()` 스냅샷을 전달하면 `PrototypeBuildingSystems` 어댑터가 이 코어를 연결합니다. 어댑터는 모델의 건물·소속 병력·지갑·지대 보너스를 읽고 생산 결과와 합체를 모델에 반영합니다. 새로운 소비자는 위 코어 타입을 생성하고 자신의 완공 건물 스냅샷을 전달하면 됩니다.

조정은 `Assets/Prototype/Resources/Data/Buildings/` 아래 건물 SO에서 합니다. `BuildingStats`가 점유 너비/깊이, 시야/영역, 건설 보너스, 통행, 생산 주기/종류/정원/가속 비용, 합체 대상을 소유합니다. 값은 다음 게임 시작 때 깊은 복사되며 프리팹에는 중복 저장하지 않습니다. `ProductionAmount`는 보리·에테론에 적용하고 병력은 회차당 1명씩 생산합니다.

`VisionRadius`와 `TerritoryRadius`는 독립적인 `float` 월드 반경입니다. 영역은 주택·회관에 적용하며 타일 중심과 건물 중심의 `거리² ≤ 반경²`로 결정합니다. 현재 타일 간격은 Unity 1유닛입니다. 영역의 계단 경계는 정상이며 시야는 0.65유닛의 기존 감쇠로 부드럽게 표시합니다. 기존 시야/영역 연동 옵션은 제거했습니다. 숫자·참조는 유지하되 기존 사각형 외곽 확장보다 실제 범위는 작아집니다. 추가 설치/제거 절차는 없습니다.

마을 연결은 실제 포함 타일의 중첩 또는 상하좌우 인접으로 판정합니다. 사각 바운딩 박스만 닿거나 대각선으로 닿는 경우는 연결하지 않습니다. 반경 0이거나 포함 타일이 없는 소스는 건설 보너스를 제공하지 않습니다.

빛은 건물 SO의 `Stats.LightRadius`로 별도 설정합니다. 광원 기준 3D Unity 월드 반경이며 0 이하이면 주변 조명을 끕니다. 시야 반경을 변경해도 빛 반경은 변하지 않습니다. 기존 초기값은 집 1.95, 회관 2, 병영 0.5이며 다른 건물에도 양수를 지정할 수 있습니다. 설정 변경 후 새 게임에서 밤의 밝힘 범위를 비교하고, 시야만 변경했을 때 빛이 유지되는지와 빛만 변경했을 때 오브젝트 노출 범위가 유지되는지 확인합니다. 플레이어 블러는 커서 기준으로 독립 유지합니다. 추가 설치는 필요 없습니다.

회차와 소속 정보는 판 모델에만 존재합니다. 새 판/환생 시 어댑터의 회차·연결 상태를 초기화합니다. 재화 초기화는 기존 판 수명 관리가 맡으며, 에테론은 새 게임에서 0이 됩니다. 이벤트 구독을 생성하지 않아 별도 구독 해제가 필요하지 않습니다. 해제는 소비자의 모델 참조를 놓으면 됩니다.

## 검증

프로젝트 정책에 따라 Unity Test Runner·Play Mode 자동 검증은 실행하지 않습니다. 코어는 `dotnet build Afterlife.Buildings.csproj --no-restore`로 컴파일하고, 전체 연결은 `Tools/AfterlifePrototype/Build-ScriptableData.ps1`의 생성 검증 프로젝트를 빌드합니다.

사용자가 플레이 모드에서 확인할 항목:

1. 떨어진 주택의 영역을 연결하면 각 연결 마을의 주택당 +10%, 회관당 +60%가 합산되고 연결 주택 파괴 시 분리됩니다. 대각선만 닿으면 합산되지 않습니다.
2. 주택은 영역 밖에, 다른 건물은 부지 전체가 영역 안에 있을 때만 배치됩니다. 영역에서 이탈한 공사는 기본 속도로 이어집니다.
3. 주택/제단 4개를 2×2로 완공하면 회관/성소로 합쳐집니다. 현재·최대 체력 합계와 제단 평균 생산 진행률이 유지되며 회관만 남아도 패배하지 않습니다.
4. 농장은 3초마다 보리 1개/골드 1을 지급하고 인접 농장당 속도 +25%(최대 +100%)를 얻습니다. 유닛이 농장을 통과하되 적은 공격할 수 있어야 합니다.
5. 병력 정원 도달 시 진행률은 0으로 대기하고 사망 후 새 회차를 시작합니다. 생산 위치가 막히면 완료 회차 하나를 보류하고 재시도합니다.
6. 1초 미만이 남은 가속은 현재 회차만 완료합니다. 다음 회차로 가속이 넘어가지 않으며 자금 부족·정원 충족·정지 상태에서는 지불하지 않습니다.
7. 건물 이전 중 생산·주거 영역·시야는 멈추고 완료 시 목적지로 회차와 소속 병력이 이어집니다. 이전 중 건물은 합체하지 않습니다.
8. 낮은 프레임에서 일반 생산 주기의 초과 시간이 보존되고, 새 게임에서 회차·에테론이 초기화되며 원본 SO 수치는 변경되지 않습니다.
9. 고립된 1×1 주택의 영역 반경 2는 13타일, 1.5는 9타일입니다. (2,0)은 반경 2에 포함되고 (2,2)는 제외됩니다. 2×2 회관도 실제 중심을 기준으로 대칭인지 확인합니다.
10. 건물 SO에서 시야/영역 반경을 각각 바꾸고 새 게임을 시작하여 서로 독립 적용되는지 확인합니다. 0은 비활성이며 시야 확인 시 다른 시야 소스와 커서를 치웁니다.

2026-09-29 반경 수정의 빌드는 Buildings·Prototype.Data·Prototype·Prototype.Editor 모두 `project.assets.json` 부재(NETSDK1004)로 컴파일 전에 중단되었습니다. Unity 플레이 검증은 수행하지 않았습니다. 상세 절차는 저장소 `docs/game-process/64-building-economy.md`를 참고합니다.

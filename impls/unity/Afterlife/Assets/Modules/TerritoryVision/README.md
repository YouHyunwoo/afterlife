# 마을 영역 시야·빛

단위 타일 사각형의 외곽에서 XZ 거리 2까지 확장한 합집합을 제공한다. 대각선 모서리는 원형이며, 실제 마을·건설 가능 타일은 확장하지 않는다.

## 사용법과 연결

- 순수 C# `Afterlife.TerritoryVision` 어셈블리의 `TerritorySight`에 `AddTile(x, z)`로 타일 중심을 전달하고 `Contains(x, z)`로 시야·조명 여부를 조회한다. 영역 교체 시 `Clear()` 후 다시 입력한다. Unity나 게임 모델 의존성은 없다.
- 프로토타입은 기존 `PrototypeView` 컴포넌트 경로에서 자동 적용된다. 새 프리팹, Inspector 참조, Tools 메뉴나 설치 작업은 필요 없다. 순수 코어는 MonoBehaviour가 아니므로 별도 컴포넌트를 추가하는 대신 기존 게임 어댑터가 연결한다.
- 다른 게임은 타일 공급과 표시/조명 셰이더 연결을 자체 어댑터에서 맡는다. 마우스 위치나 블러를 이 모듈에 연결하지 않는다.
- 적용 해제는 모델 `Visibility`의 마을 합집합, 뷰의 마스크 갱신, 셰이더의 마을 시야·조명 입력을 함께 해제한다. 건물 시야와 조명 경로는 독립적으로 남는다.

## 데이터 흐름과 수명

`Territory` → `TerritoryRevision` 기준 코어 캐시 → 모델 `Visibility` 및 Unity 마스크 → 일반 표면·식생·물 셰이더.

`PrototypeTerritorySight`는 게임의 타일 키를 좌표로 변환하는 얇은 어댑터다. 뷰는 타일당 8픽셀의 Point 마스크를 영역 변경 때만 업로드한다. GPU 경계는 1/8칸 해상도로 근사하며 CPU는 정확한 사각형 거리 판정을 사용한다. 지도 밖 샘플은 0이다.

마을 시야와 기존 시야는 최댓값으로 합친다. 밤 조명도 기존 건물 조도와 최댓값으로 합친다. 시야(R)는 Point 샘플링을 유지하고, 조명(G)은 별도 Linear Clamp 샘플링으로 부드럽게 보간한다. `TerritoryEdgeLighting.Create`에 확장 완료된 시야 마스크와 해상도·월드당 픽셀 수를 전달하면 조명 바이트 배열을 반환한다. 전체 확장 영역의 바깥까지 유클리드 거리를 계산하여 **최종 테두리에서 안쪽 1.8칸**에 smoothstep을 적용한다. 바깥 경계에서 0, 안쪽 0.9칸에서 절반, 1.8칸부터 최대 조도다. 원래 타일까지의 거리로 밝기를 정하지 않으므로 오목한 부분에서 합쳐진 영역도 하나의 테두리를 따른다. 두 축 거리 변환의 비용은 픽셀 수에 선형 비례하며 영역 변경 때만 수행한다. 기존 밤 색조와 낮밤 보간은 유지한다. 타일별 실제 Light는 생성하지 않는다.

2026-10-09부터 프로토타입의 밝기 구분에는 마을 상시 시야까지 포함한 전체 시야를 사용한다. 시야 밖만 낮·밤 모두 조명이 계산된 색에 0.8을 곱하며, 마을 시야 안은 추가 어두움이 없다. 밝기용 R 샘플만 Linear Clamp로 경계를 보간하고 노출용 Point 판정은 유지한다. 조명 G의 1.8칸 감쇠와 별도로 누적되며, 새 마스크·리소스·설치는 필요 없다. 공용 GPU 규칙과 연결·해제·검증은 [시야 표현 기록](../../../../../../docs/game-process/48-vision-blur-and-night.md)에 있다.

새 판·환생에서 영역 revision으로 캐시를 갱신하며, 모델 인스턴스 교체도 감지한다. 뷰 파괴 시 텍스처와 전역 연결을 해제한다. 기존 뷰가 잠시 비활성화되는 동안은 다른 시야 텍스처와 동일하게 캐시를 보존한다.

**블러는 변경하지 않는다. 마을과 바깥 2칸도 마우스가 멀어지면 흐려지고, 가까워지면 선명해진다.**

## 검증

- Unity가 프로젝트 파일을 생성한 후 `dotnet build Afterlife.TerritoryVision.csproj --no-restore`, `dotnet build Afterlife.Prototype.csproj --no-restore`로 컴파일한다.
- 일반 csproj 직접 빌드는 복원 자산 누락으로 실패하므로 기존 Unity DLL 참조 기반 검증 경로를 사용한다. Unity 프로젝트 폴더에서 `& ./Tools/AfterlifePrototype/Build-ScriptableData.ps1 -Modules Afterlife.TerritoryVision,Afterlife.Prototype`를 실행한다. 선택하지 않은 의존 모듈은 기존 Unity DLL을 참조한다. 이번 경계 보정: 코어 경고/오류 0, 프로토타입 오류 0·기존 직렬화 필드 CS0649 경고 30개로 통과했다.
- 프로젝트 규칙에 따라 Unity Test Runner와 자동 플레이는 실행하지 않는다.
- 수동으로 낮·밤에 마우스를 마을에서 멀리 이동한다. 오브젝트는 사라지지 않고 밤 조도도 유지되지만, 기존처럼 흐려져야 한다. 가까이 이동하면 선명해져야 한다.
- 단일 타일 기준 중심에서 축 방향 2.5까지 포함되고, 모서리 (0.5, 0.5)에서 거리 2까지 둥글게 포함되는지 확인한다. 영역 밖은 기존 시야 소스가 없을 때만 숨겨져야 한다.
- 집 완공·이동·철거로 영역을 확장/축소하고, 떨어진 마을·지도 가장자리·환생·새 판에서 이전 마스크가 남지 않는지 확인한다.
- 일반 오브젝트·풀·물의 조명, 기존 건물 조명 범위, 건설 가능 범위, 카메라 줌·회전 후의 마우스 블러 동작을 함께 확인한다.
- 밤에 마을 바깥 0.2~2칸 구간이 점차 어두워지며 딱 끊기는 밝기 경계나 타일별 이음새가 없는지 확인한다. 시야 반경 2와 마우스 블러는 그대로여야 한다.
- 낮·밤 모두 마을 상시 시야 안은 추가로 어두워지지 않고, 모든 시야 밖은 조명이 계산된 색의 80%여야 한다. 커서·건물·마을 시야가 겹친 곳에서는 어두움이 중복되지 않고 밝기 경계가 부드럽게 연결되어야 한다.
- 오목한 ㄱ자·ㄷ자 마을, 좁은 틈에서 확장 영역이 합쳐지는 배치, 떨어진 두 마을을 확인한다. 확장된 전체 경계에서 감쇠 폭이 자연스럽게 이어지고, 합쳐진 내부에 이전 타일별 밝기 골이 남지 않아야 한다. 먼 마우스와 가까운 마우스 양쪽에서 확인한다. 지도 끝 자체를 조명 경계로 추가하지 않는다.

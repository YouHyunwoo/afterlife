# Afterlife Editor

Windows 독립 데스크톱 영상 편집기다. 일반 영상·음성·자막 편집과 MP4 출력은 본체가 담당하고, 개발일지 제작은 끄고 켤 수 있는 플러그인으로 제공한다. 기존 웹 UI와 FFmpeg 엔진을 재사용하며 앱이 로컬 서버를 자동 시작·종료한다.

## 실행

현재 수정본: `.tooling/devlog-editor/dist-workflow/AfterlifeEditor/AfterlifeEditor.exe`. 제목표시줄과 화면 비율 설정, 제목표시줄 아래에 제한한 스크롤, Windows 프로젝트 열기를 포함한다. 왼쪽 미디어·개발일지 탭, 하단 타임라인 직접 편집, 자동 저장과 원본 다시 연결을 추가했다. 종료 멈춤 수정과 Supertonic 나레이션도 포함한다. `start.cmd`로 실행하는 소스 버전도 수정됐다.

위 EXE를 실행한다. EXE가 있는 폴더 전체가 배포 단위이며 Python과 FFmpeg가 포함되어 있다. Windows WebView2 Runtime이 필요하다. 소스에서 실행할 때는 `tools/devlog-editor/start.cmd`를 더블클릭한다. 편집기 전용 `.tooling/devlog-editor/venv`를 사용하며 터미널이나 브라우저를 별도로 열 필요가 없다.

처음 개발 환경을 준비할 때 Python 3.12에서 `setup.cmd`를 실행한다. 이 명령은 기존 `.tooling/day01-tts/assets/`의 Supertonic 모델을 편집기 전용 `.tooling/devlog-editor/tts_assets/`로 복사한다. 배포본 생성은 전용 환경에 `requirements-build.txt`를 설치한 뒤 `python tools/devlog-editor/build_desktop.py`를 실행한다. 배포본에는 모델이 포함되어 Day01 폴더 없이 음성을 생성할 수 있다. 앱 설정·렌더 캐시는 배포본에서 `%LOCALAPPDATA%/AfterlifeEditor/`, 개발 실행에서는 `.tooling/devlog-editor/`에 둔다. 시작 실패 기록은 그 아래 `desktop-error.log`다.

## 프로젝트와 파일

**프로젝트 생성 → 이름 입력 → 프로젝트 폴더 선택 → 확인**으로 시작한다. Windows 폴더 선택창을 사용하며 선택한 폴더에 JSON과 `<파일명>.media/`를 함께 보관한다. **프로젝트 열기**는 Windows 파일 선택창으로 기존 JSON을 연다. 데스크톱에서는 브라우저용 저장 방식 구분이 없다. 다른 드라이브의 프로젝트도 선택할 수 있다.

왼쪽 **프로젝트 에셋 → 추가**에서 영상·음성을 가져와 트랙에 배치한다. 업로드한 미디어는 프로젝트에 복사하며, **파일 경로로 연결**은 원본을 복사하지 않는다. 오른쪽 **오디오 믹서·출력 설정**에서 미디어 위치를 확인하고 **출력 위치 선택**으로 MP4 위치를 바꿀 수 있다. 기본 출력 위치는 해당 프로젝트 미디어 폴더의 `video/exports/`다. 기존 파일은 자동 덮어쓰지 않는다.

**프로젝트 → 저장 / Ctrl+S**로 저장한다. 기존 JSON은 백업하며, 저장되지 않은 변경이 있는 상태에서 창을 닫으면 확인한다. 내보내기·플러그인 작업 중에는 완료 후 종료한다.

데스크톱에서는 편집 중 90초마다 작업을 자동 저장한다. 재생·입력·모달·출력 중에는 기다렸다가 저장하며 자동 저장은 추가 시간표시 백업을 만들지 않는다. 수동 저장은 기존처럼 백업을 만든다. 연결한 파일이 이동했다면 에셋을 선택하고 오른쪽 **원본 파일 다시 연결**에서 새 경로를 선택한다. 해당 에셋을 쓰는 클립도 함께 새 경로로 바뀌며 새 파일이 사용 구간보다 짧으면 거부한다.

## 개발일지 플러그인

프로젝트를 열고 상단 **플러그인 → 개발일지 제작 → 열기**를 선택한다. 사용 체크박스로 켜고 끌 수 있으며 설정을 재실행 후에도 유지한다.

- **대본 → 자막 초안**: 한 줄에 한 문장씩 입력하고 문장 길이·시작 시간을 지정한다.
- **대본 → 음성 + 자막**: 앱에 포함된 Supertonic 3 모델로 한국어 문장별 WAV와 실제 음성 길이에 맞춘 자막을 생성한다. M1~M5 음성과 속도(0.5~1.5)를 선택할 수 있다. 별도 음성 서버나 Windows 설치 음성은 필요하지 않다.
- **SRT → 자막**: 시간표를 유지한 독립 자막 트랙으로 변환한다. 여러 줄 자막과 시작 오프셋을 지원한다.
- **녹화본 순서대로 배치**: 선택한 영상 에셋을 목록 순서대로 이어 붙인다. 영상은 원본 전체 길이로 배치한 후 일반 구간 편집으로 다듬는다.
- **이전/현재 비교 장면**: 영상 에셋 2개를 선택하면 지정한 길이의 이전·현재 영상과 표시 자막을 순서대로 만든다.
- **엔딩 크레딧 자막**: 입력한 여러 줄 텍스트를 지정한 구간에 표시한다. 현재는 정적 자막이며 스크롤 효과는 아니다.

TXT·Markdown·SRT 파일을 패널에서 불러올 수 있다. 결과는 기존 트랙 위에 일반 트랙으로 추가한다. 추가한 결과는 한 번에 되돌릴 수 있고, 플러그인을 꺼도 저장·재열기·편집·출력이 가능하다. 생성한 WAV와 음성 생성 기록은 프로젝트 미디어 폴더의 `audio/narration/`에 보존하며 되돌리기는 파일을 삭제하지 않는다. 출력 전 나레이션 발음·자막 타이밍과 음악 공개 크레딧을 확인한다. 기존 `devlog/youtube/tools/generate_narration.py`는 Day01·Unity 촬영 자료용 스크립트로 남아 있으며 편집기 실행에는 사용하지 않는다.

## 트랙과 클립

창 맨 위에는 프로젝트·영상·내보내기·플러그인 메뉴, 가운데 프로젝트 이름, 오른쪽 최소화·최대화/복원·닫기 버튼이 있다. 제목을 드래그해 창을 이동하고 더블클릭해 최대화/복원한다. 왼쪽에는 미디어·개발일지 탭을 두고, 오른쪽 작업 영역은 상단 프리뷰와 선택 정보·하단 타임라인으로 배치했다. 에셋 검색, 개발일지 작업 바로가기, 현재 재생 위치의 촬영 메모와 완료 표시를 지원한다. 기존 화면 내부 헤더와 프리뷰 높이 조절은 제거했다.

**영상 → 화면 비율**에서 16:9·9:16·1:1·4:3·21:9 프리셋을 선택한다. 선택 중 프리뷰에 즉시 반영되며 **적용**하면 프로젝트에 저장되고 MP4 출력에도 반영된다. **취소/Esc**는 원래 비율로 되돌린다. 이전 프로젝트는 16:9로 연다. 출력 설정의 기준 크기 720/1080은 짧은 변을 뜻하며, 실제 픽셀 크기를 설정 아래에 표시한다.

프로젝트 생성·열기는 Windows 대화상자를 사용한다. 프로젝트를 바꿀 때 저장되지 않은 변경은 확인을 거친다.

1. 영상·오디오·자막 중 종류를 선택하고 **트랙 추가**를 누른다.
2. 트랙을 선택한 뒤 **클립 만들기** 또는 트랙 왼쪽 **＋**를 누른다.
3. 영상/음원 파일을 선택하거나 경로를 불러온다. 클립별로 다른 원본 파일을 쓸 수 있다.
4. 클립을 좌우로 드래그해 시작 시간을 바꾼다. 위아래로 드래그하면 같은 종류의 다른 트랙으로 옮긴다.
5. 클립을 **더블클릭**하면 구간 편집 창이 열린다. 원본 프리뷰 아래 한 트랙에서 양 끝 손잡이는 시작/끝을 변경하고, 몸체는 길이를 유지하며 원본 구간을 이동한다. 구간 확대와 숫자 입력도 가능하다. **확인**만 적용하고 **취소/Esc**는 원래 상태를 유지한다.
6. 영상·나레이션·자막은 기본적으로 독립적이다. 함께 움직일 클립은 시작·길이를 맞춘 뒤 정보 패널에서 연결한다. 음원과 자막도 각각 드래그·복제·삭제·편집할 수 있다.
7. **재생 → 저장 → MP4 내보내기** 순서로 확인한다. 편집 직후에도 재생을 누르면 켜진 오디오 트랙이 함께 들린다. 내보내기 전 원본 파일·원본 길이를 확인하고, 미완료 촬영 메모·꺼진 자막·검은 화면·미저장 변경은 확인 사항으로 표시한다. 원본 오류가 있으면 내보내기를 막는다. 브라우저 재생은 클립별 스트리밍이며, 최종 출력은 별도 PCM 믹스로 음량 피크를 보호한다.

시간 눈금은 드래그로 탐색한다. 최대 300px/초 확대, 스냅 ON/OFF 및 0.1/0.5/1/5초 간격을 지원한다. 타임라인과 구간 모달의 드래그는 동일 스냅 설정을 사용한다. 실수는 **되돌리기 / Ctrl+Z**로 최대 40단계 복구한다.

클립의 양끝 손잡이를 끌어 길이를 줄이고, 재생 위치에서 **분할 / S**로 클립을 나눈다. **구간 당겨 삭제**는 선택한 클립 시간 범위를 모든 트랙에서 제거하고 뒤 구간과 촬영 메모를 당긴다. 영상·음성·자막 중 종류가 다른 클립이 같은 시작·길이라면 정보 패널에서 연결할 수 있다. 개발일지 TTS로 만든 문장별 음성·자막은 자동으로 연결되어 함께 이동·분할·길이 조정된다. 원본 파일의 자세한 시작·끝 조정은 기존 구간 편집 창을 쓴다.

영상은 위쪽 트랙이 우선한다. 같은 영상 트랙 안의 겹침은 제한하며, 겹쳐 놓으려면 다른 영상 트랙을 사용한다. 표시 가능한 영상이 없는 구간은 검은 화면이다. 모든 트랙이 비어도 최소 길이만큼 검은 영상으로 내보낼 수 있다. 오디오는 켜진 트랙을 합산한다. 위 영상에 가려진 영상의 원음은 재생하지 않는다. 트랙 왼쪽 끄기/켜기와 ↑/↓로 우선순위를 조절한다.

## 자막·음악·크레딧

녹화본에 이미 포함된 자막과 크레딧은 이미지의 일부이므로 제거되지 않는다. 오른쪽 **오디오 믹서·출력 설정 → 자막 트랙 표시·내보내기**를 켜야 편집기 자막이 추가된다. 기존 자막 텍스트를 바꿔도 음성은 자동 재생성하지 않는다. 새 음성이 필요하면 플러그인에서 다시 생성하거나 나레이션 클립에 새 파일을 연결한다.

배경음악은 오디오 트랙의 독립 클립이다. 음원 종류를 배경음악으로 선택하면 음악 볼륨·페이드·크레딧 배율을 적용한다. 반복 옵션을 켜면 4초 이하 크로스페이드로 반복한다. 길이는 타임라인 길이 입력으로 늘릴 수 있다. 배경음악도 클립이 없는 구간에는 나오지 않는다. 기존 크레딧 영상 클립의 `credits: true`를 변환 시 유지한다. 공개 크레딧은 `docs/audio-credits.md`를 확인한다.

## 저장 및 이전 데이터

기존 Day01 프로젝트는 `devlog/youtube/day-01/edit-project/day01.devfilm.json`에서 **프로젝트 열기**로 선택한다. 구버전 샷 데이터는 열 때 메모리에서 변환하고 저장 전에는 원본 JSON을 덮어쓰지 않는다. 기존 전체 오프셋은 각 영상 클립의 원본 시작에 합쳐진다. 나레이션 길이는 WAV 길이, 자막 길이는 기존 표시 길이로 각각 유지한다. 기존 프로젝트 저장 시 시간표시 백업을 만든다. 프로젝트 파일을 다른 폴더에 저장하면 리소스 상대 경로를 새 위치에 맞춘다.

## 프로젝트별 저장 위치

`Day02.devfilm.json`을 생성하거나 열면 같은 폴더의 `Day02.media/`를 사용한다. 같은 폴더에 여러 JSON이 있어도 파일명별로 분리한다.

```text
Day02.devfilm.json
Day02.media/
  video/imports/   가져온 영상
  audio/imports/   가져온 음성
  video/exports/   MP4와 출력 당시 프로젝트 JSON
```

**이전 브라우저 모드 호환:** 개발용 `server.py`를 직접 실행한 경우에만 아래 규칙을 적용한다. 데스크톱 UI에는 이 방식이 노출되지 않는다. 브라우저 기본 저장창은 서버에 실제 저장 경로를 제공하지 않는다. 이 방식의 프로젝트는 `devlog/youtube/editor-projects/<browserStorageId>/project.devfilm.json`을 서버 작업 사본으로, 옆의 `project.media/`를 영구 미디어 폴더로 사용한다. 새 프로젝트 JSON에 ID를 기록하며 같은 파일을 다시 열면 같은 위치를 사용한다. 이전 브라우저 JSON에 ID가 없다면 열 때 발급하므로 한 번 저장해야 재열기에도 유지된다. JSON을 복사하면 같은 ID를 공유한다. 독립 프로젝트는 **새 프로젝트**로 생성한다. 이 보관 폴더는 캐시가 아니므로 미디어와 함께 보존해야 한다.

기존 Day01 자료와 이전 `.tooling/devlog-editor/browser-projects/` 파일은 이동·삭제하지 않는다. 기존 미디어 참조는 유지하고 이후 업로드와 기본 출력부터 새 규칙을 적용한다. JSON 저장 위치를 바꾸면 기존 미디어 경로만 재계산하고 미디어 자체는 이동하지 않는다. 외부 파일을 경로로 연결한 경우도 복사하지 않는다. 프로젝트 전체 복사·이동 기능은 별도다.

프로젝트 전환 시 사용자 지정 MP4 출력 경로는 초기화한다. 출력 경로를 직접 입력하면 기존처럼 해당 경로를 사용하며, 데스크톱에서는 Windows 대화상자에서 선택한 프로젝트·출력 폴더에 저장한다. 시작할 때 Day01 프로젝트를 자동 생성하거나 불러오지 않는다.

## 데이터 계약

`schemaVersion: 2`, 시간은 초, 경로는 JSON 기준 상대 경로 또는 절대 경로다.

|필드|역할|
|---|---|
|tracks[].id / name / kind / enabled|트랙 식별자·이름·video/audio/subtitle·활성 여부|
|tracks[].clips[].id / title / start / duration|클립 식별자·이름·타임라인 시작·길이|
|tracks[].clips[].linkGroup|함께 이동·분할하는 영상·음성·자막 연결 그룹(선택)|
|markers[].id / title / time / done|촬영 메모와 완료 상태(선택)|
|assets[].id / name / kind / path / duration|영상·음성 원본의 목록과 길이|
|assets[].defaultVolume / role / loop|이후 배치되는 클립의 기본 음량·음원 종류·반복 여부|
|영상/음원 클립 path / sourceIn / volume|원본 파일·파일 내부 시작·개별 음량|
|영상 padEnd / credits|끝 프레임 유지·크레딧 음악 배율 구간|
|음원 role / loop|narration/music/effect·반복 여부|
|자막 text|독립 텍스트|
|minimumDuration|모든 트랙이 비었을 때도 유지할 최소 길이|
|narrationVolume / video.volume / music|종류별 음량 및 음악 페이드·크레딧 배율|
|export|기준 크기·화면 비율·프레임·자막 출력 여부|

`video.path`는 새 영상 클립의 기본 소스이고, 기존 `video.offset`은 v2 재생에는 적용하지 않는다. 실제 재생 소스는 클립의 path/sourceIn만 사용한다. 최대 32트랙·1000클립·1시간을 지원한다.

## 모듈 및 검증

- `desktop.py`, `desktop_ui.js`: 독립 창과 네이티브 파일 선택.
- `aspect_ratio.py`: 화면 비율 프리셋과 짝수 픽셀 출력 크기.
- `close_controller.py`: UI 이벤트를 차단하지 않는 비동기 종료 확인, 미저장 변경·진행 작업 보호.
- `runtime_paths.py`: 개발/배포 경로 분리.
- `plugin_registry.py`, `plugin_host.js`: 플러그인 검색·활성 상태·명령 실행·되돌리기 연결.
- `timeline_edit.js`: 연결된 클립의 이동·분할·길이 조정과 전체 트랙 구간 당겨 삭제.
- `plugins/devlog/`: 개발일지 전용 패널·제작 명령.
- `tts.py`, `third_party/supertonic_helper.py`: 앱 공용 Supertonic 음성 합성 및 모델 로더.
- `project.py`: 저장·경로 변환·구버전 호환.
- `storage.py`: 프로젝트별 미디어·출력 폴더와 브라우저 영구 보관 ID.
- `timeline.py`: 트랙 모델·v1→v2 변환·검증·영상 우선순위 구간 계산.
- `render.py`: FFmpeg·오디오 공통 유틸리티와 구버전 렌더링.
- `render_tracks.py`: 독립 오디오 합성·레이어/공백 영상 출력·자막.
- `live_audio.js`: 브라우저에서 오디오 클립별 재생 위치·반복·페이드·크레딧 음량 동기화.
- `server.py`: 로컬 API·등록 원본 스트리밍·작업 진행.
- `media_library.py`: 브라우저 영상·음성 전송·검증·중복 제거·등록.
- `ui.html`, `editor.css`, `editor.js`: 화면·트랙 드래그·구간 편집 모달.

검증: `.tooling/devlog-editor/venv/Scripts/python.exe -m unittest discover -s tools/devlog-editor -p 'test_*.py'`, `node --check tools/devlog-editor/editor.js`, `node tools/devlog-editor/test_live_audio.js`. `test_storage.py`는 로컬 HTTP API에서 프로젝트 분리·저장·재열기·출력 경로를 검증한다.

개발 실행의 렌더 중간 산출물은 `.tooling/devlog-editor/cache/`에 둔다. 파형·썸네일 스트립, 투명도/크기 기반 영상 합성, 전환 효과와 프록시 편집은 아직 제공하지 않는다. 영상은 각 트랙의 전체 화면 컷으로 합성한다.

데스크톱 통합 검증: `python tools/devlog-editor/desktop.py --smoke-test <결과 JSON 경로>`. 임시 프로젝트로 실제 WebView2의 생성·플러그인 패널·되돌리기·저장·재열기·MP4 출력을 검증하고 임시 자료를 정리한다. 배포 EXE도 같은 옵션을 지원한다. 결과 JSON의 `ok`를 확인한다.

플러그인 확장 계약은 [PLUGIN_API.md](PLUGIN_API.md)를 참조한다.
